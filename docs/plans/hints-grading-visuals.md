## 1. 목표와 사용자 결정

학생이 맞게 만든 작품이 사소한 차이로 떨어지지 않게 채점을 넓히고, 길고 읽기 싫은 블록 연결 힌트를 '힌트'답게 짧게 고치고, 반복 수업 개념 그림을 실제 엔트리 블록으로 바꿉니다. 학생·교사의 사용 경험이 최우선입니다.

- **[결정]** 채점: 같은 뜻의 블록 인정, 말 문구 완화(기대한 말을 포함하고 다른 결과의 말은 없으면 통과). 도형은 반복 안에서 그려야 한다는 조건은 유지. 테스트에서 나오는 엣지 케이스는 유연하게 반영.
- **[결정]** 힌트: 단계마다 한 줄, 블록은 팔레트에서 찾을 수 있는 이름에 실제 값을 넣어 칩으로 표시(예: `A를 대답으로 정하기`), 이유는 💡 한 줄. 단계를 다 따라가면 답에 거의 닿되 하나하나 설명하지 않음.
- **[결정]** 그림: lc1·lc3·lc4를 실제 엔트리 블록 캡처로, 미션 블록 조립을 그대로 보여 주지 않게 예시를 바꿈. lc0·lc2는 유지.
- **[결정]** 전체 E2E 실행 안 함. PR까지 만들고 병합은 사용자가 함.

## 3. 작업

### A. 채점 완화

- **파일:** `src/lib/server/programming-grader.ts`, `src/lib/classroom/entry-palette.ts`, `src/lib/classroom/programming-entry.ts`, `src/lib/classroom/name-entry.ts`, `public/entryjs/workspace.js`(이름 미션 실행 기록), `tests/entry-palette.test.ts`, 관련 E2E 단언, `docs/PRD.md`(179·189행 부근), `docs/DEVELOPMENT.md`(§4.1 해석기·채점 범위).
- **말 비교:** 글자와 숫자만 남겨 비교(띄어쓰기·문장부호·이모지 무시). 결과표의 다른 결과 낱말이 이 결과 낱말을 품으면(`불합격` ⊃ `합격`) 먼저 지우고 찾음. 말한 줄 가운데 결과가 있는 줄이 하나 이상이고 모두 기대한 결과일 때 통과. 인사·마무리 말처럼 결과가 없는 줄은 무시.
- **말 목록 판정:** 마지막 말 대신 말한 줄 전체로 판정. 이름은 입력에서 온 줄에 이름이 있으면, 곱셈·평균은 마지막 계산 결과 줄로, 금고는 '열렸' 줄이 정확히 하나이고 마지막 묻기 뒤일 때. A·B는 처음 저장한 입력값으로 확인.
- **같은 뜻·해 없는 블록:** 모든 미션에 해 없는 블록 묶음(기다리기, 말풍선 지우기, 보이기·숨기기, 붓 색·굵기·채우기·도장, 효과·크기·뒤집기, 대답 보이기 등)을 허용하고 해석기는 건너뜀. 의미가 같은 블록에 해석 추가: `move_x`·`move_y`, `move_xy_time`·`locate_xy_time`(끝점으로), `rotate_by_time`, `direction_relative_duration`, `calc_basic` 더하기의 글자 이어 붙이기(엔트리와 같게). 곱셈에 일반 말하기, 판단 미션·정다각형에 변수, 그리기 미션에 말하기 허용. **금지:** `locate_x`·`locate_y`를 이동 미션에 허용(해석기가 항상 0,0에서 시작해 절대 이동이 통과해 버림), `rotate_absolute`를 방향 정하기와 같게 보기(엔트리에서 뜻이 다름), 이동·방향키·정사각형에 묻기 허용(화면 실행 기록 방식이 바뀜).
- **메시지:** 시작 줄이 0개와 2개 이상을 나눠 안내. 생각하기 안내. 같은 뜻 블록 안내 문구는 팔레트 이름으로.
- **안전장치 테스트:** 허용한 모든 블록이 해석기에서 '시작 블록은 맨 위에…'로 떨어지지 않는지 블록마다 확인. 통과해야 할 변형과 실패해야 할 변형(불합격을 합격으로, 결과 둘 다 말하기, 고정 답, 반복 없는 도형, 나선·팔각형) 표 테스트.
- **고정 자료:** `tests/fixtures/entry-legacy-keys.json`은 바꾸지 않음(정찰 모의 실행에서 허용 범위 확대만으로는 불일치 0 [확인]). 바뀌는 단언은 이유를 PR에 적음.

### B. 힌트 다듬기 (A 뒤)

- **파일:** `src/lib/classroom/programming-entry.ts`(미션 데이터·칩 도우미), `src/lib/classroom/entry-palette.ts`(팔레트 표기), `src/components/student/programming-lesson.tsx`·`.module.css`, `src/lib/server/programming-grader.ts`(`fail(mission.failure)`), `tests/entry-palette.test.ts`, `tests/ui-workspace-refinement.spec.ts`, `docs/DESIGN.md`(§2.1 색 쓰임, §5.1 미션 안내 카드), `docs/DEVELOPMENT.md`(§4.1 힌트 규칙).
- **데이터:** `ProgrammingMission`에 `failure: string`(필수)과 `tip?: string`. 칩은 문자열 안에 `` `블록종류: 보이는 글자` ``로 쓰고, `hintParts(text)`(평문·칩 조각 배열)와 `hintPlain(text)`(칩 표시 없는 평문)로 읽음.
- **문구 기준:** 요약 한 줄은 목표를 되풀이하지 않고 먼저 볼 곳을 말함. 단계는 5개 이하, 한 단계에 행동 하나와 칩, 1,024px에서 한 줄. 💡는 미션당 최대 한 줄. 칩 글자는 학생이 팔레트에서 그 블록 하나를 찾을 수 있을 만큼만 쓰고 실제 값을 넣음. 단계를 모두 따르면 기준 정답과 같은 블록 구성이 됨. 사용자 예시(곱셈·정사각형)의 길이와 말투가 기준.
- **표시:** 칩은 엔트리 꾸러미 색(교사 작품 미리보기의 `entryBlockPill` 색과 같은 토큰)으로 왼쪽 테두리·옅은 바탕, 진한 글자, 줄바꿈 가능, 화면 읽기에는 평문으로 읽힘. 💡는 `<ol>` 뒤 별도 문단. '검증에는 이 블록만 봐요'는 '이 미션에서 쓸 수 있는 블록'으로 바꾸고 팔레트 표기 칩으로, 해 없는 블록 묶음은 빼서 보여 줌.
- **테스트:** 기존 따옴표=`BLOCK_LABELS` 비교를 칩 검사로 바꿈: 모든 칩의 블록 종류가 그 미션의 허용 블록에 있음, 칩 글자에 그 블록의 고정 낱말이 있음, 칩 밖 백틱·`( )`·'팔레트에서는' 없음, 단계 수·길이 상한, 기준 정답이 쓰는 블록이 칩에 모두 나옴(공통 블록 소수 제외). E2E의 힌트 문장 비교는 `hintPlain`으로.
- **완료 기준(화면):** 1,024×768에서 힌트를 펼쳐도 작업실 시작 위치가 약 230px 넘게 내려가지 않음, 1,440×900의 222px 칸에서 단계당 4줄 이하, 390px 가로 넘침 없음. 가상 학생 검토에서 '읽기 싫다'·'블록을 못 찾겠다' 지적이 남지 않음.

## 4. 루프와 검증

- 작업마다 '구현 → 독립 검증'을 최대 3회 돌림. 검증자는 구현자가 아닌 새 에이전트이며, A는 반례 프로그램을 직접 만들어 채점기를 공격하고, B는 기술 검증과 가상 학생 검토를 따로 받고, C는 캡처와 화면을 눈으로 확인합니다. 3회째에도 통과하지 못하면 남은 문제를 보고하고 멈춥니다.
- 통합 단계: 린트·타입·`check-docs`·`test:scope`·단위(`playwright.logic.config.ts`)·선별 E2E(`npm run test:e2e:scope:running`, 켜 둔 서버 사용)·빌드·1,024/1,440/390px 화면 확인. 전체 E2E는 실행하지 않습니다.
- 지킬 것: 운영 데이터·설정 변경 없음, 축제 자료(`teaching-materials/festival-romance/`) 손대지 않음, Playwright MCP는 저장소 최상위에 `.playwright-mcp/`를 만들므로 쓰지 않거나 지움, 커밋은 파일 이름을 지정해서.
