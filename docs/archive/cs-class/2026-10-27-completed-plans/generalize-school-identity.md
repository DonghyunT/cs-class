## 4. 반영 경로

문서(`README.md`·`docs/` 아래 `*.md`)만 바꾸므로 [개발 안내 §2.1](../DEVELOPMENT.md#위험도별-반영-경로)의 직접 push 경로에 해당합니다. 다만 브랜치가 이미 원격에 있으니 **PR 경로를 추천합니다.** 검토 기록이 남고, squash 병합으로 이 계획 커밋도 하나로 정리됩니다. CI는 문서 모드로 짧게 끝나고, Vercel은 문서 전용 변경이라 빌드를 생략합니다.

**시작할 때 사용자에게 물을 것:** PR과 직접 push 중 어느 쪽인지, 그리고 승인 범위(PR 생성까지인지, 병합까지인지)입니다. 전체 E2E는 문서만 바꾸므로 필요 없습니다.
