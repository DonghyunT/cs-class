## 제품 방향

- 이름: **CS Class** / 보조 문구: **즐거운 정보 교실**.
- 공개 방문자는 수업 구조와 짧은 개념 소개를 볼 수 있습니다. 로그인한 학생은 자기 반의 수업을 이어서 합니다.
- 첫 실제 적용은 **한 반의 일반 학습**입니다. 수행평가와 기존 성적은 V1에서 계속 운영합니다.
- V1의 전체 Git 이력을 비공개 새 저장소에 보존하지만 V1 `main`, 사이트, `donghyun-algo` 데이터는 수정하지 않습니다.
- 현재 구현은 HTML/CSS/Vanilla JS 시안입니다. 새 프런트엔드 기반은 위 2026-09-26 환경 논의에 따라 검토 중입니다.

## 교실·계정

- 학생: 반 코드, 출석번호, 개별 비밀번호로 로그인. 공유 PC에서는 인증 지속성 및 브라우저 임시 저장을 세션 기준으로 제한합니다.

- 전입생 추가 시 교사가 출석번호를 지정하고 이름은 기본 공란으로 둡니다. 비밀번호 재발급은 작업을 보존합니다. 같은 번호의 학생 교체 시 새 계정은 새 식별자를 얻고 이전 작업은 기록실로 분리합니다.
- 시안의 계정·마감·교체 조작은 전부 가상 상태이며 실제 인증·권한·자료에 영향을 주지 않습니다.

## 저장·제출·기록

- 나만의 백지 초안을 서버에 자동 저장하고 복구 상태를 학생에게 명확히 알립니다. 저장 실패 시 작성 내용을 유지하고 재시도를 안내합니다.
- 제출 직전 **현재 초안**에 대한 AI 설계 검사 통과를 확인합니다. AI 장애는 통과로 처리하지 않고 재시도를 안내합니다. 시안의 “시안용 구조 확인”은 AI가 아니며 운영에서 그대로 사용하지 않습니다.
- 학생이 명시적으로 제출합니다. 제출본은 고정하고, 마감 전 재제출을 허용합니다. 교사는 최신본과 이전 제출본을 조회합니다.
- 학년도별 읽기 전용 기록실은 연도·반·번호 조회와 내보내기를 지원합니다. 자동 삭제 시점은 두지 않는 방향으로 설계합니다. 실제 학생별 작업·성적의 장기 보관에 학교 규정이 적용되는지 원문을 확인한 뒤 운영 방침을 확정합니다.
- 기존 V1 평가 답안·확정 성적은 이관하지 않고 보존합니다. 수행평가 이관은 한 반 학습 시범 이후 별도 설계합니다.

## 환경과 진행 순서

1. **대표 화면 시안**: `web/`을 Firebase 미연결 상태로 구현하고 교사·학생이 화면 흐름을 검토합니다. 현재 단계.
2. **개발용 Firebase**: V2 개발 프로젝트와 다른 별도 프로젝트를 사용합니다. 가상 학생으로 계정 분리, 저장·복구, 비밀번호 재발급, 제출·재제출, 마감·재개방, API/Firestore 권한을 검증합니다. 시험 자료는 실행 단위로 정리합니다.
3. **운영 연결**: `cs-class-f74c4`에만 연결합니다. 실제 학생 자료 투입 전에 보관 규정과 권한·복구 절차를 확인합니다. 한 반의 수업 중 사용과 수업 후 이어하기를 확인합니다.
4. **수행평가 이관 검토**: 별도 승인·설계 단계.

첫 시안에는 배포 자산을 `web/`로 제한합니다. V1 루트의 기존 Firebase 설정이나 평가 API를 새 배포에 넣지 않습니다.

## 시각 방향 재검토 (2026-09-25)

- 선생님이 현재 웹 시안의 디자인에 만족하지 않아 **화면 시각안은 미채택** 상태입니다. 기존 시안의 기능 클릭 경로는 구현 증거로 남기되, 그 스타일을 다른 화면에 확장하지 않습니다. 어두운 공개 첫 화면을 포함한 최종 시각 방향도 다시 검토합니다.
- 외부 도구 Google Stitch에서 [비공개 학생 홈 디자인 검토안](https://stitch.withgoogle.com/projects/11262479829296966022)을 만들었습니다. 두 번째 화면인 '학생 홈 · 즐거운 정보 교실 (개선안)'은 왼쪽 텍스트 탐색, 단일 '이어서 학습하기', 잠금 없는 세로 학습 목록을 제안합니다. **제품에 적용하거나 승인받은 시안은 아닙니다.** 같은 Google 계정에서만 열리며 공개 공유는 켜지 않았습니다.
- Stitch가 처음 생성한 학교명·점수·단계 잠금 등은 실제 정책과 달라 제거했습니다. 마지막 수정에서는 미승인 '오늘 할 일' 체크리스트를 '초안 저장됨 / 최종 제출 전' 상태로 바꿨습니다. 실제 상태, 한국어 문구, 좁은 화면, 읽기 크기는 코드 반영 전에 다시 검토합니다.
- 디자인 근거: [Riseapps의 LMS UI/UX 글](https://riseapps.co/lms-ui-ux-design/)의 내용 중심·명확한 탐색·접근성 원칙과 [Canvas 학생 대시보드 안내](https://community.instructure.com/en/kb/articles/664877-how-do-i-use-the-dashboard-as-a-student)의 할 일·이어가기 위계를 참고합니다. 어느 서비스의 고유 화면도 그대로 복제하지 않습니다.
- 다음 순서는 선생님과 학생 홈 대표 화면의 시각 방향을 합의한 뒤, 같은 규칙을 공개 첫 화면·교사 홈·학습 화면에 적용하는 것입니다. 실제 인증·저장 연동은 디자인 검토 후 진행합니다.
