# Stitch 시안 수정·검토 기록

후속 상태: 이 문서는 최초 Stitch 수정본의 검토 기록입니다. 이후 선생님의 요청으로 중복 예시 제거·스크롤 고정 전환·마우스 반응을 `platform/`의 실제 홈에 구현했습니다. 현재 실행 상태는 [HANDOFF](HANDOFF.md)를 참고합니다.

확인: 2026-09-27. 대상은 [CS Class 랜딩페이지 디자인](https://stitch.withgoogle.com/projects/9952170337891001891)입니다. 이번 작업은 승인된 공개 홈 시안의 문구·제품 요구사항 보정이며, `platform/` 코드는 변경하지 않았습니다.

## 연결과 수정 결과

- 사용자 환경변수로 등록한 키를 참조하는 Stitch MCP로 프로젝트·화면 조회와 화면 수정을 확인했습니다. 키 값은 저장소에 기록하지 않습니다.
- [수정 요청문](STITCH_REVISION_PROMPT.md)을 두 화면에 적용했습니다. 모바일에서 빠진 Pretendard와 움직임 줄이기 처리를 별도 요청으로 보완했습니다.
- 아래 최종 ID는 수정 응답 이후 `get_screen`으로 다시 조회해 HTML 파일까지 확인했습니다. `list_screens`는 검토 시점에 최초 화면 세 개만 반환했으므로, 다음 작업은 최종 ID로 직접 조회합니다. 기존 캔버스 화면을 덮어썼다고 가정하지 않습니다.

## 확인한 변경

- 반·학교 코드 입장 안내를 학번·비밀번호 안내로 정리했습니다.
- 가상 진행률·저장·출석·과제 상태, 가상 교사명·45분 표기, 과한 홍보 문구를 제거했습니다. 숨겨진 상태를 포함한 HTML 텍스트에서도 대상 문구가 남지 않았습니다.
- 제품 미리보기에는 ‘화면 예시’, 수업 전환 프레임에는 ‘수업 구성 예시’를 표시했습니다.
- 개념학습·퀴즈·실습, 지난 활동 이어하기, 학생·교사 공간 설명을 유지했습니다. 탐색 메뉴는 공개 홈 안의 구간 이동으로 정리했습니다.
- 두 HTML에 Pretendard 설정과 움직임 줄이기 CSS가 있습니다. 모바일의 스크립트 스크롤에도 설정 분기가 있습니다.

## 실제 검증과 한계

- 내려받은 HTML을 로컬 서버에서 열어 데스크톱 1440px, 모바일 390px·320px 화면을 확인했습니다. 모바일의 페이지 너비는 각각 390px·320px으로 가로 넘침이 없었습니다.
- 두 화면 모두 세 단계 전환, 퀴즈 선택, 비트 스위치 계산, 학생·교사 미리보기 전환을 확인했습니다. 데스크톱은 오답 안내도 확인했습니다. 계산 결과는 데스크톱 5→13, 모바일 11→3으로 바뀌었습니다.
- Tab으로 단계 선택기에 접근하고 Enter·Space로 전환했으며 초점 테두리를 확인했습니다. 모바일 320px의 표시된 링크·버튼은 너비·높이 모두 44px 이상이었습니다. 전체 접근성 인증이나 스크린리더 검사는 수행하지 않았습니다.
- 모바일의 실제 계산된 제목·본문 글꼴과 Pretendard 로드 상태를 확인했습니다. 확인한 조작 중 두 화면의 브라우저 콘솔 오류는 없었습니다. 각 HTML의 인라인 스크립트 구문도 통과했습니다.
- 움직임 줄이기는 생성 코드만 확인했습니다. OS 설정을 바꾼 실제 재생 검증은 하지 않았습니다.
- 로그인·수업 시작·이어하기 버튼은 시안용 자리표시자입니다. 실제 로그인·저장·수업 열기 동작을 검증한 결과가 아닙니다. 앱 코드를 바꾸지 않아 앱의 lint·typecheck·build·E2E는 재실행하지 않았습니다.

## 앱에 옮길 때

- [DESIGN.md](../DESIGN.md)와 최종 시안을 참고해 기존 Next.js 컴포넌트로 구현합니다. 시안의 CDN Tailwind·폰트 로딩을 그대로 이식하지 않고 기존 로컬 Pretendard와 스타일 체계를 사용합니다.
- 모바일 헤더의 로고 이미지와 별도 ‘CS Class’ 텍스트 중복을 정리합니다. 예시 퀴즈의 선택·정답 표시를 구분하고 데스크톱·모바일 피드백을 통일합니다.
- 탭의 방향키 이동·ARIA 연결, 움직임 줄이기, 고정 헤더·하단 탐색의 가림을 실제 반응형 앱에서 검증합니다. 미리보기의 버튼은 역할을 명확히 하고 실제 입장 버튼은 기존 로그인 흐름에 연결합니다.
