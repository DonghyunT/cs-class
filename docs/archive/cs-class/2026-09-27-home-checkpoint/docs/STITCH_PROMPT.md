# CS Class 공개 홈 — Stitch 생성 프롬프트

아래 코드 블록 전체를 Google Stitch의 새 디자인 요청에 복사해 사용합니다. 프로젝트의 세부 지침은 [DESIGN.md](../DESIGN.md)이며, 아래 프롬프트는 단독으로도 사용할 수 있습니다. 파일을 함께 제공할 수 있는 작업 환경에서는 DESIGN.md도 참고 자료로 제공합니다.

StitchDesign 플러그인은 디자인 지침을 생성하는 스킬입니다. 선생님이 이 프롬프트로 첫 시안을 생성했으며 전체 디자인에 동의했습니다. 2026-09-27 별도로 연결한 Stitch MCP의 인증·조회·수정을 확인하고 [수정 요청문](STITCH_REVISION_PROMPT.md)을 적용했습니다. 결과와 검증 범위는 [Stitch 검토 기록](STITCH_REVIEW.md)에 있습니다. 이후 승인된 시안을 Next.js 공개 홈에 반영하면서 중복 예시·스크롤 전환·호버를 정리했습니다. 현재 상태는 [HANDOFF](HANDOFF.md)를 참고합니다.

```text
중학생을 위한 정보 수업 플랫폼 ‘CS Class’의 공개 홈을 디자인해 주세요.
데스크톱 1440px과 모바일 390px 시안을 만들고, 320px에서도 자연스럽게 읽히도록 구성해 주세요.
결과물의 모든 사용자용 문구는 한국어로 작성해 주세요.

[프로젝트와 작업 범위]
CS Class는 학생이 교사가 열어 둔 수업을 확인하고, 수업 활동을 시작하고, 지난 활동을 이어가는 온라인 교실입니다. 교사는 반별로 수업을 열고 ‘이번 수업’을 지정합니다.
이번에는 공개 홈을 디자인합니다. 로그인·학생 홈·교사 관리 화면은 홈 안의 사용 예시에 필요한 범위만 표현해 주세요.
실제 인증과 저장은 아직 연결 전입니다. 수업 화면은 ‘화면 예시’ 또는 ‘수업 구성 예시’로 표시하고, 가상의 실적·후기·저장 성공·AI 기능을 만들어 넣지 마세요.
수업 콘텐츠는 이후 확장합니다. 순서도나 코딩 등 특정 단원·도구를 서비스 전체의 정체성으로 내세우지 마세요.

[핵심 디자인 방향]
레퍼런스: https://toss.im/
참고할 요소는 넓은 여백, 짧고 큰 한국어 제목, 한 구간에서 한 가지를 설명하는 전개, 제품 화면이 스크롤과 조작에 반응하는 연출, 밝은 바탕과 맑은 파랑·옅은 보조색의 조화입니다.
CS Class 고유의 웹 수업 화면과 그래픽으로 표현해 주세요. 토스의 로고·사진·영상·금융 화면은 사용하지 마세요.
전체 소개 → 사용 방법 → 수업 안의 경험 → 역할별 공간 → 입장의 흐름을 유지합니다.
‘담백한 설명과 생동감 있는 제품 시연’이 함께 느껴지게 해 주세요. 중학생에게 어울리는 정돈된 화면과 실제로 읽을 수 있는 UI를 우선합니다.

[문구와 말투]
학생에게 자연스러운 편한 존댓말을 사용합니다. 설명은 ‘~해요’, 행동 안내는 ‘~하세요’, 버튼은 ‘교실 입장’, ‘수업 시작’, ‘이어하기’처럼 짧게 씁니다.
실제로 무엇을 할 수 있는지 구체적으로 말하고, 한 문장에서 여러 가치를 홍보하지 마세요.
‘나만의 발견’, ‘생각의 다음 장’, ‘준비물은 호기심’, ‘나만의 속도로, 나만의 방식으로’ 같은 추상적·상투적인 교육 홍보 문구는 사용하지 마세요.
장식용 영어 슬로건, 불필요한 감탄사, 이모지와 어린이용 말투는 제외해 주세요.

[색과 글꼴]
기본 글꼴은 Pretendard입니다. 대체 글꼴은 한국어 sans-serif를 사용합니다.
넓은 영역은 흰색 #FFFFFF와 옅은 회색 #F5F7FA, 본문은 #202B3A, 보조 설명은 #526173을 사용합니다.
주요 버튼과 선택 상태는 맑은 파랑 #376FC8, hover는 #2E5FAB, 옅은 파란 배경은 #EAF2FF를 출발점으로 합니다.
그래픽 안에서는 하늘색 #DCEBFF, 살구 #F8E1D5, 라일락 #E9E4F7을 부드럽게 섞어 주세요. 각기 다른 버튼의 강조색으로 쓰지 말고, 작은 그래픽·표면의 보조색으로 사용해 주세요.
이 값들은 CS Class를 위한 제안 색상입니다. 전체 조화를 위해 조정할 수 있지만 본문·버튼의 대비는 충분히 유지해 주세요.
민트색, 네온, 발광 효과, 순수 검정, 대형 그라데이션 제목은 사용하지 마세요.
첫 제목은 데스크톱 약 56~64px, 모바일 약 34~40px, 본문은 16~18px을 기준으로 읽기 쉽게 구성합니다. 한국어 어절과 의미 단위를 지켜 줄바꿈해 주세요.

[페이지 구성]
1. 상단 헤더와 첫 화면
   로고 ‘CS Class’와 주요 버튼 ‘교실 입장’을 보여 주세요. 스크롤 중이나 모바일에서도 입장 버튼을 쉽게 찾을 수 있어야 합니다.
   제목: ‘정보 수업을 위한 온라인 교실’
   설명: ‘이번 수업을 확인하고, 수업 활동을 시작해요. 지난 활동도 이어갈 수 있어요.’
   주요 버튼: ‘교실 입장’
   제목과 함께 CS Class 웹 수업 화면을 크게 보여 주세요. 수업 확인·활동·이어하기를 암시하는 제품 화면을 사용하되 첫 화면에 모든 설명을 몰아넣지 마세요.
   큰 화면과 제목의 비율·여백으로 인상을 만들고, 글자와 그래픽은 겹치지 않게 배치해 주세요.

2. 이번 수업 확인
   제목: ‘이번 수업을 확인해요’
   설명: ‘선생님이 열어 둔 수업을 확인하고 시작하세요.’
   학생 홈에서 ‘이번 수업’과 ‘수업 시작’이 눈에 들어오는 장면을 보여 주세요.

3. 수업 안의 활동 — 홈의 대표 시연 구간
   제목: ‘수업은 이렇게 진행돼요’
   보조 라벨: ‘수업 구성 예시’
   하나의 큰 수업 화면 프레임을 유지하면서 내부 내용이 다음 세 상태로 전환되게 설계해 주세요.
   - 개념학습: ‘설명과 예시로 내용을 익혀요.’ 짧은 설명과 예시 자료가 보이는 화면.
   - 퀴즈: ‘배운 내용을 확인해요.’ 간단한 문항·선택지·선택 반응이 보이는 화면.
   - 실습: ‘직접 해보며 적용해요.’ 활동 안내와 직접 조작할 영역이 보이는 화면.
   단계가 다른 수업으로 보이지 않도록 화면의 제목·탐색 구조·프레임은 이어지게 해 주세요. 세 개의 동등한 홍보 카드로 나누지 마세요.
   데스크톱에서는 스크롤 진행에 맞춰 현재 단계와 화면 내용이 바뀌고, 단계 선택기로 직접 전환할 수 있게 설계해 주세요.
   모바일에서는 긴 스크롤 고정을 줄이고, 읽을 수 있는 크기의 화면과 직접 선택 가능한 단계로 표현해 주세요.
   이 구성은 한 수업의 예시입니다. 모든 수업이 같은 세 단계여야 한다거나 정답을 맞혀야 다음 단계로 갈 수 있다는 규칙을 만들지 마세요.
   특정 단원의 완성 콘텐츠를 새로 만들 필요는 없습니다. ‘개념 설명’, ‘확인 문제’, ‘실습 활동’처럼 용도를 알 수 있는 한국어 예시를 사용해 주세요.

4. 하던 활동 이어가기
   제목: ‘하던 활동을 이어가요’
   설명: ‘지난 시간에 하던 활동을 다시 열어 보세요.’
   최근 활동과 ‘이어하기’가 보이는 제품 화면으로 짧게 소개해 주세요.

5. 학생과 교사 공간
   ‘학생 공간’과 ‘교사 공간’을 선택해 미리 볼 수 있게 해 주세요.
   학생 설명: ‘이번 수업과 지난 활동을 확인해요.’
   교사 설명: ‘반별 수업을 열고, 이번 수업을 지정해요.’
   이번 디자인 범위 밖의 통계·달력·공지·순위·채점·수업 편집 기능은 추가하지 마세요.

6. 마무리
   문구: ‘내 교실로 들어가세요’
   주요 버튼: ‘교실 입장’
   간결하게 마무리하고 과장된 교육 슬로건을 추가하지 마세요.

[움직임과 조작]
움직임과 시각적 재미는 유지해 주세요. 특히 수업 화면의 상태 전환과 사용자의 조작에 반응하는 부분에 집중합니다.
작은 조작은 약 160~240ms, 내용 전환은 약 300~500ms로 부드럽게 표현하고 과도한 튕김을 피합니다.
모든 요소에 반복 모션을 넣거나 스크롤을 강제로 이동시키지 마세요. 핵심 내용은 애니메이션을 기다리지 않아도 읽을 수 있어야 합니다.
주로 transform·opacity로 구현 가능한 가벼운 연출을 사용하고, 실제 영상이나 무거운 3D 제작을 전제로 하지 마세요.
움직임 줄이기 설정에서는 동일한 정보를 정적 화면과 직접 선택으로 제공해 주세요. 자동 반복 시연에는 멈출 수 있는 방법이 있어야 합니다.
키보드 초점은 뚜렷하게, 조작 영역은 최소 44px, 모바일에서는 가로 넘침 없이 구성해 주세요.

[요청 산출물]
하나의 일관된 디자인 방향으로 공개 홈의 데스크톱·모바일 시안을 만들어 주세요.
대표 구간인 ‘개념학습 → 퀴즈 → 실습’은 세 상태를 각각 확인할 수 있게 제시해 주세요.
정적 화면만 생성할 수 있다면 화면과 별도로 스크롤 전환·클릭 반응·모바일 전환·움직임 줄이기 동작을 짧게 설명해 주세요. 정적 시안을 동작하는 애니메이션으로 표시하지 마세요.
새 가격표, 회원가입 유도, 허구의 통계·후기, 추가 제품 기능은 넣지 마세요.
```
