# UI Component Lab 활용 검토

선생님이 제공한 `ui-component-lab`의 `index.html`, `styles.css`, `components-data.js`, `app.js`를 읽었습니다. 20가지 컴포넌트의 목적·상태·상호작용을 비교할 수 있는 학습 자료입니다. 원본 파일은 수정하지 않았습니다.

## 이번 홈에 반영한 패턴

| 요소 | 적용한 위치 | 동작 |
| --- | --- | --- |
| Tooltip | 상단 움직임 아이콘 | 호버·키보드 초점에 설명 표시, Escape로 닫기, 44px 조작 영역 |
| Dialog | 교실 입장 | 학생·교사 선택, 창 안의 초점 이동, Escape·바깥 클릭·닫기 버튼, 닫은 뒤 초점 복귀 |
| Tabs·Segmented Control | 기존 수업 단계·공간 미리보기 | 이미 쓰던 용도를 유지. 단계를 고르는 조작과 입장 조작을 분리 |

구현은 [home-entry.tsx](../platform/src/components/home-entry.tsx)에 있습니다. 프로젝트에 이미 설치된 Base UI와 기존 Dialog 래퍼로 구현했고 새 UI 패키지는 추가하지 않았습니다.

학습 자료는 Radix의 형태를 참고한 순수 JavaScript 예제입니다. 전체 런타임을 복사하기보다 패턴을 React 컴포넌트로 옮기는 편이 적합합니다. 예를 들어 원본 Dialog의 전역 키보드 이벤트 해제는 닫는 경로마다 같지 않고, Tooltip은 설명에 있는 Escape 동작이 실제 데모에는 없습니다. 홈 구현에서는 라이브러리의 열기·닫기·초점 관리를 사용하고 실제 조작을 검증합니다.

## 대시보드를 논의할 때 검토할 후보

| 요소 | 맞는 상황 |
| --- | --- |
| Segmented Control | 이번 수업·지난 활동 등 2~4개 범위 전환 |
| Combobox | 반이나 수업 선택지가 많아져 검색이 필요할 때 |
| Toast | 저장·초기화 결과를 확인할 때. 실제 처리 결과와 일치해야 함 |
| Drawer | 좁은 화면에서 메뉴나 보조 설정을 열 때 |
| Skeleton | 실제 데이터를 기다리는 시간에 화면 구조를 먼저 보여줄 때 |

대시보드 변경은 선생님과 별도로 방향을 정한 뒤 진행합니다. 기능이 필요해질 때 도입하며, 장식 목적으로 컴포넌트 수를 늘리지 않습니다.
