### 세션·입장 지연 분석 후보

성능 후속 후보는 **교실 입장 준비와 세션 조회 지연의 원인 분리**입니다. 대시보드의 트랜잭션 일괄 조회는 이미 릴리스에 포함됐으며, 위 성능 개선과 별개로 남은 입장 지연을 살펴봅니다.

- 브라우저 흐름은 [HomeEntry](../src/components/home/home-entry.tsx)의 입장 준비 → [SessionProvider](../src/components/session-provider.tsx)의 최초 `refresh()` → [클라이언트 세션 요청](../src/lib/classroom/client.ts) → [인증 라우트](../src/app/api/auth/[action]/route.ts)입니다.
- 서버 흐름은 [auth.ts](../src/lib/server/auth.ts)의 `readSession()` → `identity()` → `authorized()`와 [Firebase 초기화](../src/lib/server/firebase.ts)입니다. 쿠키 없는 익명 요청은 `identity()`에서 종료하므로 `admin()` 호출·Firestore 계정 읽기를 하지 않습니다. 라우트 모듈 로딩·브라우저 요청 시작 지연과 로그인된 세션의 계정 조회 시간을 분리해야 합니다. 현재 코드의 경로 확인이며 병목을 실측해 확정한 결과는 아닙니다.
- 먼저 [기존 측정 방법](DEVELOPMENT.md#대시보드-성능-측정)을 재사용합니다. 같은 커밋·환경·로그인 상태에서 첫 관찰과 반복 5회를 구분하고 입장 버튼 준비·세션 요청 시작/응답·대시보드 조회를 비교합니다. 분석 완료 기준은 지연이 발생하는 구간과 근거, 가장 작은 변경 후보를 제시하는 것입니다. 코드 변경 뒤에는 [검증 절차](DEVELOPMENT.md#검증)에 따라 로딩·세션 만료/교체·권한 경계를 확인합니다.

### 다른 환경으로 옮길 자료

로컬 이식 묶음은 Git 제외 `scratch/handoff/cs-class-2026-10-01-handoff.zip`입니다. 안의 `TRANSFER.md`·`handoff-manifest.json`에서 기준 HEAD·브랜치·전체 상대 경로·바이트 SHA-256을 확인합니다. `workspace/`에는 이번에 변경한 문서, 신규 참고 자료/체험 화면, 아래 신규 소스/검사 9개를 포함합니다. 커밋·원격 업로드·완전한 저장소 백업은 아닙니다.


새 체크아웃은 위 기준 커밋을 출발점으로 하고 `workspace/` 파일을 같은 경로로 적용합니다. 기존 체크아웃이라면 **기존 수정·신규 파일 충돌을 먼저 비교**합니다. 원본 PPT·추출 미디어·`.env*`·인증/키·학생 자료·`.git`·node_modules·빌드·Java/브라우저/Entry 자산 캐시는 담지 않았습니다. 설치/자산은 `npm ci`, 실제 Firebase 설정은 별도 경로를 따릅니다. 이 묶음 자체도 Git 밖의 로컬 파일이므로 다른 PC에 자동 전달되지 않으며 사용자가 안전한 경로로 옮겨야 합니다.

수업 내용과 대화 구상은 Git에 넣을 담당 문서에 요약했습니다. 이전 완성형 HTML 시안은 대화의 시각화 영역에만 있지만 세 장면의 후보 경험은 PRD에 보존했으므로 그 HTML이나 Codex 대화가 없어도 논의 맥락을 이해할 수 있습니다. 그림 원본이 필요한 후속 작업만 원 PPT를 별도 확인합니다.
