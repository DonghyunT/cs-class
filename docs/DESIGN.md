# Design System: CS Class

갱신: 2026-10-30(Asia/Seoul). 공개 홈과 로그인·대시보드의 시각 디자인 기준, 수업 화면과 선택 복습의 UI 레이아웃 명세입니다. 제품 정책은 [PRD](PRD.md), 실행 및 검증 절차는 [DEVELOPMENT](DEVELOPMENT.md), 상태는 [HANDOFF](HANDOFF.md)를 따릅니다.

## 1. Visual Theme & Principles

중학생이 매일 사용하는 정보 수업 플랫폼입니다. 담백한 한국어, 넓은 여백, 읽기 쉬운 큰 제목, 실제 사용 과정을 투명하게 보여주는 화면으로 구성합니다. 학생의 눈높이에 맞춘 존중의 태도를 유지하며 직관적이고 친절한 정보 전달을 지향합니다.

- **여백과 밀도 (Density):** 한 화면 구간에서는 한 가지 핵심 내용에 집중합니다. 넉넉한 여백과 높은 가독성을 균형 있게 유지합니다.
- **시각적 질서 (Hierarchy):** 제목과 카드 배치의 일관된 여백으로 정돈된 리듬을 만듭니다. 콘텐츠 간의 위계와 경계를 명확히 하여 학생의 인지 부하를 줄입니다.
- **인터랙션 원칙 (Motion):** 공개 홈의 대표 시연과 조작 피드백에 가벼운 트랜지션(160~240ms)을 집중하고, 학습 작업 공간에서는 정보 확인과 조작의 명확성을 최우선으로 합니다.
- **타이포그래피:** 프로젝트 로컬의 Pretendard Variable을 기본 글꼴로 사용합니다.

## 2. Design Tokens & Semantic Roles

### 2.1 컬러 토큰 (Color Palette)

밝은 무채색 표면 위에 맑은 파랑(`Clear Blue`)을 주요 강조색으로 쓰고, 색마다 뜻을 하나씩 둡니다. 단계색(개념 파랑·퀴즈 보라·실습 청록)은 수업 화면과 진도 표시에만, 보조색 금색은 성취(배지·살펴볼 학생), 자두색은 일정·할 일에만 씁니다. 한 화면의 강조색은 따뜻한 안내색을 빼고 3개 이하이며, 색만으로 뜻을 전하지 않습니다.

### 2.2 타이포그래피 스케일 (Typography Rules)

- **기본 글꼴 체계:** `var(--font-pretendard)`, "Malgun Gothic", sans-serif.
- **헤드라인 크기 및 행간:**
  - 대형 첫 제목: 데스크톱 최대 82px (행간 1.2), 모바일 34~50px.
  - 구간 제목 (h2): 28~44px (굵기 600~700). 크기와 여백으로 명확한 계층 분리.
  - 소제목 (h3): 20~26px (굵기 600).
- **본문 텍스트:**
  - 기본 본문: 15~16px (행간 1.65). 최대 읽기 너비 약 65ch (한국어 30~42자).
  - 보조 텍스트: 13~14px. 보조 설명 및 부가 메타데이터에 적용하며, 충분한 명암비를 유지합니다.
- **숫자 서식:** 대시보드 통계나 진도율 수치는 `tabular-nums`를 적용해 숫자 자릿수 변경 시 레이아웃 흔들림을 방지합니다.
- **문구 톤앤매너:** 학생에게 친근하고 정중한 `~해요`, 권유는 `~하세요`, 버튼은 `교실 입장`, `수업 시작`, `이어하기`처럼 간결한 명사형/동사형을 사용합니다. 과도한 수식어보다는 명확하고 직관적인 정보 전달을 우선합니다.
- **학생이 아는 말:** 교과 용어는 처음 나오는 곳에 한 줄 풀이를 붙이고, 줄임말·은어·영어 라벨을 쓰지 않습니다. 바뀌는 이름 뒤 조사는 받침에 맞추거나, 맞출 수 없으면 `‘이름’ 정보는`처럼 조사가 바뀌지 않는 말로 씁니다.
- **버튼 이름:** 같은 행동은 모든 수업에서 같은 이름을 씁니다(개념 확인 `정답 확인`, 도움 열기 `힌트 보기`, 단계 건너가기 `먼저 실습하기`·`퀴즈로 이동`). 이름은 실제 효과의 범위를 말합니다(예: `무대 초기화`, 문항으로 옮겨 가는 `문제 N 결과 보기`).

### 2.3 레이아웃 및 반응형 기준선 (Breakpoints)

- **데스크톱:** 최대 1,440px 기준 그리드 (콘텐츠 최대 너비 1,200~1,440px).
- **태블릿 / 서랍형 전환선 (820px):**
  - 화면 폭 820px 이하에서 대시보드 좌측 사이드바가 모바일 서랍형 메뉴(Drawer)로 전환됩니다.
  - 수업 헤더의 820px 이하 배치는 [§4.1](#41-수업-전용-공통-틀-lessonshell)을 따릅니다.
- **모바일:** 390px 기준 (최소 320px까지 가로 스크롤 없이 유연하게 축소).
- **학교 기기 폭:** 학습 작업 도구(엔트리 작업실 등)는 1,024px 가로 화면에서 잘림·페이지 가로 스크롤 없이 전체가 보입니다. 더 좁은 화면은 작업 영역 안 가로 스크롤이나 세로 배치로 작업을 이어 갈 수 있게 합니다.
- **스크롤바 안정화:** 문서 루트(`html`)에 `scrollbar-gutter: stable`을 적용해 모달 열림이나 동적 콘텐츠 로드 시 레이아웃 흔들림(CLS)을 방지합니다.
- **스크롤바:** 사이트 전체 스크롤바는 얇게(`scrollbar-width: thin`, 연회색 `scrollbar-color`) 그려 모달·패널에 스크롤이 생겨도 자리를 적게 차지합니다.

## 3. 공통 컴포넌트 명세 (Global Components)

- **상단 글로벌 헤더:** 좌측 브랜드 로고, 중앙 목차 앵커, 우측 움직임 조절 아이콘 및 `교실 입장` 버튼의 3개 구획으로 나뉩니다.
- **공개 홈 첫 화면:** 주 버튼은 학생 로그인으로 바로 가는 `학생으로 입장`(로그인한 상태면 `내 교실로 가기`), 그 옆 보조 버튼이 소개로 내려가는 `수업 방식 보기`이고, 아래 작은 글씨로 `선생님으로 입장`을 둡니다. 정면의 큰 버튼은 입장이어야 학생이 소개 버튼을 먼저 누르지 않습니다.
- **버튼 (CTA):**
  - 주 버튼: Clear Blue 배경, 흰색 텍스트, 최소 높이 44~48px, 둥근 모서리 10~12px. 누르면 1px 내려가 눌린 느낌을 줍니다.
  - 보조 버튼: 투명 또는 옅은 무채색 표면. 주 버튼의 시각적 위계를 방해하지 않습니다.
  - 터치 타깃: 모바일과 데스크톱 모두 인터랙티브 요소는 최소 44×44px를 권장합니다.
- **입력창 (Input / Select):**
  - 상단 라벨, 하단 오류 메시지. 키보드 포커스는 [globals.css](../src/app/globals.css)의 공통 외곽선(`button`·`a`·`input`·`select`에 `3px solid #83A9F5`, 4px 띄움)이 기본이고, 컴포넌트가 따로 정할 때는 `3px solid #376FC8`을 씁니다(공용 Select 트리거와 여러 화면의 모듈 CSS). 외곽선을 지우지 않습니다.
  - 새 선택 상자는 공용 [`ui/select`](../src/components/ui/select.tsx)를 씁니다. 목록은 16px 둥근 모서리의 공통 팝오버, 항목별 10px 라운드·파란 하이라이트·체크 표시입니다.
  - 남은 네이티브 `<select>`는 지원 브라우저(Chromium 계열 customizable select)에서 `appearance: base-select`로 같은 모양이 되고, 미지원 브라우저는 시스템 목록을 씁니다.
- **대화상자:** 공통 닫기 버튼은 36×36px 정사각형(`icon-lg`)입니다.
- **알림 및 토스트 (Toast):**
  - 수업 설정 저장 성공 등 피드백은 우측 하단에 약 4초간 토스트로 노출되며 본문 레이아웃을 밀어내지 않습니다.
  - 호버 또는 포커스 시 닫힘 타이머를 일시 중지하며 닫기 버튼을 제공합니다.
- **스켈레톤 및 로딩 상태:**
  - 첫 데이터 조회 시 실제 UI 영역 형태의 스켈레톤을 렌더링하며, 재조회 시에는 기존 화면을 유지한 채 미세 인디케이터만 표시합니다.
- **손들기 일시 중지 시 배치:** 손들기가 중지된 동안([PRD §5.5](PRD.md#설정과-손들기)) 학생 헤더의 손들기 버튼, 교사의 요청 패널·건수 안내와 전용 래퍼를 마운트하지 않습니다. 남은 요소는 기존 Flex/Grid 흐름으로 재배치하고 대체 플레이스홀더·안내 배너는 추가하지 않습니다. 저장·메뉴·수동 새로고침의 접근성을 유지합니다.

## 4. 도메인 전용 UI 컴포넌트 명세

### 4.1 수업 전용 공통 틀 (`LessonShell`)
<a id="수업-전용-공통-틀"></a>
<a id="수업-전용-공통-틀--2026-10-06-구현"></a>

학생 수업 화면은 대시보드의 좌측 메뉴를 숨기고 학습에 몰입할 수 있는 전용 셸(`LessonShell`)을 사용합니다.

- **헤더 구성:** 가용 화면 폭 전체를 활용합니다. 821px 이상은 좌(수업 나가기·이번 수업 이동) / 중앙(줄바꿈 가능한 수업 제목·학습 상태) / 우(저장 버튼·저장 상태, 세로 구분선, 학생 메뉴) 3구획입니다. 다른 수업이 이번 수업이면 나가기 옆에 엷은 파랑 알약형 `이번 수업: 제목 →` 링크를 두고(길면 말줄임, 전체 이름은 툴팁), 링크 유무와 관계없이 헤더 높이를 같게 유지합니다. 820px 이하는 제목이 둘째 줄 전체 폭으로 내려가고 이번 수업 링크는 제목 아래에 둡니다. (양 끝 여백: 데스크톱 16px, 820px 이하 12px).
- **콘텐츠 영역 폭 기준선:**
  - 개념 학습: 최대 **1,120px** (목록 + 본문).
  - 퀴즈: 최대 **1,120px**. 정규·복습 모든 수업이 같은 퀴즈 화면(`LessonQuizPanel`)을 씁니다.
  - 실습 작업실 (기본): 최대 **1,440px**.
  - 작업실 넓게 보기: 브라우저 가용 폭 전체 (좌우 여백 16px / 모바일 12px).
- **개념 화면 그림(조건·반복 수업):** 공통 개념 화면의 `예를 들어 볼까요?` 위에 개념마다 작은 정적 그림 하나를 둡니다(`concept-visual.tsx`, 개념 ID별 등록). 옅은 파랑·보라 바탕 상자 안에 참·거짓 타일, 엔트리 색 블록(흐름·붓), 순서도·도형 SVG를 쓰고 글자는 14px 이상입니다. 조건 `cc4`(중첩 선택)와 반복 `lc1`(정삼각형)·`lc3`(벽에 닿을 때까지)·`lc4`(클릭 수 5에서 다음 모양)는 엔트리가 그린 블록을 3배로 내보낸 캡처(`public/concepts/`, `alt=""`, 표시 폭 = CSS 크기 × 1.226, 예: `cc4` 320px)를 쓰고, 반복 그림은 미션 조립(정사각형 4번·100·90°, 금고 1234, 나무 5·10·15·20·25)을 그대로 보이지 않습니다(`tests/lesson-feedback.test.ts`). 다시 캡처할 때는 Windows에서 로컬 `/entryjs/workspace.html?exercise=programming`을 최상위로 열어 `Entry.loadProject`로 `buildProgrammingProject` 예시를 불러오고, 개념 블록(이벤트가 개념이면 시작 블록)의 `block.view.getDataUrl()` SVG에서 `<image>` 아이콘을 data URL로 바꾼 뒤 (너비+2)·(높이+2)의 3배 캔버스에 그려 PNG로 저장합니다(이 방법으로 `cc4`가 바이트 단위로 같게 재현됨). 예시 작품이나 블록 문구가 바뀌면 다시 캡처합니다. 그림 전체는 `role="img"`와 한 줄 설명(`aria-label`)을 가지며 조작 요소는 없습니다. 복습 수업·「프로그래밍의 기초」는 각자의 체험 화면을 씁니다.
- **개념 목록 안내와 상태:** 목록 아래 안내 문장은 실제로 할 수 있는 행동만 말합니다. 조작 체험이 있는 「프로그래밍의 기초」·복습은 `직접 바꾸고, 결과를 보고…`, 정적 그림만 있는 조건·반복은 `예시를 읽고 결과를 예상한 뒤…`를 씁니다. 목록 상태는 `확인 완료`·`다시 생각해 보기`(마지막 확인이 오답)·`지금 보는 개념`·`확인 전`이고(기초 수업은 마지막 두 상태 대신 개념 부제), 확인 결과 문구 앞에 `맞았어요.` 또는 `다시 생각해 보기`를 붙입니다.
- **실습 집중 모드:**
  - 단계 탭 우측의 `실습 집중 모드` 알약형 토글(확대/축소 아이콘)을 누르면 상단 안내 및 미션 상세가 접히고 작업실 캔버스가 전체 폭으로 확장됩니다.
  - 샌드위치, 추상화, 순서도, 프로그래밍, 일반 Entry 모두 동일한 집중 모드 인터랙션을 공유합니다.
- **논리적 포커스 복구:** 모달 닫힘, 미션 제출 완료, 폭 전환 시 포커스는 논리적 주 조작 대상(버튼, 입력창, 섹션 제목)으로 안전하게 이동해야 합니다.
- **다음 행동으로 초점:** 학생은 초점이 간 곳을 따라 움직이므로, 한 단계를 마친 뒤에는 결과 문구보다 다음에 누를 버튼에 초점을 둡니다. 개념 확인이 정답이면 `다음 개념`(마지막 개념은 `퀴즈로 이동`)이 주 버튼 모양으로 바뀌고 초점을 받으며, 결과 문구는 그 버튼의 설명(`aria-describedby`)으로 읽힙니다. 오답이면 결과 문구에 초점을 둡니다. 퀴즈 회차를 채점하면 틀린 문제가 있을 때 `틀린 문제만 다시 풀기`, 모두 맞으면 `실습으로 이동`에 초점을 두며, 회차 요약은 그 버튼의 설명으로 읽힙니다. 미션 제출 뒤에는 `다음 미션`, 마지막 미션은 완료 문구에 초점을 둡니다. 수업 완료 안내는 화면을 막지 않도록 초점을 옮기지 않습니다([§4.2](#42-저장-상태-표시와-이탈-확인)). 우리 반 질문에서 질문을 등록하면 펼쳐 둔 `질문 쓰기`를 접고 초점을 오른쪽에 열린 그 질문의 제목으로 옮깁니다(실패하면 펼친 채 입력을 지킵니다).

### 4.2 저장 상태 표시와 이탈 확인

수업 상단 헤더의 저장 상태는 한 줄 문구(`role="status"`, 14px, `#526173`)로 보여 줍니다. 아이콘은 `저장 완료`일 때의 구름 체크(CloudCheck)만 씁니다. 문구는 `lesson-editor.tsx`의 `saveLabel`이 정합니다.

| 상태 | 문구 |
| :--- | :--- |
| `saved` (기록 있음) | `저장 완료` + 구름 체크 아이콘 |
| `saved` (기록 없음) | `아직 학습 기록이 없어요` |
| `dirty` | `저장하지 않은 변경 있음` |
| `saving` | `저장 중…` |
| `failed` | `저장 확인 필요` |
| 충돌 표시(`conflict`) | `저장 기록 충돌` |
| 단계 이동 중 | `입력 확인 후 이동 중…` |
| 교사 미리보기 | `이 창에서 체험 중` / `체험 작품 확인 필요` |

- **실패·충돌 안내:** 요청이 실패하면 본문 위에 오류 패널(`role="alert"`, 배경 `#FFF4EF`)이 열립니다. 일반 실패는 `저장 다시 확인` 버튼을, 충돌은 제목 `저장 기록이 서로 달라요.`와 `서버 기록과 비교` 버튼을 보여 줍니다. 비교는 모달이 아니라 화면 안 비교 섹션에서 `현재 입력을 새 버전으로 저장`과 `서버 기록으로 이어하기` 중 하나를 고릅니다.
- **`conflict`의 뜻:** 저장 상태(`SaveState`, [PRD §3.2](PRD.md#작업-저장과-통신-비용)의 4가지)가 아닙니다. 저장·채점·제출 같은 요청이 revision 충돌로 실패하거나, 다시 열었을 때 보관한 입력과 다른 창의 기록이 어긋날 때 켜지는 표시입니다.
- **이탈 확인창(`navigation-provider.tsx`):**
  - 미저장 내용이 있을 때 외부 링크·브라우저 뒤로가기·로그아웃을 누르면 화면 중앙 대화상자 `저장하지 않은 변경이 있어요`가 열립니다.
  - `저장 후 나가기`(주 버튼) / `저장하지 않고 나가기`(외곽선 버튼) / `취소`(텍스트 버튼). 처음 초점은 `취소`에 둡니다.
  - Esc 키나 바깥 클릭은 `취소`로 닫히며, 원래 누른 조작 버튼으로 초점을 돌려 놓습니다.
- **수업 완료 안내(`lesson-complete.tsx`):** 진도가 100%가 되는 순간 오른쪽 위(헤더 아래 84px, 820px 이하는 위 16px, 너비 최대 380px)에 흰 카드로 띄웁니다. 600px 이하에서는 헤더(나가기·저장)를 가리지 않게 아래쪽(좌우·아래 16px)에 두고 큰 아이콘을 뺍니다. 방금 끝낸 활동의 결과 문구가 보통 화면 아래쪽에 있어 가리지 않게 위에 두며, 헤더(z-index 20)의 계정 메뉴와 토스트(40)보다 아래 층(19)입니다. 오른쪽 위 44px 닫기(X), 초록 원 안의 축하 아이콘, 제목 `이 수업을 모두 마쳤어요!`, 단계별 완료 칩, `이번에 오른 배지` 칩(이번 완료로 받은 수가 1 늘어난 배지만), `내 배지 보기`(주 버튼, 학생만, `내 배지` 화면으로 이동)·`계속 둘러보기`(외곽선) 순서입니다. 모달이 아니라 초점을 옮기지 않고 화면 읽기용 상태 문구로 알리며, `계속 둘러보기`·X(초점은 현재 단계 제목으로)나 Esc(다른 대화상자가 열려 있으면 무시)로 닫습니다. 떠오르는 움직임은 `prefers-reduced-motion`에서 끕니다. 완료한 수업에는 단계 탭 아래에 초록 띠(`#E6F3EE`, 체크 아이콘, `이 수업은 완료했어요.`)를 둡니다.
- **바로 저장되는 결과와 저장 버튼이 필요한 영역:** 개념 확인·퀴즈 채점처럼 버튼을 누르는 순간 서버에 저장되는 결과에는 결과 바로 아래(또는 결과 문단 안)에 `저장 버튼 없이 바로 저장돼요`를 적습니다(교사 미리보기는 `이 창에만 남아요`). 작업실처럼 저장 버튼이 필요한 영역은 헤더의 저장 상태와 작업실 상태 줄의 `저장` 항목으로 보여 줍니다. 두 표시를 한 문장으로 합치지 않습니다.

### 4.3 3구간 원형 진도 게이지 (`ActivityProgressRing`)

대시보드 메인에서 정규 수업의 전체 필수 활동 완료율을 시각화하는 위젯입니다.

- **기하 구조:** SVG `viewBox="0 0 180 180"`, 중심 `(90, 90)`, 반지름 `78px`, 선 두께 `14px`.
- **3구간 120도 호 분할:** 개념(0°~120°)·퀴즈(120°~240°)·실습(240°~360°)이며 색은 [§2.1](#21-컬러-토큰-color-palette)의 Stage 색을 씁니다. 완료한 활동이 하나도 없는 구간은 시작점에 반원(지름 14px) 표시를 두어, 다른 단계를 진행 중이어도 아직 시작하지 않은 단계가 구분되어 보입니다.
- **중앙 수치:** 세 구간의 완료율을 1/3씩 평균한 정수 퍼센트(내림, 모두 끝나야 100) (`#28548E`, 34px bold, `tabular-nums`) 및 하단 `전체 진도` 라벨. 계산 기준은 [PRD §5.1](PRD.md#대시보드의-전체-필수-활동-완료율)입니다.
- **인터랙티브 툴팁:** 마우스 호버 또는 키보드 포커스 시 해당 단계의 세부 완료 개수와 완료율 툴팁(`n/m개 완료 · p%`)을 가운데에 띄웁니다.

### 4.4 학생·교사 대시보드
<a id="학생교사-대시보드"></a>
<a id="대시보드-파일럿--노션을-참고한-내-할-일"></a>

- **사이드바 반응형:** 821px 이상에서는 좌측 고정 사이드바로 표시되며, 820px 이하에서는 햄버거 메뉴를 통한 서랍형으로 전환됩니다.
- **교사 대시보드 툴바 (`TeacherToolbar`):** 담당 반 선택 셀렉터, 최종 갱신 시각, 수동 새로고침 버튼을 둡니다.
- **교사가 확인할 일 카드:** 카드 제목 아래 책 아이콘과 선택 수업 이름, 학생 대시보드 진도 링과 같은 단계 색(§2.1 Stage 색)의 점·8px 막대와 큰 숫자(`1/28명`)를 둡니다. 확인 요청이 1명 이상이면 그 행을 따뜻한 안내색(`--warm-*`)으로 맨 위에 강조하고, 학습 현황 행의 숫자는 굵게, 최근 제출 학생은 번호 칩·제출 작품 수·최근 제출 시각을 보여 줍니다.
- **이번 수업 카드:** 학생·교사 모두 데스크톱에서 좌측 진도 링, 우측 이번 수업(책 아이콘 라벨·제목·설명·행동 버튼) 순서입니다. 학생은 학습 시작/이어하기, 교사는 `수업 미리보기`를 둡니다. 교사 진도 링은 이번 수업이 선택 수업과 같을 때만 표시되고, 없으면 수업 정보가 전체 폭을 씁니다. 600px 이하에서는 수업 정보가 위, 진도가 아래입니다.
- **수업별 학습 진도·수업 목록의 완료 표시:** 완료 수업의 상태 칩(`완료`·`복습 완료`)은 Stage Practice 계열 초록(`#E6F3EE` 바탕, `#1F6B5C` 글자)입니다. 수업 목록 카드는 완료 시 `#B8DCCF` 테두리, 옅은 초록 그라데이션, 왼쪽 4px `#268673` 강조선을 둡니다. 진행 중인 정규 수업은 진도 아래에 `남은 활동` 한 줄(13px, `#526173`)을 둡니다.
- **배치:** 데스크톱 두 열에서 학생은 왼쪽 `수업별 학습 진도`·`내 배지`, 오른쪽 `다가오는 일정`·`내 할 일`이고, 교사는 왼쪽 `교사가 확인할 일`·(손들기)·`살펴볼 학생`, 오른쪽 일정·할 일입니다. 1,100px 이하 한 열에서는 왼쪽 열 다음 오른쪽 열 순서로 쌓입니다.
- **살펴볼 학생 (교사):** `교사가 확인할 일`과 같은 행 목록(숫자 굵게, 화살표)이며 제목 아이콘은 금색(`--gold-ink`)입니다. 학생 이름·학번은 두지 않습니다.
- **내 배지 (`StudentBadges`):** 대시보드에서는 `수업별 학습 진도` 아래 패널로, `이번 수업 도장` 4칸(44px 원, 찍은 도장은 배지 색 이중 테두리와 -8° 기울임, 아닌 것은 회색 점선)과 `도장 n개 · 별 · 희귀 배지 a/b · 깜짝 배지 c/d` 한 줄, 제목 줄 오른쪽 `모두 보기`입니다. `/student/badges`는 `minmax(220px, 1fr)` 격자(600px 이하 한 줄) 카드이며 배지마다 고유 색(개념 파랑·만점 보라·미션 초록·완주 주황·도전 붉은 주황·복습 청록·오뚝이 새싹 초록·생각 기록가 남보라·첫 작품 분홍·도장 갈색)을 씁니다. 단계 배지의 메달은 별 수에 따라 동→은→금→보라→무지개, 별 5개와 `다음 별까지 n개` 막대를 둡니다. 희귀·깜짝 배지는 받기 전에는 빗금 배경·자물쇠·`???`·귀띔이고, 받으면 희귀 배지는 금빛 배경·빛나는 메달·지나가는 반짝임, 깜짝 배지는 고유 색 카드로 열립니다. 수업 중 배지를 새로 받으면(완료 카드가 뜨는 순간 제외) 오른쪽 아래 토스트(`SuccessToasts`, 4초)로 알립니다. 카드는 마우스·초점에서 4px 떠오르며 살짝 기울고, 처음 보는 받은 배지는 오른쪽 위 `새로 받음`과 함께 톡 튀어 오릅니다. `prefers-reduced-motion`에서는 반짝임·떠오름·튀어 오름을 모두 끕니다. 별 단계는 색 외에 별 개수와 화면 읽기용 `별 5개 중 n개`로도 알리고, 이름 뒤에 `받은 배지`/`아직 받지 않은 배지`/`아직 받지 않은 희귀 배지`/`아직 받지 않은 깜짝 배지`를 붙입니다.
- **다가오는 일정 패널:** 학생은 `전체 보기`, 교사는 `일정 관리` 링크로 반 일정 화면에 들어갑니다.
- **내 할 일 (체크리스트):** 체크박스와 텍스트 행이 1개 단위를 이룹니다. 완료 시 취소선과 옅은 텍스트로 전환됩니다. Enter로 추가·편집하고 Esc로 취소해 키보드로도 다룰 수 있습니다.
- **일정 및 미니 달력:** 일요일부터 토요일 순(`일 월 화 수 목 금 토`)으로 표시하고 일요일은 `#B44C43`, 토요일은 `#4F6B9A` 글자색을 씁니다(오늘·일정 있는 날 강조가 우선). 오늘 날짜와 일정이 존재하는 날을 강조 표시하며, 다가오는 일정 최대 5개를 날짜순으로 카드에 정돈합니다. 지난 일정은 native `<details>`로 접어둡니다.
- **임시 비밀번호 일괄 발급 (`BulkIssuePasswords`):** 학생 현황 결과 줄의 `임시 비밀번호 한꺼번에 발급` 버튼(320px에서는 다음 줄로 내려감)으로 엽니다. 선택 단계는 학번 체크 칸 격자(칸 높이 44px 이상, `최근 접속`·`HH:MM까지 발급됨` 보조 문구), 결과 단계는 학번·가린 값 표와 `비밀번호 보이기`·`쪽지 인쇄`·`전달 완료` 버튼입니다. 결과가 있으면 바깥 클릭으로 닫히지 않습니다. 인쇄할 때만 `body` 바로 아래 쪽지 묶음(2열, 점선 자르는 선)이 보이고 나머지 화면은 숨깁니다.
- **명단에서 뺀 계정:** 학생 현황 표 아래 점선 테두리의 접힌 `<details>`(`명단에서 뺀 계정 n개`, 계정이 없으면 숨김)입니다. 줄마다 학번·상태(`체험 계정 · 로그인 가능` / `명단에서 뺌 · 로그인 막힘`)를 두고, 뺀 학생만 `다시 넣기` 버튼이 있습니다. 학생 줄의 `명단에서 빼기`는 `비밀번호 초기화` 옆 보조 버튼이며 확인 창(초점은 `취소`)을 거칩니다.
- **반 공통 첫 입장 (`FirstEntry`):** 학생 현황 결과 줄의 `첫 입장 열기`(비밀번호를 정해야 하는 학생이 있을 때만)로 엽니다. 코드는 프로젝터에서 읽히게 가운데 큰 고정폭 숫자(`clamp(44px, 12vw, 72px)`)로 보이고, 남은 시간(`role="status"`)과 `이번에 입장한 학생`·`아직 비밀번호를 정하지 않은 학생` 학번 목록(최대 32vh 스크롤)을 둡니다. 열린 동안 버튼은 `입장 현황 새로고침`·`10분 연장`·`첫 입장 닫기`, 닫히거나 만료되면 `닫기`·`새 코드로 다시 열기`입니다.
- **교사 제출 작품 대화상자 (`SubmissionViewer` · `EntryProjectPreview`):**
  - **제출 목록:** 열린 수업이 둘 이상이면 머리말 아래 `볼 수업` 선택을 둡니다. 안내 문장은 목록 위에 두고, 미션마다 테두리 카드형 `<details>`(요약 높이 52px 이상, 제목 굵게·제출 시각 보조색)로 보여 주며 가장 최근 제출본만 펼칩니다.
  - **대화상자 폭 기준:** 일반 관리 모달은 `min(560px, calc(100vw - 32px))`, 제출 작품 모달 기본 상태는 `min(860px, calc(100vw - 32px))`입니다. 인라인 작업실을 열면 전환 애니메이션 없이 동일 레이아웃 프레임에서 즉시 `min(1220px, calc(100vw - 32px))`로 넓어집니다(`[data-workspace-open="true"]`, `:has(.entryRunner)`).
  - **프로그래밍 작품 시각화:** 상단에 오브젝트 요약 칩(아이콘·이름·초기 좌표 `X/Y`·시작 묶음 수)과 `작업실에서 실행해 보기` / `작업실 닫기` 토글 버튼을 배치합니다. 본문에는 오브젝트별 `시작 묶음 N`(또는 `블록 묶음 N`) 카드 그리드와 8대 카테고리 색상 알약 블록(`entryBlockPill`), 조건·반복 중첩 분기(`entryBranches`, `아니면` 구분선 포함)를 표시하며, 파싱할 수 없는 구형 데이터는 번호 매김 목록(`<ol>`)으로 안전하게 폴백합니다.
  - **인라인 실행 작업실 및 2단계 `Escape` 포커스 복구:** 한 번에 하나의 미션 작업실만 열리며(격리 iframe 가로 스크롤 영역 `min-width: 760px`, 높이 `620px`), 작업실이 열린 상태에서 `Escape`를 누르면 작업실만 먼저 닫히고 토글 버튼으로 초점이 돌아갑니다. 작업실이 닫힌 상태에서 `Escape`를 다시 누르면 대화상자가 닫히고 원래 누른 학생 행 버튼으로 초점이 복구됩니다.

## 5. 수업별 실습 작업실 레이아웃

### 5.1 프로그래밍 기초 실습 화면 구성
<a id="프로그래밍-13차시--경험-검토용-표현"></a>

운영 경로 `/classroom/programming-13`의 시각 구성 명세입니다.

- **실습 화면 2열 레이아웃:**
  - 1,340px 이상: 좌측 미션 안내(260px) + 우측 EntryJS 작업실을 16px 간격으로 나란히 배치.
  - 821~1,339px: 첫 줄 왼쪽 목표·오른쪽 `만든 뒤 확인하기`, 둘째 줄 전체 폭 `블록 연결 힌트 보기` + 하단 작업실. 조립 순서는 내부 스크롤 없이 모든 단계를 펼칩니다. 이 폭에서만 안내 묶음(`PracticeGuidance`의 `<details>`와 `::details-content`)을 `display: contents`로 풀어 두 카드를 격자에 올리고, 집중 모드에서는 풀지 않습니다.
  - 820px 이하: 상단 안내(1열) + 하단 작업실.
- **무대 변수 칸:** A·B를 쓰는 미션은 `A`·`B` 값 칸을, 나무 키우기는 `클릭 수` 칸을 무대 왼쪽 위에 둡니다(A 아래 B). 질문을 하면 무대 아래쪽에 대답 입력창이 열리므로 그 자리를 피하고, 미션끼리 같은 자리로 맞춥니다. 위치는 `buildProgrammingProject`가 정하고, 저장된 작품도 불러올 때 같은 자리로 다시 맞춥니다(채점 키에는 들어가지 않음). 나무 키우기 시작 작품의 물뿌리개는 이 칸과 겹치지 않게 무대 왼쪽 가운데(x -150, y 0)에 둡니다.
- **엔트리 오브젝트 추가 창(조건·반복 수업):** 넓은 대화상자(최대 1,080px, 공통 대화상자의 `sm:max-w-sm`보다 높은 선택자로 덮어씀)에 이름 검색, 왼쪽 분류 버튼(`aria-pressed`), 썸네일 격자(지연 불러오기, 모양이 여러 개면 ‘모양 N개’)와 출처 문구를 둡니다. 600px 이하에서는 분류 버튼이 위로 줄 바꿈됩니다. 창 높이는 분류와 관계없이 같고(`height: min(62vh, 560px)`) 목록만 스크롤하며, 스크롤바 자리는 항상 비워 둡니다(`scrollbar-gutter: stable`). 미션 의도에서 벗어난 작업은 공통 토스트(`type: "warning"`, 경고 아이콘)로 알리고 되돌리지 않습니다.
- **미션 안내 카드:** 목표는 늘 보이게 짧게 씁니다. 그 아래 접힌 `블록 연결 힌트 보기`에 한 줄 요약, 번호 조립 순서, 💡 한 줄을 둡니다. 요약은 목표를 되풀이하지 않고 먼저 볼 곳(꾸러미, 헷갈리는 블록)을 말합니다. 순서는 5단계 이하이며 한 단계에 행동 하나와 블록 칩을 쓰고 1,024px에서 한 줄, 1,440px의 222px 칸에서 4줄을 넘지 않습니다. 블록 칩은 학생이 만들 블록을 실제 값을 넣은 모양(예: `A를 대답으로 정하기`, `4번 반복하기`)으로 쓰되, 팔레트에서 그 블록 하나를 찾을 수 있게 고정 낱말(정하기·만큼 움직이기·묻고 대답 기다리기 등)과 팔레트 기호(곱하기 `x`)를 지킵니다. 칩은 엔트리 꾸러미 색([§2.1](#21-컬러-토큰-color-palette)의 강조선·옅은 바탕, 진한 글자)으로 글 사이에서 줄바꿈되고, 화면 읽기에는 평문으로 읽힙니다. 💡는 미션당 최대 한 줄로 이유를 말하고 순서 목록 뒤 별도 문단에 둡니다. 단계를 모두 따르면 기준 정답과 같은 블록 구성이 되지만 하나하나 설명하지 않습니다. 시작 작품에 시작 블록이 없는 미션은 1단계 맨 앞에 `시작하기 버튼을 클릭했을 때` 칩을 두고, 블록의 ▾를 바꿔야 하는 단계에는 `(A▾를 B로)`처럼 바꿀 칸을 적습니다. 821~1,339px(집중 모드 아님)에서는 💡와 블록 목록 요약을 순서 오른쪽 240px 칸에 두어 힌트를 펼쳐도 작업실이 230px 넘게 내려가지 않게 하고, 블록 목록을 펼치면 순서 아래 전체 폭으로 돌아갑니다. 미션이 받는 블록은 그 안의 접힌 목록(`이 미션에서 쓸 수 있는 블록`)에 팔레트 순서·팔레트 표기 칩으로 두며, 결과를 바꾸지 않는 블록과 같은 뜻으로 받는 블록은 빼고 보여 줍니다. 만든 작품으로 확인할 사례(판단 미션은 경계값 포함)를 적은 `만든 뒤 확인하기` 카드는 힌트 다음에 12px 띄워 둡니다(821~1,339px에서는 목표 옆, 읽기 순서는 힌트 다음 그대로).
- **EntryJS 작업실 크기:** 실제 편집기 및 무대는 최소 가로 960px, 세로 660px(저해상도 620px)를 확보하며, 1,024px 가로 화면에서는 페이지·작업실 영역 모두 가로로 밀리지 않고 무대·팔레트·조립판(300px 이상)이 다 보입니다. 더 좁으면 페이지 가로 스크롤 대신 작업실 내부 가로 스크롤을 허용합니다. 엔트리 자체의 최소 너비(1,024px)는 `workspace.css`에서 960px로 낮춰 조립판 오른쪽(확대·휴지통)이 iframe 밖으로 나가지 않게 합니다.
  - 작업실 iframe 폭이 1,100px보다 좁으면(1,024px 화면, 1,340px 부근의 2열 배치, 휴대전화) 무대를 엔트리 최소 크기(324px)로 줄여 조립판을 300px 이상 확보하고, 무대 아래 `오브젝트 추가하기`·`시작하기`가 작업실의 처음 보이는 영역에 들어오게 합니다. 약 350px 미만에서는 `시작하기` 오른쪽 여백 일부가 가려지지만 글자와 누르는 영역은 보입니다. iframe이 1,100px 이상으로 넓어지면 기본 무대(480px)로 돌아갑니다.
- **실행 결과 유지:** 붓으로 그린 선과 채우기는 실행이 끝나도 학생이 무대 아래 `정지하기`를 누르기 전까지 무대에 남깁니다(엔트리는 정지할 때 무대를 처음 상태로 되돌림). 말한 내용은 결과 줄의 `마지막 말`로 남깁니다. 이렇게 대기하는 동안 검증·제출이 막히는 이유(`정지하면 조건을 검증할 수 있어요`)는 같은 결과 줄에 적습니다.
- **상태 표시:** 상태는 무엇에 대한 상태인지 말하고, 다시 들어와도 같게 보입니다. 작업실 상태 줄은 저장·검증·제출을 따로 말합니다. 바로 저장되는 결과와 저장 버튼이 필요한 영역의 구분은 [§4.2](#42-저장-상태-표시와-이탈-확인)를 따릅니다.
- **미션 목록:** 미션 카드는 한 줄 5칸 너비를 기준으로 하며 가운데 정렬합니다. 미션이 4~5개(기본 3~4개+선택 1개)여도 오른쪽이 비지 않고, 1000px 이하는 3칸, 600px 이하는 2칸으로 줄 바꿈하며 마지막 줄도 가운데에 놓입니다.
- **하단 미션 탐색:** 좌측 `이전 미션`, 우측 `다음 미션` 버튼을 대칭 배치합니다. 수동 제출 성공 시 다음 미션 버튼이 시각적으로 강조됩니다.

### 5.2 알고리즘 선택 복습
<a id="알고리즘-선택-복습"></a>

#### 문제 추상화 (`review-abstraction`)
- **노선도 전환 지도:** 일반 지도(건물/도로 포함)와 지하철 노선도(단순화)를 1개 캔버스 안에서 전환하여 추상화 원리를 체험합니다. 좁은 창에서는 역 이름과 환승 정보가 겹치지 않도록 좌표를 재정렬합니다.
- **4단계 워크북:** 좌측 닥터 말풍선 대화 + 우측 워크북 입력창으로 구성됩니다. 맥락 요소 7개는 칩(Chip) 형태로 배치되어 클릭으로 덜어내기/되살리기를 직관적으로 토글합니다.

#### 알고리즘 설계 / 샌드위치 (`review-sandwich`)
- **조리대와 대화창:** 901px 이상에서 조리대와 명령 대화창을 **약 2:1** 비율로 가로 배치합니다. 900px 이하에서는 세로 1열로 배치합니다.
- **SVG 높이 제한:** 큰 조리대 일러스트는 최대 450px(낮은 창 300~400px)로 제한하여 1280×720 해상도에서도 명령 입력창이 스크롤 없이 노출되도록 보장합니다.
- **명령 대화창:** 우측 파란색 말풍선(학생 명령), 좌측 밝은 회색 말풍선(로봇 응답)으로 시각적으로 구분하며, 하단에 누적 실행 기록 바를 둡니다.

#### 순서도 연구소 (`review-flowchart`)
- **퍼즐 실습:** 보관함(좌) / 조립 캔버스(중앙) / 실행 모니터(우)의 3열 레이아웃을 사용합니다.
- **예시 공방:** 자연어 카드(좌) / 다이어그램(우)의 2열 레이아웃을 사용합니다.
- **자유 공방:** 기획서(300px) / 기호 보관함(100px) / 무한 캔버스 / 실행 과정 모니터(220px)의 4열 레이아웃을 지원하며, 기획서와 실행 과정은 필요 시 얇게 접을 수 있습니다.
- **모니터 구성:** 상단 흰색 변수표(현재값/직전값)와 하단 어두운 콘솔창으로 분리하여 실행 상태를 명확히 관찰할 수 있습니다.
- **기호 색상 규격:** 단말(시작/종료) 보라, 자료(입출력) 초록, 판단(조건) 주황, 처리(연산) 파랑으로 학습 의미를 전달합니다.

## 6. 접근성 및 UI 가이드라인 (Accessibility & Best Practices)

- **명암비 기준 (WCAG AA):** 본문 4.5:1, 버튼·경계선·포커스 표시 3:1 이상을 지킵니다.
- **움직임 감축 (`prefers-reduced-motion`):**
  - 공개 홈은 상단에 수동 모션 토글을 지원하며, OS 설정 또는 사용자 토글 해제 시 장식용 인터랙션을 정적인 화면으로 안전하게 대체합니다.
- **최소 글자 크기:** 13px 이상을 권장하고, 글자를 줄이기보다 줄바꿈·2열→1열 재배치·작업실 내부 스크롤을 먼저 씁니다.
- **새 강조색·그림자:** [§2.1](#21-컬러-토큰-color-palette)의 토큰을 먼저 쓰고, 새 색은 뜻이 분명할 때만 더합니다(색마다 뜻 하나). 그림자는 정의된 표면 토큰을 씁니다.
- **포커스 표시:** [§3](#3-공통-컴포넌트-명세-global-components)을 따릅니다.
