# Design System: CS Class

갱신: 2026-10-03(Asia/Seoul). 공개 홈과 로그인·대시보드의 디자인 기준, 별도로 표시한 수업 프로토타입의 표현 방향입니다. 제품 방향은 [PRD](PRD.md), 구현·검증·배포 상태는 [HANDOFF](HANDOFF.md), Stitch 조회 정보는 [DEVELOPMENT](DEVELOPMENT.md#stitch-연결)에 있습니다. 홈은 사용자 만족을 확인했고 로그인은 중앙 집중형으로 확정했습니다. 학생·교사 대시보드는 홈의 색·타이포그래피·그래픽에 맞춰 재정리했습니다. 최초 생성·수정 요청 원문은 [보관함](archive/README.md)에 있습니다.

## 1. Visual Theme & Atmosphere

중학생이 매일 사용하는 정보 수업 플랫폼. 담백한 한국어, 넓은 여백, 읽기 쉬운 큰 제목, 실제 사용 과정을 보여주는 화면으로 소개합니다. 학생을 어린아이처럼 대하지 않으며 감성적인 교육 홍보 문구를 반복하지 않습니다.

공개 홈의 주요 레퍼런스는 [토스 메인](https://toss.im/)입니다. 여백·타이포그래피·밝은 색의 조화와 스크롤에 반응하는 제품 화면 전개를 참고합니다. CS Class의 수업 화면과 고유한 그래픽으로 표현합니다.

- **Density 4/10:** 한 구간에서 한 가지 내용을 전달합니다. 넓은 여백과 충분한 정보량을 함께 유지합니다.
- **Variance 5/10:** 제목과 제품 화면의 크기·배치를 달리하며 리듬을 만듭니다. 지나친 비대칭이나 겹침은 피합니다.
- **Motion 6/10:** 공개 홈의 대표 시연에 움직임을 집중합니다. 학생·교사 작업 화면에서는 정보 확인과 조작에 집중합니다.
- **범위:** 공개 홈의 데스크톱·모바일 구현을 기준으로 학생·교사 로그인·대시보드·검증용 학습 화면에 같은 시각 기준을 적용했습니다. 기존 제품 기능·권한 범위를 유지하며 실제 서버의 상태를 표현합니다.
- **기존 방향 유지:** 공개 소개 → 사용 방법 → 역할별 공간 → 입장으로 연결합니다. 홈 중앙에서 한 수업의 구성 예시를 자세히 보여줍니다.

사용자 합의에 따라 한국어 글꼴은 Pretendard를 유지하고, 파랑 외에도 절제된 보조색을 허용합니다. 반복 모션을 모든 요소에 넣는 대신 수업 시연에 집중합니다. 이 프로젝트 기준을 일반적인 디자인 프리셋보다 우선합니다.

## 2. Color Palette & Roles

아래 HEX는 승인된 홈에서 후속 화면으로 계승할 기준입니다. 밝은 무채색 바탕 위에 맑은 파랑을 사용하고, 보조색은 작은 그래픽과 옅은 배경에 제한적으로 배합합니다.

| 색상 | HEX | 역할 |
|---|---|---|
| Canvas White | `#FFFFFF` | 기본 바탕과 제품 화면 |
| Cool Paper | `#F5F7FA` | 구간 구분, 옅은 표면 |
| Ink | `#202B3A` | 제목·본문 |
| Quiet Slate | `#526173` | 보조 설명·메타데이터 |
| Fine Border | `#E3E8EF` | 입력창과 제품 화면의 경계 |
| Clear Blue | `#376FC8` | 주요 버튼·선택·키보드 초점 |
| Deep Blue | `#2E5FAB` | 주요 버튼의 hover/active |
| Blue Mist | `#EAF2FF` | 선택 영역의 옅은 배경 |
| Sky Tint | `#DCEBFF` | 제품 시연의 하늘색 그래픽 |
| Soft Apricot | `#F8E1D5` | 그래픽의 작은 따뜻한 보조색 |
| Soft Lilac | `#E9E4F7` | 그래픽의 작은 보라 계열 보조색 |
| Teacher Purple | `#79639F` | 교사 비밀번호 로그인 버튼 |
| Night Navy | `#152641` | 마지막 입장 화면 |

- 주요 조작과 선택의 강조색은 파랑으로 일관되게 유지합니다. 교사 로그인은 동등한 두 입장 방법을 파랑과 Teacher Purple로 구분합니다. 다른 버튼에 의미 없이 보조색을 분산하지 않습니다.
- 전체 화면은 밝은 무채색이 대부분을 차지합니다. 색이 들어간 영역도 옅은 바탕과 작은 선명한 요소로 강약을 나눕니다.
- 그래픽 안에서는 하늘색·살구·라일락의 부드러운 혼합을 허용합니다. 본문과 대형 제목에는 그라데이션을 쓰지 않습니다.
- 민트색, 네온색, 순수 검정 `#000000`, 발광 테두리와 과도한 그림자는 사용하지 않습니다.
- 본문과 버튼 텍스트는 실제 배경에서 명암비 4.5:1 이상, 큰 텍스트·의미 있는 UI 경계는 필요한 대비를 확보합니다. 색과 함께 글자·아이콘·형태로 상태를 표현합니다.

## 3. Typography Rules

- **기본 글꼴:** 프로젝트의 로컬 Pretendard Variable. 대체 글꼴은 `Noto Sans KR`, `Malgun Gothic`, sans-serif 순서입니다.
- **첫 제목:** 데스크톱 최대 82px, 모바일 34~50px 수준. 굵기 750, 행간 1.2를 출발점으로 사용합니다. `온라인 교실`은 단색 파랑으로 강조합니다.
- **구간 제목:** 28~44px, 굵기 600~700. 글자 크기뿐 아니라 여백과 굵기로 계층을 만듭니다.
- **본문:** 기본 16~18px, 행간 1.6~1.75. 설명은 한국어 약 30~42자 너비를 출발점으로 두고 최대 65ch 안에 배치합니다.
- **보조 정보:** 14px 이상. 학습 화면의 핵심 안내를 작은 회색 글자로 숨기지 않습니다.
- 한국어 어절과 의미 단위를 지켜 줄바꿈합니다. 불필요한 영문 대문자 표제, 장식용 영문 슬로건은 사용하지 않습니다.
- 대시보드에서 세리프체나 장식 글꼴을 사용하지 않습니다. 숫자 정렬이 필요한 경우에만 tabular numbers 또는 등폭 글꼴을 사용합니다.

### 문구 기준

학생에게 자연스럽게 말하는 편한 존댓말을 사용합니다. 설명은 `~해요`, 행동을 권할 때는 `~하세요`, 버튼은 `교실 입장`, `수업 시작`, `이어하기`처럼 짧게 씁니다.

| 위치 | 초안 문구 |
|---|---|
| 첫 제목 | 정보 수업을 위한 온라인 교실 |
| 첫 설명 | 이번 수업을 확인하고, 수업 활동을 시작해요. 지난 활동도 이어갈 수 있어요. |
| 수업 찾기 | 이번 수업을 확인해요 |
| 수업 찾기 설명 | 선생님이 열어 둔 수업을 확인하고 시작하세요. |
| 수업 시연 | 수업은 이렇게 진행돼요 |
| 시연 보조 라벨 | 수업 구성 예시 |
| 개념학습 | 설명과 예시로 내용을 익혀요. |
| 퀴즈 | 배운 내용을 확인해요. |
| 실습 | 직접 해보며 적용해요. |
| 이어하기 | 하던 활동을 이어가요 |
| 이어하기 설명 | 지난 시간에 하던 활동을 다시 열어 보세요. |
| 학생 공간 | 이번 수업과 지난 활동을 확인해요. |
| 교사 공간 | 반별 수업을 열고, 이번 수업을 지정해요. |
| 마무리 | 오늘의 정보 수업, 여기서 시작해요. |

`나만의 발견`, `생각의 다음 장`, `준비물은 호기심`, `나만의 속도로, 나만의 방식으로`처럼 의미가 흐릿하거나 반복되는 교육 홍보 문구를 피합니다. 특정 단원이나 도구를 플랫폼 전체의 정체성으로 내세우지 않습니다.

## 4. Component Stylings

- **상단 탐색:** 왼쪽 `CS Class`, 화면 중앙의 `수업 미리보기`·`공간 안내`, 오른쪽 움직임 아이콘·`교실 입장`의 세 영역입니다. 가운데 목차는 좌우 내용 길이와 관계없이 중앙에 놓습니다. 비로그인 입장 선택창은 Escape·바깥 클릭으로 닫으며 초점이 돌아옵니다. 로그인 상태별 입장 대상은 [PRD](PRD.md#로그인-정책)를 따릅니다. 움직임 아이콘은 44px 영역과 호버·초점 툴팁을 제공합니다. 모바일에서도 입장과 움직임 버튼은 유지합니다.
- **주요 버튼:** Clear Blue 바탕과 흰 글자, 높이 44~48px 이상, 모서리 12~14px. 눌림은 짧은 축소 또는 1px 이동으로 표현합니다. 한 구간에서 주요 CTA는 하나를 출발점으로 합니다. 교사 로그인은 아래의 확정 기준에 따라 두 입장 버튼을 동등하게 보여 줍니다.
- **보조 버튼:** 투명하거나 옅은 무채색 표면. 파랑의 주요 조작과 경쟁하지 않습니다.
- **제품 화면 프레임:** 브라우저 또는 웹 학습 공간의 모습을 가진 하나의 큰 화면. 모서리 20~28px, 얇은 경계, 약한 그림자. 데스크톱 학습 서비스에 어울리는 화면을 사용합니다.
- **카드:** 이번 수업이나 이어할 활동처럼 실제 묶음·우선순위를 나타낼 때 사용합니다. 모든 설명을 같은 카드로 나누지 않습니다.
- **로그인 후 공통 탐색:** 흰 사이드바와 옅은 파랑의 선택 상태, 작은 학사모 로고, 44px 조작 영역을 사용합니다. `AppShell`의 CSS Module에서 관리하며 옛 전역 화면 스타일에 새 규칙을 추가하지 않습니다.
- **수업 단계 전환:** `개념학습`, `퀴즈`, `실습` 라벨을 가진 탭 또는 단계 선택기. 현재 단계는 글자·밑줄·형태로도 구분하며 클릭과 키보드로 선택할 수 있습니다.
- **입력창:** 라벨은 위, 오류는 아래, 초점은 파랑. 합의된 실제 로그인·필수 비밀번호 변경을 연결하며 학생 직접 회원가입·명단 업로드 양식을 임의로 추가하지 않습니다.
- **상태:** 빈 상태는 다음 행동이 보이는 편한 존댓말, 오류는 해당 조작 가까이에 표시합니다. 첫 조회·재조회·세션 준비의 로딩 표현은 [공통 기준](#확정된-공통-기준)에 모읍니다.

## 5. Layout Principles

데스크톱 1440px과 모바일 390px 시안을 우선 만들고 320px 폭까지 자연스럽게 줄어드는 구성을 유지합니다. 콘텐츠 최대 너비는 약 1200px, 좌우 여백은 20~64px, 구간 사이 여백은 `clamp(4rem, 9vw, 8rem)`을 출발점으로 합니다.

### 공개 홈의 순서

1. **첫 화면:** 헤더·시안 안내를 포함해 한 화면을 채웁니다. `정보 수업을 위한 온라인 교실`이라는 큰 제목, 짧은 설명, `수업 방식 보기` 옆에 9×9 픽셀 캔버스를 배치합니다. 파랑 커서·라일락과 살구색 반짝임·코드 모양을 클릭·키보드·터치로 바꿉니다. 이진수·코드 기호는 작은 보조 요소로 씁니다. 창 높이에 맞춰 그래픽을 줄이며 학생 홈 목업은 중복하지 않습니다. 입장 버튼은 상단과 마지막 구간에 모읍니다.
2. **하나의 사용 시연:** 이번 수업 → 개념학습 → 퀴즈 → 실습 → 이어하기를 같은 프레임에서 전환합니다. 데스크톱에서는 설명과 프레임을 고정하고 네이티브 스크롤 위치로 장면을 선택합니다. 단계 선택기는 화면 위에 두고, 키보드로 선택기 다음에 현재 패널에 접근할 수 있게 합니다.
3. **학생·교사 공간:** 역할별 하는 일을 짧게 설명합니다. 학생 홈 전체를 다시 복제하지 않고 수업·지난 활동으로 가는 용도를 보여줍니다. 교사는 반 선택·열린 수업·이번 수업 지정 범위를 유지합니다. 입장 링크는 중복하지 않습니다. 공간 안내 앵커는 제목에 두고 낮은 데스크톱에서는 간격을 줄여 제목부터 예시 하단까지 들어오게 합니다.
4. **입장 안내:** 남색 `#152641` 배경으로 한 장면을 만듭니다. `오늘의 정보 수업, 여기서 시작해요.`와 `학생으로 입장`·`선생님으로 입장`을 함께 배치합니다. 상단 헤더와 하단 푸터까지 창 높이에 맞추되 짧은 창에서는 내용이 잘리지 않게 자연스럽게 늘어납니다. 푸터는 메인 로고를 반복하지 않고 작은 `cs·` 서명과 `안동현T`, 현재 연도의 저작권 표기를 씁니다.

### 수업 구성 예시의 의미

`개념학습 → 퀴즈 → 실습`은 사용자가 재확인한 기본 수업 틀입니다. 공개 시연은 그 틀을 한 차시의 예로 보여주며 개념·문항·미션 수는 수업에 맞게 정합니다. 완료 여부로 다음 단계 진입을 잠그거나 자동으로 화면을 넘기지 않습니다. 홈의 내용은 단원을 확정하지 않는 예시 라벨로 표현하며 순서도·코딩 등 하나의 주제가 홈 전체의 대표 메시지가 되지 않게 합니다.

### 학생·교사 대시보드

- 두 공간은 같은 제목 크기·본문색·여백·파랑 주요 버튼을 사용합니다. 첫 화면의 영역별 배치·달력·목록 조작은 [파일럿 표현 기준](#대시보드-파일럿--노션을-참고한-내-할-일)에 모읍니다.
- 홈의 픽셀 캔버스를 재사용한 작은 정적 SVG는 수업 관리 등 상세 화면의 보조 장식으로 유지합니다. 장식은 학습 상태나 조작 영역을 대신하지 않으며 600px 이하에서는 숨깁니다.
- 학생의 열린 수업·완료 수는 제목 옆의 간결한 집계로 표시합니다. 단계별 진행은 수업 카드 안에 모으고 모바일에서는 세로로 재배치합니다.
- 교사의 반 선택은 독립된 조작 줄, 집계는 하나의 요약 영역으로 구성합니다. 좁은 화면의 학생 목록은 학생·전체 상태·기본 제출 요약을 우선 표시하고 상세 펼치기로 단계별 진행·작품·초기화 조작을 확인합니다. 상세를 접으면 내부 조작을 Tab 순서에서 제외하며 화면 크기 전환과 대화상자 닫기 뒤 초점을 보존합니다.
- 교사 수업 관리에는 이번 수업 강조 카드 아래 열린 수업 전체를 제목·설명·`이번 수업`/`복습 가능` 표시로 나열합니다. 넓은 화면은 3열, 900px 이하는 1열이며 수업 미지정·빈 목록을 구분합니다. 목록에 학생 관리로 가는 중복 이동 링크를 넣지 않습니다.
- 수업 설정 저장 성공 토스트는 오른쪽 아래에 약 4초 표시하고 본문 배치를 밀지 않습니다. 마우스를 올리거나 키보드 초점이 들어오면 자동 닫힘을 잠시 멈추며 닫기 버튼·정중한 음성 알림·44px 조작 영역을 제공합니다. 움직임 줄이기에서는 전환 효과를 끕니다. 저장 실패·충돌과 학생 비밀번호 초기화의 안내는 기존 화면에 유지합니다.
- 학생·교사 좌측 메뉴는 각 항목의 아이콘과 제목을 같은 형식으로 표시하며 대시보드만의 오른쪽 화살표 장식은 쓰지 않습니다. 현재 메뉴는 파란 배경과 `aria-current`로 표시합니다.
- 820px 이하의 공통 탐색은 메뉴 버튼으로 열고, 821px부터 사이드바를 표시합니다. 메뉴의 Tab 순환·Escape 초점 복귀를 유지합니다. 열린 메뉴를 데스크톱으로 전환하면 대시보드 링크에, 사이드바를 조작하다 화면을 줄이면 메뉴 버튼에 초점을 옮깁니다. 본문 조작의 초점은 유지합니다.
- 색과 장식에 가상 통계를 섞지 않습니다. 저장·권한·완료·제출 상태는 기존 서버 응답을 그대로 표현합니다. 이번 시안의 화면 기록과 검증 범위는 HANDOFF를 따릅니다.

### 반응형

- CSS Grid를 중심으로 구성합니다. 768px 미만에서는 다열 설명을 한 열로 정리합니다.
- 모바일의 학습 예시 화면은 글자를 읽을 수 있도록 재배치합니다. 데스크톱 화면 전체를 작은 그림처럼 축소하지 않습니다.
- 모바일에서는 긴 스크롤 고정 대신 짧은 구간과 직접 선택 가능한 단계로 구성합니다. 가로 넘침과 내부의 불필요한 스크롤을 만들지 않습니다.
- 텍스트·조작 영역은 겹치지 않습니다. 핵심 텍스트를 장식 이미지나 움직이는 물체 위에 얹지 않습니다.
- 화면 높이가 필요한 구간은 `min-height: 100dvh`를 사용하되 모든 구간을 화면 높이에 억지로 맞추지 않습니다.

## 6. Motion & Interaction

공개 홈의 재미는 사용 방법을 보여주는 변화에서 만듭니다. 움직임이 있어도 설명과 입장 버튼은 바로 읽고 사용할 수 있어야 합니다.

- **대표 전환:** 스크롤에 따라 하나의 수업 화면 내부가 개념학습 → 퀴즈 → 실습으로 바뀝니다. 화면 전체를 이동시키기보다 현재 단계·내용·조작의 관계를 보여줍니다.
- **호버:** 제품 프레임은 포인터 위치에 따라 최대 약 1.5도 기울어지며 그림자가 깊어집니다. 버튼·비트 카드는 짧게 들렸다가 눌립니다. 클릭 가능한 요소에만 조작을 암시하며 터치에서는 호버를 전제로 하지 않습니다.
- **수동 조작:** 단계 선택기를 클릭·키보드로 조작할 수 있습니다. 사용자가 직접 고른 단계는 조작 도중 자동 전환으로 덮어쓰지 않습니다.
- **속도:** 작은 조작 160~240ms, 내용 전환 300~500ms, 시연의 요소별 시차 40~80ms를 출발점으로 합니다. 필요한 spring은 stiffness 100, damping 20 정도로 과도한 튕김을 억제합니다.
- **장식 모션:** 첫 화면 픽셀 캔버스는 8초 주기로 작게 움직이고 포인터에 따라 기울어집니다. 클릭 영역은 고정하고 내부 그림만 움직입니다. 모든 카드·버튼에 반복을 넣지 않습니다. 상단에 항상 접근 가능한 움직임 줄이기를 제공합니다.
- **성능:** 주로 transform·opacity로 전환합니다. 스크롤과 함께 너비·높이를 계속 바꾸지 않습니다. 무거운 실사 영상이나 3D 엔진 없이도 제품 UI·가벼운 벡터·CSS로 구현 가능한 시안을 우선합니다.
- **움직임 설정:** 선생님 요청으로 공개 홈은 OS 설정과 관계없이 기본 켜짐입니다. 상단에서 줄이면 고정 구간·장식 모션·전환을 해제하고 내용과 선택 기능을 유지합니다. 새로고침하면 기본값으로 돌아옵니다. 다른 앱 화면은 기존 OS 움직임 줄이기를 따릅니다.
- **산출물 정직성:** 생성 도구가 정적인 화면만 지원하면 대표 구간의 세 상태와 전환 설명을 함께 만듭니다. 정적 시안을 동작하는 애니메이션으로 표기하지 않습니다.

## 7. Anti-Patterns (Banned)

- 과장된 교육 슬로건, 추상적인 응원, 학생을 어린아이처럼 대하는 말투.
- 장식용 영어 대문자 문구, 이모지와 만화식 마스코트의 과용.
- 순서도를 비롯한 한 단원을 전체 플랫폼의 정체성으로 고정하는 소개.
- 금융 용어·스마트폰 목업을 그대로 옮기거나 토스의 로고·영상·그래픽을 재사용하는 표현.
- 과한 민트·네온·발광·대형 그라데이션 제목, 의미 없이 각 버튼에 서로 다른 강조색을 부여하는 방식.
- 비슷한 크기의 카드 세 장으로만 기능 소개를 끝내는 구성. 수업의 세 단계는 하나의 화면 안에서 전환합니다.
- 의미 없는 둥둥 떠다니기, 모든 요소의 반복 애니메이션, 강제 스크롤 이동, 모바일의 과도한 고정 구간.
- Inter나 장식용 세리프를 기본 한국어 UI 글꼴로 새로 도입하는 변경.
- 확인되지 않은 수강생 수·완료율·후기·점수·AI 기능·자동 저장 성공 표시.
- 가격표·요금제·학생 직접 회원가입·공지·순위·교사 콘텐츠 편집기 등 합의 밖의 기능 추가. 승인된 반 일정·달력과 학습 검증은 해당 기준을 따릅니다.

### 첫 시안의 판단 기준

어떤 플랫폼인지 바로 알 수 있는지, 교실 입장을 쉽게 찾을 수 있는지, 수업의 세 장면이 하나의 흐름으로 읽히는지, 밝은 파랑과 보조색이 산만하지 않은지, 한국어 문구가 자연스러운지, 모바일·키보드·움직임 줄이기에서도 내용을 이해할 수 있는지를 확인합니다.

## 8. 로그인·대시보드와 학습 화면

### 수업 전용 공통 틀 — 2026-10-06 구현

학생 수업은 `LessonShell`과 인접 CSS Module에서 관리합니다. 대시보드·열린 수업·교사 화면은 `AppShell`을 사용하며 두 틀은 기존 접속 상태 표현을 `SessionAccess`로 공유합니다. 상세 설계·적용 기록은 [수업 전용 공통 틀](reference/student-lesson-shell-plan.md)을 따릅니다.

- 수업 나가기·줄바꿈 가능한 제목·수업 상태·실제 저장 상태·학생 메뉴를 한 상단에 모읍니다. 학생 메뉴는 본인의 학번과 로그아웃을 표시하고 Escape로 닫으며 초점을 되돌립니다. 나가기는 로그아웃과 떨어뜨립니다.
- 상단과 단계 탐색의 내용 폭은1440px입니다. 개념의 목록/본문/아래 이동은1120px, 퀴즈는880px의 기준선을 유지합니다. 기본 실습은1440px, 학생이 선택한 넓게 보기는 가용 폭을 사용하며 여백은16px/좁은 창12px입니다. 편집기·작품을 다시 만들지 않습니다.
- 상단은 폭821px 이상·높이801px 이상에서만 고정합니다. 낮거나 좁은 창에서는 일반 흐름으로 읽고 긴 제목을 자르지 않습니다. 단계와 수업 안내는 고정하지 않습니다.
- 단계는 실행 버튼과 구분되는 밑줄 탭이며 완료 수/진행 상태를 보여 줍니다. 상세 진행률은 수업 안내에서 볼 수 있습니다. 단계/결과 뒤 초점은 실제 화면 갱신을 마친 Effect에서 이동합니다.
- 알고리즘 실습은 낮은1280×720 창에서 안내·입력·실행·조리대 안내를 함께 표시하고, 실제 조리대 폭490px 초과를 검증합니다. 초기 대화 안내는 내용 높이를 사용해 일부 문장을 숨기지 않습니다. 긴 대화는 기존 내부 스크롤과 읽던 위치를 보존합니다.

### 확정된 공통 기준

- 선생님은 현재 공개 홈의 스타일에 만족하며 학생·교사 로그인과 대시보드에도 같은 스타일을 요청했습니다. 색·Pretendard·브랜드·버튼·입력창·둥근 경계·담백한 한국어를 공통으로 사용합니다.
- 로고의 파랑 그라데이션·그림자·기울기는 `Brand`의 공통 `.brand-symbol` 스타일로 유지합니다. 화면별 크기 조정과 홈의 호버 전환만 별도로 처리합니다. 로그인 카드도 홈의 역할 선택과 같은 책(학생)·학사모(교사·강사) 아이콘과 색을 사용하며 비밀번호 변경은 열쇠 아이콘으로 구분합니다.
- 홈의 입장 대상·최초 세션 확인·입력/탐색 유지 정책은 [PRD](PRD.md#로그인-정책)을 따릅니다.
- 교사 로그인은 파랑의 `Google 계정으로 로그인` 아래에 라일락의 `교사 비밀번호 로그인`을 같은 너비·높이로 배치합니다. 비밀번호 방식도 독립된 주요 입장 방법으로 보여 주며, 인증·담당 반은 [PRD](PRD.md#교사-인증과-권한)를 따릅니다. 방식 전환 시 비밀번호 입력 또는 Google 버튼으로 초점을 돌립니다.
- 반·수업·실습 블록의 선택 메뉴는 공통 Select를 사용합니다. 펼침창은 16px, 항목은 10px의 둥근 모서리와 부드러운 파랑 강조·선택 체크를 쓰며 터치 영역은 최소 44px입니다. 방향키·Enter·Escape와 닫은 뒤 초점 복귀를 지원하고 좁은 창 밖으로 메뉴가 넘치지 않게 합니다.
- 공개 홈의 수업 미리보기 하단은 `화면 안의 버튼을 눌러 보세요`로 안내합니다. 이동으로 오해할 오른쪽 화살표를 제거하고 각 장면의 실제 체험 조작으로 연결합니다.
- 최초 세션 확인 중에는 홈 버튼에 `입장 준비 중`과 회전 표시를 보여줍니다. 로그인·교실 접속 화면에도 확인 중이라는 상태를 안내하고, 입력과 홈 이동은 유지합니다. 대시보드의 첫 수업·할 일·일정 조회에는 실제 영역 모양의 스켈레톤을 표시하고, 이미 읽은 자료의 재조회는 내용을 유지합니다. 달력의 날짜·오늘은 먼저 표시하며 일정 표시가 준비되기 전에는 `일정 확인 전`을 씁니다. 조회 실패는 스켈레톤을 끝내고 기존 오류·재시도 UI로 전환하며 가짜 진척률을 표시하지 않습니다. OS 움직임 줄이기에서는 새 로딩 애니메이션을 멈춥니다.
- Stitch의 과거 테마보다 이 문서의 Pretendard·색상 기준을 우선합니다. 프로젝트·화면 ID와 조회 방법은 [개발 안내](DEVELOPMENT.md#stitch-상태)를 따릅니다.
- 홈의 대표 픽셀 그래픽은 작은 브랜드 요소로 응용할 수 있습니다. 로그인·작업 화면에 큰 홍보 영역이나 긴 스크롤 시연을 반복하지 않습니다. 작업 중에는 반복 모션보다 초점·선택·처리 결과를 명확하게 보여줍니다.
- 로그인·학습 화면은 처리 중·실패·세션 종료를 구분하고 실제 서버 결과를 표시합니다. 인증·권한은 [PRD의 로그인 정책](PRD.md#로그인-정책)을 따릅니다.
- 열린 수업의 단계별 퍼센트·완료 수와 전체 `시작 전 / 진행 중 / 완료`를 구분합니다. 계산·완료 조건은 [PRD](PRD.md#수업-단계와-완료-기준)를 따르며 전체 평균이나 장식용 통계는 만들지 않습니다.
- 열린 수업의 첫 조회는 카드 형태의 스켈레톤과 조회 안내를 표시합니다. 수동 새로고침·실패 후 재시도는 진행 표시와 상태 안내를 제공하고 초점을 유지합니다. 재조회 실패에도 이미 확인한 수업을 남깁니다. 학생 화면의 단계별 완료 수·저장 안내는 14px를 기준으로 읽기 쉽게 표시하고, 순서 이동 버튼·힌트 펼침 영역은 데스크톱과 모바일 모두 최소 44px로 둡니다.
- **개념 화면:** 설명·예시 바로 아래에 확인 문항·피드백을 두고, 완료 수와 남은 개념으로 이동하는 동작을 보여줍니다. 마지막 해설을 유지하고 다음 단계는 학생이 선택합니다.
- **퀴즈 화면:** 미응답·오답·해결을 구분하고 힌트는 기본으로 접어 `힌트 보기`로 엽니다. 재도전·단계 이동 정책은 [PRD](PRD.md#퀴즈)를 따릅니다.
- **실습 화면:** 검증 결과·제출 결과·저장 상태를 분리하고 제출본과 미제출 수정 내용을 구분합니다. 기본·심화 표시와 완료 유지, 향후 AI 오류·교사 확인 경로는 [PRD](PRD.md#실습-검증과-제출)를 따릅니다. EntryJS는 실제 편집기·무대를 카드 안에 두고 위에 실행·무대 초기화, 아래에 조건 검증·제출을 배치합니다. 좁은 창에서는 작업실 안에서 가로로 이동하며 바깥 페이지는 넘치지 않게 합니다. 로딩·실패·재시도를 구분하고 Esc는 바깥 실행 버튼으로 초점을 돌립니다.

- **간결한 기본 배치와 넓게 보기:** 제목·전체 상태·단계별 진행률은 항상 표시하고 수업 설명·상세 진행·작업실 사용 안내는 펼쳐 볼 수 있게 둡니다. 학생이 넓게 보기를 선택하면 데스크톱 탐색을 접고 본문 너비를 넓히며 같은 편집기와 작품을 유지합니다. 기본 크기 복귀·Escape·실습 밖 이동을 지원하고 모바일 탐색은 유지합니다. 실행 도구 가까이에 저장·현재 작품 검증·실제 제출을 각각 표시하며 이전 제출 후 수정은 다시 검증 필요와 이전 제출 유지를 안내합니다. 저장 실패/충돌의 해결 조작은 넓게 보기에서도 접근할 수 있게 둡니다.

### 화면별 방향 — 확정 범위 구현

사용자가 제공한 좌측 메뉴·여백·카드 참고 이미지에서 탐색 구조를 응용합니다. 실제 화면의 역할은 아래 표, 공통 배치·초점 경계는 [대시보드](#학생교사-대시보드), 목록·달력은 다음 절을 따릅니다. 확인 요청·Q&A의 범위는 [PRD의 구성 제안](PRD.md#대시보드-탐색과-우리-반-질문--구성-제안)에 있으며 시안 수치·질문을 실제 데이터로 옮기지 않습니다.

| 화면 | 초점 | 현재 배치 |
| --- | --- | --- |
| 학생·교사 로그인 | 무엇을 어디에 입력하는지 직관적으로 이해 | **중앙 집중형 확정.** 중앙의 간결한 입력 영역, 필요하면 작은 픽셀 장식. 왼쪽의 큰 홍보 영역 제거 |
| 학생 대시보드 | 개인 할 일과 다음 학습 행동 | **파일럿 구현.** 작은 이번 수업·내 할 일·수업에서 할 일·다가오는 일정. 열린 수업 메뉴에 기존 진행·필터·복습 유지 |
| 교사 대시보드 | 개인 할 일과 담당 반의 다음 확인 | **파일럿 구현.** 담당 반·작은 이번 수업·실제 현황/제출 바로가기·내 할 일·다가오는 일정. 학생 현황·계정과 수업 관리는 별도 메뉴 |

**교사 상세 화면:** 반·수업 선택 줄과 학생별 단계 진행 표·제출 작품·계정 상태를 읽기 쉽게 묶습니다. 대시보드 바로가기에서 선택 맥락을 유지하고 좁은 창에서도 주요 조작을 찾을 수 있게 합니다. 권한·완료 규칙·관리 기능은 [PRD](PRD.md#교사-대시보드의-1차-범위)를 따르며 전체 평균이나 장식용 차트를 추가하지 않습니다.

작업 화면 제목은 28~36px, 본문은 14~16px, 입력창·주요 버튼은 48~52px를 출발점으로 검토합니다. 모바일 터치 영역은 최소 44px를 유지합니다. 학생 화면은 읽기 편한 여유, 교사 화면은 관리에 필요한 정보량을 확보합니다.

구현·검증 기록은 [HANDOFF](HANDOFF.md)에서 확인합니다. 후속 Stitch 생성은 기존 화면 수정의 전제가 아니며, 아래 UI Component Lab의 패턴은 실제 조작에 필요할 때 선택합니다.

### 대시보드 파일럿 — 노션을 참고한 내 할 일

2026-10-05 개선에서는 기존 색·글꼴을 유지하고 정보 우선순위를 조정합니다. 열린 수업은 이번 수업·진행 중 순으로 안내하며 카드 하단에 저장된 단계·실습 미션을 표시합니다. 일정 요약은 5개까지 행 간격을 줄여 보여주고 나머지 개수/전체 보기를 카드 아래에 둡니다. 상세 일정의 여백·달력·학교 시간표 출처와 변경 표시는 유지합니다. 제출 학생(명)과 최근 제출 작품(개)의 단위는 분리합니다.

2026-09-30 사용자는 대시보드의 수업 정보 밀도를 낮추고 일정·할 일을 더하는 공통 파일럿을 요청했습니다. `내 할 일`은 노션 스타일을 참고하며 아래 기준을 **파일럿에 반영했습니다.** 제품 범위·저장·권한 가정은 [PRD](PRD.md#대시보드-파일럿--방향과-로컬-완료-범위-확정), 최신 구현·검증·배포 상태는 [HANDOFF](HANDOFF.md#현재-작업-상태)를 따릅니다. 완료한 작업 지시 원문은 [보관함](archive/README.md)에 있습니다.

- 첫 화면은 작은 이번 수업·내 할 일·실제 기록의 다음 행동·달력으로 구성하고, 전체 수업·상세 진행·학생 관리는 해당 메뉴에서 확인합니다. 큰 카드나 숫자로 정보량을 늘리지 않습니다.
- 이번 수업의 옅은 파랑 배경에는 작은 라일락·살구 그래픽을 섞고, 할 일·수업 행동·일정의 아이콘과 표면에는 각각 구분되는 옅은 보조색을 씁니다. 주요 행동과 키보드 초점은 계속 파랑으로 표시하며 상태는 색만으로 전달하지 않습니다.
- **내 할 일:** 체크박스와 한 줄 텍스트가 기본 단위입니다. 목록 안에서 바로 추가·수정하고 완료를 해제할 수 있게 합니다. 항목마다 큰 카드나 작성 대화상자를 만들지 않으며 완료는 체크와 취소선처럼 색 이외의 표시로 구분합니다.
- 입력 후 Enter로 항목을 추가하거나 편집을 확정하고 다음 입력을 이어갈 수 있는 흐름을 파일럿 기본안으로 합니다. 한국어 IME 조합 중 Enter는 문자를 확정하며 항목을 생성하지 않습니다. 빈 입력으로 항목을 만들지 않습니다. Esc는 편집을 취소하고, Tab·Space로 목록과 체크박스를 조작할 수 있게 합니다.
- 삭제·수정 등 조작은 키보드 초점과 모바일에서도 찾을 수 있게 합니다. 서버 저장 중·실패는 입력을 보존하고 알아볼 수 있게 표현합니다. 화면 갱신 이후 초점 이동은 기존 AGENTS의 Effect 기준을 따릅니다.
- **일정:** 대시보드에는 이번 달 미니 달력으로 오늘과 일정이 있는 날을 표시하고, 아래에 다가오는 일정 최대 3개의 제목·날짜를 보여줍니다. 전체 일정과 등록·수정은 해당 메뉴로 연결합니다. 월 이동·드래그 조립·위젯 배치 편집은 현재 범위에 넣지 않습니다.
- **학교 시간표:** 정보 수업에는 교시·시작 시각·`학교 시간표` 출처와 글자로 된 변경 표시를 함께 제공합니다. 전체 일정에는 학교·공개 기간·마지막 확인 시각·교사용 갱신 버튼을 표시합니다. 갱신 오류에도 기존 내용을 남기며 갱신 성공/실패가 미전송 제목을 초기화하거나 초점을 빼앗지 않습니다. 시간표는 직접 일정의 수정·삭제 메뉴와 구분하고 두 종류의 날짜를 달력에 함께 표시합니다.
- 학생·교사의 기본 배치·빈 상태는 공유하고, 학생은 수업 이어하기, 교사는 담당 반·제출 작품 확인으로 연결합니다. 탐색·초점은 위 공통 대시보드 기준을 따릅니다.

**참고:** 2026-09-30 확인한 [Notion 쓰기·편집 안내](https://www.notion.com/help/writing-and-editing-basics)의 체크박스 목록·직접 편집과 [키보드 안내](https://www.notion.com/help/keyboard-shortcuts)를 참고합니다. 위 Enter·Esc·IME 동작은 CS Class 파일럿을 위한 구체화이며 노션의 모든 동작을 동일하게 구현한다는 뜻은 아닙니다.

**논의용 배치 기록:** [학생 데스크톱](reference/dashboard-pilot/2026-09-30/student-proposal.png)·[교사 데스크톱](reference/dashboard-pilot/2026-09-30/teacher-proposal.png)·[교사 모바일](reference/dashboard-pilot/2026-09-30/teacher-mobile-proposal.png). 2026-09-30 대화에서 만든 HTML 구성안의 Chromium 화면이며, 노션 스타일 요청 전의 배치 참고 자료입니다. 할 일·일정은 예시이고 실제 서버·학생 화면이나 파일럿 구현 완료의 증거가 아닙니다. 이후 구현은 위 목록 조작 기준을 반영합니다.

**실제 파일럿 화면:** [학생 1440px](reference/dashboard-pilot/2026-09-30/student-1440.png)·[학생 390px](reference/dashboard-pilot/2026-09-30/student-390.png)·[교사 1440px](reference/dashboard-pilot/2026-09-30/teacher-1440.png)·[교사 390px](reference/dashboard-pilot/2026-09-30/teacher-390.png). 로컬 합성 계정과 에뮬레이터의 저장 기록으로 만든 화면입니다. 학생 자료·운영 화면이 아닙니다. 촬영 당시 환경·검사 범위는 [9/30 보관 기록](archive/cs-class/2026-10-01-before-local-ui-release/HANDOFF.md)에 있으며 현재 선택 메뉴·낙관적 UI의 화면 증거로 사용하지 않습니다. 위 논의용 원본 세 장은 그대로 보존합니다.

### 프로그래밍 13차시 — 경험 검토용 표현

운영 수업 `/classroom/programming-13`은 아래 개념 실험을 재사용하며 공통 AppShell·저장 표시·진행률·단계 탭 안에서 제공합니다. 실습은 기본 네 미션과 선택 도전 하나를 구분하고, 현재 목표 → 작은 실험 → 실제 작업실 → 검증·제출 순서로 읽습니다. 이름·계산·시작 버튼 이동에는 `독립 작품`, 방향키 개선에는 `앞 작품에 추가`를 표시합니다. 좁은 창에서는 미션을 두 열로 배치하고 실제 Entry 작업실에만 가로 이동을 허용합니다. 제출 완료와 아직 제출 전인 검증 통과를 구분하며 이동·응답 뒤 초점은 화면 갱신이 완료된 Effect에서 옮깁니다. 공개 체험의 예시 도움 전송 버튼은 운영 수업에 두지 않습니다. 완료·저장·복사 정책은 [실제 수업 구성](PRD.md#프로그래밍-13차시--실제-수업-구성)을 따릅니다.

2026-09-30 요청은 기존 모의수업의 개념 화면을 더 재미있게 만들고 퀴즈를 풀고 싶게 만드는 것이었습니다. 2026-10-01에는 전반 구조가 괜찮다는 피드백을 받았습니다. 아래는 `/prototype/programming`에 반영한 경험이며 모든 수업의 최종 UI 규칙으로 확정하지 않았습니다. 정책·피드백은 [PRD](PRD.md#프로그래밍-13차시--경험-검토용-프로토타입), 화면 기록은 [차시 자료](reference/programming-13.md#로컬-체험-화면)를 따릅니다.

- **개념:** 읽는 설명 옆에 값을 바꿀 수 있는 실험을 둡니다. 블록/텍스트 전환, 이름→인사말, 변수 상자→계산 결과, 신호→강아지 움직임으로 원인과 결과를 바로 확인합니다. 짧은 개념 확인은 실험 바로 아래에서 이어지고 학생이 다음 개념을 선택합니다.
- **퀴즈:** 한 번에 한 문제에 집중하고 작은 코드 장면을 먼저 보여줍니다. 큰 선택 영역·선택 표시·이전/다음 이동·접힌 힌트·회차 결과·오답 재도전을 연결합니다. 전체 해결 수와 이번 회차 정답 수를 구분하고 점수 경쟁·가짜 진척률로 재미를 만들지 않습니다.
- **실습:** 목표 → 내 코드와 실행 무대 → 조건 확인 → 완료 표시 → 발견 기록이 한 흐름으로 읽히게 합니다. 기본 3미션과 평균 도전을 구분하고 블록 연결·변수 값·실행 발자국으로 학생이 스스로 원인을 찾게 합니다. 이름 미션은 실제 EntryJS 작업실, 나머지는 미니 작업실입니다. 좁은 화면은 페이지 가로 넘침 없이 작업실 영역만 키보드·스크롤로 이동합니다. 질문창은 실행 무대 안에 나타납니다.
- **도움:** ‘막혔어요’에서 작은 실험을 먼저 안내하고 원하는 결과·실제로 생긴 일을 함께 설명하게 합니다. 교사는 요청 당시 작품과 결과를 보며 다음에 할 행동을 짧게 남깁니다. 최신 작품과 요청 당시 작품의 차이를 표시하고 학생이 다시 시도한 뒤 해결을 표시합니다.
- **표면과 강조:** 기존 Pretendard·Brand·Button을 재사용합니다. 밝은 회색 바탕과 흰 작업 영역, 파랑의 선택/주요 행동, 라일락 변수·살구색 피드백을 쓰며 강아지는 이번 차시의 실험 대상입니다. 전체 플랫폼의 마스코트로 확정한 것이 아닙니다.
- **좁은 화면과 초점:** 개념 목록·미션 목록은 작은 격자로, 코드와 무대·교사 요청/작품은 세로로 재배치합니다. 드래그 외에 버튼으로 블록을 추가·이동·삭제할 수 있게 합니다. 무대에 초점이 있을 때만 방향키가 움직임을 만들고 탭의 좌우/Home/End와 단계 갱신 뒤 초점 이동을 유지합니다.
- **상태 표현:** 탭 보관·실습 조건 확인·완료 표시·도움 요청·교사 답변을 서로 다른 상태로 보여줍니다. 실제 전송·제출·AI 처리처럼 보이지 않게 체험 안내를 유지하고 내부 enum 대신 ‘시작 버튼’, ‘A의 값’, ‘A × B’ 등 수업 표현을 사용합니다.

후속 UI 조정은 학생이 실험의 변화를 이해하고 다음 행동을 찾는지, 퀴즈 피드백이 재도전을 돕는지, 도움을 요청해도 하던 작품을 잃지 않는지를 기준으로 검토합니다. 모션·터치·키보드·읽기 편의의 구체적인 수정은 다음 작업에서 정합니다.

### 알고리즘 선택 복습

2026-10-06에는 [개선 계획](reference/student-learning-readability-plan.md)의 1~7차를 구현했습니다. 대표 알고리즘 설계의 시각/교육적 표현은 휴먼 리뷰를 앞두고 있으며 실제 학생 관찰은 아직 없습니다. 추상화·순서도의 새 체험과 프로그래밍 시각 확장은 8~10차에서 다룹니다.

- 학생 수업의 주요 조작·선택·초점은 파랑 `#376FC8`, 예시·관찰 안내는 `--warm-surface:#FFF3E8`·`--warm-foreground:#A84F2A`·`--warm-border:#EDC3A8`입니다. 전역 토큰은 추가하되 현재 사용은 수업 컨테이너에 한정합니다.
- 사용 색의 대비 계산(2026-10-06): 살구 안내 글자/배경5.04:1, 파랑/흰색4.92:1, 보조 글자`#526173`/흰색6.33:1입니다. 의미 있는 선택지·조작 경계`#8091AA`/흰색은3.21:1입니다. 살구 연한 경계는 안내 영역의 장식이며 선택·완료 여부는 텍스트와 파랑 표시를 함께 사용합니다.
- 대표 개념 본문18px/모바일16px·줄높이1.7, 설명 너비 최대42em, 버튼/선택지16px, 보조 문구14px 이상, 제목24~28px·조작44px 이상을 사용합니다. 목록은 상단 줄바꿈, 단일 퀴즈는 최대880px 중앙입니다. 개념 제목·목록·본문 카드·아래 이동 영역은 최대1120px의 같은 기준선을 사용합니다. 목록은 옅은 탐색 그룹, 체험 선택은 선택 표시, 실행은 파랑 주 버튼으로 구분합니다.
- 체험의 그림·관찰 질문·결과·확인 문제를 연결하고 초기화는 체험 상단에 둡니다. 초기화는 임시 체험 상태만 지우며 답안·완료 기록은 보존합니다. 중지·최종 단계 뒤 보조 버튼이 사라질 때는 Effect에서 시작 버튼으로 초점을 돌립니다. 로봇의 모호한 해석은 해당 예시임을 표시하고, 반복의 자동 종료/외부 중지 및 실제 조건에 따른 경로를 구분합니다. 움직임 줄이기에서는 결과를 즉시 또는 한 단계씩 비교합니다.
- 10/6 휴먼 리뷰의 ‘원작처럼 큰 실습·실제 대화’ 요청을 반영해 샌드위치의 공간 배분을 변경합니다. 901px 이상에서 조리대:대화는 약2:1,900px 이하에서는 세로 배치입니다. 그림의 빈 상단40만 덜어내고 재료·칼·상태 변화는 유지합니다. SVG 최대 높이는450px,1440px 이상·높이800px 이하에서는400px입니다. 901~1439px의 낮은 창에만190px 제한을 적용합니다.
- 오른쪽은 로봇 준비 안내→시간순 명령/응답→하단 입력입니다. 학생 명령은 오른쪽 파랑 말풍선, 로봇 응답은 왼쪽 밝은 말풍선이며 해석 출처·학습상 오류·연결 실패를 표시합니다. 기록만 내부 스크롤하고 이전 대화를 읽을 때 새 응답이 위치를 당기지 않습니다. 실패·확인 질문은 화면을 열어둔 동안 보존하고, 재접속은 기존 저장된 실행 명령을 복원합니다. 실행 기록은 주방과 대화 아래 전체 폭이며 재실행·되돌리기는 ‘기록 도구’에 접습니다. 새 레시피는 대화창 제목 옆에 둡니다. 한 줄 높이의 입력에서 Enter 또는 ‘실행’으로 보내며 Shift+Enter 줄바꿈과 한글 조합 확인 Enter를 구분합니다. AI 실패 때만 ‘AI 없이 실행’을 표시합니다.
- 상태 글자는14px 이상이며1440px 이상8×1,그 아래4×2,480px 이하2×4입니다. 1280×720 초기 입력·실행 주 버튼·조리대 안내 동시 노출은 유지합니다. 이 낮은 창의 초기 대화만140px로 준비 안내를 온전히 표시하고,명령이 쌓이면240px에서 스크롤합니다. 모바일 대화는320px이며 입력은 자연스러운 세로 스크롤로 접근합니다.
- 실습은 기본 폭으로 진입하고 학생이 넓게 보기를 선택합니다. 같은 수업의 단계 왕복·미션/크기 변경에는 수동 폭을 유지하며 재접속/다른 수업에서는 기본 폭입니다. 넓은 배치는 데스크톱 좌우16px·820px 이하12px입니다. EntryJS iframe 최소 크기와 엔진, 기호 의미 색은 유지합니다. 실제 확대와 브라우저·기술 검증의 현재 범위는 [HANDOFF](HANDOFF.md)에서 확인합니다.

열린 수업 카드에서는 복습 수업·다시 둘러보기·이어서 복습하기를 중심으로 표현하며 큰 0%·미완료로 이전 경험을 부정하지 않습니다. 수업 내부에는 실제 해결·제출 기록을 표시합니다. 첫 진입에 “새 사이트에서 다시 해 본 활동을 기록해요. 성적에는 반영하지 않아요.”를 안내합니다.

2026-10-05 공개 후 사용자 피드백으로 실습 표현 기준을 변경했습니다. 원작의 실습 배치·그림·색·상태 변화·조작을 최대한 재사용합니다. 샌드위치의 큰 조리대·실제 재료와 칼·8종 상태, 추상화의 색으로 구분한 워크북·닥터 카드, 순서도의 기호 보관함·조립 캔버스·실행 모니터가 기준입니다. 실습 안의 알록달록한 색은 재료·기호·행동 결과를 전달하는 요소로 유지합니다. 로그인·탐색·저장·AI·교사 확인은 cs-class 기능에 연결합니다. 추상화 맛보기는 선택이며 자유 단계 이동을 유지합니다. 작은 화면에서는 패널을 세로로 배치하고 캔버스 내부만 스크롤합니다. 구현·검증 상태는 HANDOFF에서 구분합니다.

주요 조작은 최소44px, 단계/검증 뒤 초점은 갱신한 DOM에서 이동합니다. AI 대기 중 새 입력을 보존하고 결과·진행·저장·제출을 구분합니다. 규칙 대체 해석과 이전 작품의 AI 리뷰는 명시적으로 표시합니다. 교사 상세는 고정 요청본·최근 제출본을 보여 주며 현재 수정본을 승인한 것으로 표현하지 않습니다.

AI가 원문 근거·연결을 확신하지 못한 경우는 미완성이나 점수 하락으로 강조하지 않고, 내용을 확인하거나 선생님 확인을 요청하는 다음 행동을 안내합니다. 작성한 작품·이전 제출본과 현재 요청 상태를 함께 유지합니다.

위 흐름과 원작 실습 표현을 구현했습니다. 모바일·키보드·저장 실패의 검사와 운영 확인, 실기기·학교망의 미검증 범위는 [공개 기록](HANDOFF.md#105-원작-실습-ui-복원-공개)에서 구분합니다.
