# 이어갈 작업

갱신: 2026-10-30(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정:** 등록 현황과 입장 방식(10/21부터 반 공통 첫 입장 코드)은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있습니다. 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.
- **진행 중 브랜치(원격):** `feat/festival-character-v7`(축제 캐릭터 초안 보존, 게임 미적용).
- **진행 중 계획:** [포트폴리오 채점](plans/assessment-portfolio.md)(0단계 반영, 1단계 전).

## 최근 반영

- **#97·#98 엔트리 라이브러리 Cloudflare CDN** (10/30): 운영 빌드만 작업실 HTML의 `/entryjs/vendor/` 주소를 Cloudflare Workers 정적 파일 `cs-class-entry`로 바꿈(CDN에 같은 지문이 없으면 Vercel 파일 유지, 작업실 `workspace.*`·작품 그림은 Vercel). 첫 작업실의 Vercel 요청 약 93→5건(가짜 CDN E2E). 검증: 단위 26, 파일 지정 E2E 8개 스펙 59 통과, 실제 CDN 파일 555개 대조·엔트리 E2E 4 통과, 학교 PC 접속 확인, 전체 E2E 미실행. 끄기·라이브러리 교체 순서는 [CDN 절차](FIREBASE_SETUP.md#엔트리-라이브러리-cdn), 계획은 [보관 원문](archive/cs-class/2026-10-30-completed-plans/entry-assets-cloudflare.md).
- **#96 문서·코드 정리** (10/30): #94·#95 뒤 문서를 현재 상태로 맞춤(포트폴리오 계획 0단계 완료, PRD §5.1 수업 화면 30초 조회, DEVELOPMENT §4.1 프록시 규칙·§4.4 시간표 합성 서버, 중복 규칙은 링크로). ESLint의 `.ua/` 제외, `src/proxy.ts`를 엔트리 선별 E2E에 연결, 배포 제외에 `private` 추가, 쓰지 않는 `abstractionPresets`·낡은 주석 제거. 검증: typecheck·lint, 단위 21·72, 파일 지정 E2E 6개 스펙 40 통과, 전체 E2E 미실행.
- **#95 엔트리 프록시를 사전 요청에만** (10/29): Vercel 함수 호출 76%·Active CPU 78%의 주원인으로 본 `src/proxy.ts`가 `/entryjs/` 모든 파일 요청마다 함수로 돌던 것을, `access-control-request-method` 헤더가 있는 사전 요청에만 돌게 함. 검증: typecheck·lint·build, 빈 캐시 수업 1회+2분에 프록시 실행 92→2회(소리 정상), 단위 21, 파일 지정 E2E 24 통과·1 실패(단독 3회 통과), 전체 E2E 미실행.
- **#94 엔트리 정적 파일 브라우저 캐시** (10/29): Vercel CDN 요청 한도의 75%가 쓰였고 6시간 표본의 85%가 `/entryjs/` 정적 파일이라, `next.config.ts`가 `public/entryjs/vendor/`·`sprites/`에 하루 브라우저 캐시(`max-age=86400`)를 붙임([개발 안내 §4.1](DEVELOPMENT.md#41-entryjs-4023-실습-환경)의 지연 전제). 로컬에서 작업실 재진입 요청 70→2건. 검증: Tier 1~1.5(단위 21), 파일 지정 E2E `programming-classroom` 16(1개는 20초 대기 검사가 단독 재실행에서 통과)·`lesson-smoke` 6 통과, 로컬 `build`, 전체 E2E 미실행, 운영 응답 헤더(`max-age=86400`)는 공개 뒤 확인함.
- **Show the quiz button as primary only after the last concept is checked** (10/29): 마지막 개념의 `퀴즈로 이동`이 정답 확인 전부터 파란 주 버튼이라 학생이 확인 없이 넘어가던 문제를 고쳐, `다음 개념`처럼 맞힌 뒤에만 주 버튼이 됨(공통 개념 화면·프로그래밍 기초 개념 화면). 검증: typecheck·lint, 파일 지정 E2E 4개 스펙 16 통과, 화면 확인, 전체 E2E 미실행.

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 `main` 전체 성공은 10/18 `7264de7`(run 39063459497)입니다. 마지막 실행은 10/27 로컬(#89 브랜치, 444 통과·2 실패·13 건너뜀)이고 실패 2개는 아래 순서도 검사입니다. Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **CI·로컬 검사 불안정:** `main` CI의 10초 대기 검사가 재실행으로 통과한 일이 두 번 있었습니다(10/19 `programming-classroom`, 10/21 `conditionals`의 `마지막 말`). 로컬에서는 `programming-classroom`의 `entry-assets` 검사(새로 켠 서버의 첫 실행)·`flowchart-auto-completion`(#67)·`review-flowchart`의 빈 기호 검사·`programming-classroom`의 정지 뒤 저장 상태 검사(#95)가 실패했다가 단독 재실행에서 통과합니다(원인 미확정, 반복되면 대기 시간 기준 점검).
- **의존성:** 10/21 `npm audit` 24건은 운영 화면 경로가 아닌 개발 도구이고, `@grpc/grpc-js` 권고(GHSA-m9gg-hp2v-232j)는 서버 `firebase-admin`만 Firestore를 써서 해당하지 않습니다.
- **Firestore 무료 한도:** 10/21 실제 두 반(엔트리 수업)은 읽기 약 3만·쓰기 약 1.4만이었고, 시계 폭주를 빼도 저장·채점이 반당 쓰기 약 1천 회입니다. 하루 4반(반 정원 기준)×45분의 정기 읽기는 수업 화면 기준 측정 환산 약 2.9만 회(과금 실측 아님, 10/24부터 대시보드 30초 조회도 같은 2회)이고, 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 안을 보장하지 않습니다.
- **Vercel 무료 한도:** 10/30 오전 CDN 요청 865K·함수 호출 767K/1M, Active CPU 3h7m/4h(최근 30일, 많이 쓴 10/21~ 은 11/20 무렵 빠짐)입니다. 사용자가 무료 유지를 정해 라이브러리를 Cloudflare로 옮겼으니(#97·#98) 며칠 사용량 그래프로 효과를 봅니다. 남는 함수 호출은 학생 화면 30초 조회(분당 약 3.5회)입니다.
- **첫 제출 시각(#93):** 10/28 이전 제출본은 다시 내면 옛 `submittedAt`을 넘겨받아 `firstSubmittedAt`을 상한으로만 쓸 수 있습니다.
- **수업 누적:** 대시보드 응답에 수업마다 엔트리 작품 원문이 담겨 프로그래밍 수업이 수십 개면 응답이 수 MB가 될 수 있으니, 그때 진도 판정 필드만 보내도록 줄입니다.
- **복습 확인 결정(#46):** 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전 재요청은 결정 메시지를 덮습니다.
- **손들기:** 일시 중지 상태입니다. 재개 방법은 [PRD §5.5](PRD.md#설정과-손들기)와 [연결 기준](FIREBASE_SETUP.md#연결-기준)을 따르고, 재개 전 오래된 대기 요청 처리 기준을 정합니다.
- **엔트리 작업실:** 엔트리 저작권 가이드 원문(PDF)은 읽지 못해 공개 요약(CC BY-NC 2.0·학교 수업 허용·출처 표시)만 확인했습니다(#58).
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다. 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
- **학습 경험 후속:** 옛 피드백 문구·긴 식 잘림 등 기록만 한 항목, 5단계, 복습 개념 확인 정답 위치(사용자 결정)는 [계획 §14](archive/cs-class/2026-10-24-completed-plans/learning-experience.md#14-제외와-이유).
- **학교 식별 정보:** 현행 문서만 일반화했고(#91) 학교명은 코드·시간표 카드·Git 기록에 남습니다([계획 §7](archive/cs-class/2026-10-27-completed-plans/generalize-school-identity.md#7-남는-위험)).
- **엔트리 학생 변수(#88):** 학생이 변수를 쓰기 시작한 뒤 이전 버전으로 되돌리면 그 작품을 읽지 못하므로(원문은 보존) 문제는 되돌리지 않고 수정 반영으로 고칩니다.
