## 마지막 사용자 결정과 다음 작업

- 사용자는 현재 홈을 마음에 들어 하며 학생·교사 로그인과 대시보드에도 같은 스타일을 요청했습니다.
- **로그인은 중앙 집중형으로 확정했습니다.** 사용자의 이유는 “무엇을 어디에 입력해야 하는지 직관적으로 보이는 게 좋다”입니다. 좌우 분할 유지 여부를 다시 묻지 않습니다.
- 다음에는 학생·교사 로그인 시안을 먼저 정리합니다. 학번·비밀번호, 교사 Google·강사 비밀번호, 첫 입장 비밀번호 변경, 잘못된 입력 상태를 함께 다룹니다.
- 로그인 → 학생 대시보드 → 교사 대시보드 순으로 작업하는 방향을 제안했습니다. 대시보드 세부 배치는 **사용자와 대화하며 천천히** 정합니다. 이번 정리 작업에서 새 대시보드 디자인을 임의로 만들지 않았습니다.
- 아직 후속 로그인·대시보드 Stitch 생성 요청이나 해당 화면의 스타일 구현은 하지 않았습니다. 코드에 있는 기존 로그인·대시보드는 이전 시안입니다.
- 사용자는 잠들기 전 현재 작업을 다른 PC에서 이어가도록 보존하고 문서를 통합하며 main 병합하기를 요청했습니다. 실제 병합·CI 결과는 GitHub PR과 Git 이력에서 확인합니다. 완료 전후 상태를 오래된 브랜치명만으로 판단하지 않습니다.
- 이번 기준점은 [PR #2: 플랫폼·홈·다른 PC용 인수인계](https://github.com/DonghyunT/cs-class/pull/2)에 묶었습니다. 새 PC에서는 이 PR의 병합 상태와 main의 최신 커밋을 확인합니다.

새 대화에는 다음과 같이 입력하면 됩니다.

> docs/HANDOFF.md, PRD.md, DESIGN.md를 읽고 이어서 작업하자. 홈 디자인은 확정했고 다음은 중앙 집중형 학생·교사 로그인이다. Stitch 스킬과 MCP를 활용하되 로그인부터 함께 다듬고, 대시보드는 나와 대화하면서 진행하자.

## 홈에서 유지할 결정과 구현 주의점

- 담백한 존댓말, 사용 방법이 드러나는 설명. 감성적인 홍보 문구·장식용 영어·과한 응원 문구는 줄입니다.
- 흰색·옅은 회색·은은한 파랑과 절제된 라일락·살구색. Pretendard 유지. 토스는 색·여백·전개의 참고이며 로고·영상은 재사용하지 않았습니다.
- 큰 학사모는 정보 수업과 어울리지 않아 픽셀 캔버스로 교체했습니다. 작은 브랜드 학사모는 유지합니다. 캔버스 클릭·키보드·터치로 커서·반짝임·코드가 바뀝니다.
- 헤더는 왼쪽 브랜드, 가운데 수업 미리보기·공간 안내, 오른쪽 모션 아이콘·교실 입장. 교사 입장은 통합 선택창 안에 있습니다. 첫 화면·역할 예시의 중복 입장 버튼을 다시 추가하지 않습니다.
- 홈 모션은 사용자 요청으로 **OS 설정과 관계없이 기본 켜짐**입니다. 상단에서 줄이면 고정 스크롤과 장식 모션·전환을 해제하되 조작은 유지합니다. 새로고침하면 기본값으로 돌아옵니다. 다른 앱 화면은 OS 설정을 따릅니다.
- 고정 시연은 폭 960px 이상·높이 680px 이상일 때 사용합니다. 모바일·낮은 창은 직접 단계 선택입니다. 수동 선택은 새로운 사용자 스크롤 전까지 유지합니다.
- 활성 패널은 즉시 `visibility: visible`이 되어야 빠른 방향키·Tab 이동에서도 초점이 빠지지 않습니다. 픽셀 그래픽은 클릭 영역을 고정하고 내부 그림만 움직입니다.
- 공간 안내 앵커는 여백이 있는 section이 아닌 제목 `#classrooms`에 있습니다. 낮은 데스크톱은 간격을 줄여 예시 하단까지 들어옵니다.
- Tooltip·Dialog는 기존 Base UI를 활용했습니다. 역할 선택창은 Escape·바깥 클릭·닫기 버튼, 초점 순환·복귀를 지원합니다.
- 개념학습·퀴즈·실습은 한 수업의 예시이며 모든 수업의 진입 순서를 강제하는 정책이 아닙니다. 순서도는 한 단원입니다.

## 참고 자료와 PC 사이에 옮겨지지 않는 것

- 사용자 제공 UI Component Lab 네 파일은 [저장소 복사본](reference/ui-component-lab/index.html)에 원문 그대로 보존했습니다. 직접 브라우저로 열 수 있고, [DESIGN의 활용 기준](../DESIGN.md#9-ui-component-lab-활용)에 이미 적용한 패턴·후속 후보를 통합했습니다. 원래 PC 밖의 절대 경로에 의존하지 않습니다.
- 실제 학생 계정 엑셀·초기 비밀번호·API 키·개인 설정·`백업용/`·생성 캐시·테스트 임시 출력은 Git에 올리지 않습니다. 엑셀은 원래 PC의 `outputs/01a0de21-d7f4-7c03-8abf-2e213c2bf7fc/`에만 있습니다. UI 후속 작업에는 필요하지 않습니다.
- StitchDesign 플러그인·MCP·브라우저 연결은 PC별 설정입니다. Figma는 계정·기존 Designo 스크린샷 조회까지 확인했으며 편집은 미검증, Context7은 연결 전입니다. 필요한 경우 실제 가용성을 확인합니다.
- Vercel `cs-class` 프로젝트 존재와 최근 배포의 READY 요약은 조회했지만, 상세 배포 조회는 서비스 권한 오류(403)로 확인하지 못했습니다. `web/` 배포 루트는 이전 기록이며 이번에 재검증하지 못했습니다. `platform/` 배포 전환 시 연결 권한과 실제 루트를 다시 확인합니다.
- 문서 통합 전 원문 9개는 [홈 체크포인트 보관 목록](archive/cs-class/2026-09-27-home-checkpoint/manifest.json)에 경로·SHA-256과 함께 보존했습니다. 이 보관본의 상대 링크와 당시 상태는 현재 지침이 아닙니다.

## 검증 근거와 범위

- 최종 홈 코드에서 lint·typecheck·build와 E2E 전체 **12개**를 통과했습니다. 로그인·학생·교사 기존 흐름도 포함합니다. 선택창 비교 이미지는 열기 애니메이션이 끝난 상태로 저장했습니다.
- 첫·마지막 화면: 1920×1080·1440×900·1280×720·768×900·390×844·320×812·375×667. 공간 안내: 1920×910·1440×900·1280×720의 두 역할.
- 네이티브 스크롤 고정·역방향·수동 단계 유지, 방향키·빠른 Tab 왕복, 퀴즈·비트 상태, OS 모션 두 설정, 툴팁, 모달 초점·닫기·두 입장 경로, 실제 터치 컨텍스트·가로 넘침·콘솔 오류를 검사했습니다. Chrome 실제 화면도 확인했습니다.
- 학생 오류·비밀번호 변경·초기화 후 체험 기록 보존, 교사 설정의 반영, 강사 10·11반 범위, 빈 상태·모바일 메뉴·필터를 검증했습니다. 실제 계정·서버 권한·영속 데이터·동시 사용·전체 접근성 인증은 검증 범위 밖입니다.
- 이번 병합의 원격 CI 결과는 해당 PR의 `Verify CS Class`에서 확인합니다. 새 PC 설치는 CI의 `npm ci`로 재현성을 확인하며 PC별 도구 설정까지 동기화되는 것은 아닙니다.
