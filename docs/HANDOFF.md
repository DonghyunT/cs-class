# 이어갈 작업

갱신: 2026-10-18(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

- **진행 중:** 점검 후속 F3~F6을 PR마다 CI 통과 뒤 병합하고, 끝나면 `main`에서 전체 E2E를 한 번 돌립니다(10/18 밤, 사용자 승인). 순서는 [다음에 이어갈 작업](#다음에-이어갈-작업) 0번입니다.
- **운영:** `main`의 최신 커밋을 배포 게이트(`app` 성공 뒤 공개)로 반영합니다. 앱 코드의 마지막 변경은 #47(F4·F5)입니다. 설정 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.

## 최근 반영

- **#47 서버 오류 종류·코드 기록, 담당 교사 Q&A 삭제** (10/18): 예상하지 못한 서버 오류에만 허용 목록의 `errorName`·`errorCode`를 로그에 더하고([DEVELOPMENT §5.2](DEVELOPMENT.md#52-실패-진단-및-에러-로깅-규격), 점검 F4), 담당 교사·강사가 반 Q&A 질문을 답변과 함께 지울 수 있습니다([PRD §5.4](PRD.md#54-우리-반-질문-qa), F5). #41 뒤 낡은 E2E 기대값 2개도 고쳤습니다. 검증: 관련 E2E 6파일 50개, 고친 2개 5회 반복 통과, lint·typecheck·`test:review`·`test:scope`. 전체 E2E 미실행. 한계: 실제 Firestore 오류로 로그를 남기는 E2E는 없고 단위 검사만 있습니다.
- **#46 교사 확인 결정 뒤 학생 저장 충돌** (10/18): 교사의 복습 확인 결정이 작품 revision을 올리지 않아, 열어 둔 학생 화면이 "다른 탭" 충돌 없이 저장하고 그 응답으로 결정을 받습니다(점검 F3). 검증: 재현 E2E가 수정 전 409로 실패하고 수정 뒤 통과, 관련 6파일 46개 중 44개 통과(실패 2개는 수정 전 `main`에서도 실패, 아래 전체 E2E 항목), lint·typecheck·`test:review`. 전체 E2E 미실행. 한계: 학생 화면은 저장하거나 다시 열기 전까지 교사 결정을 받지 않습니다(이전과 같음).
- **게스트 교사 1~11반 담당** (`Give the local guest teacher all eleven classes`, 10/18): 로컬 전용 `guest-teacher`가 2학년 1~11반을 맡고 처음 화면은 1반입니다([DEVELOPMENT §1.3](DEVELOPMENT.md#로컬-게스트-입장)). 운영은 게스트 로그인이 꺼져 영향 없음. 검증: 관련 E2E 3파일과 강사 반 권한 16개, lint·typecheck·문서·`test:review` 통과. 전체 E2E 미실행. 한계: 담당 반 밖 초기화 거부는 `classroom-api`의 강사 검사만 확인.
- **문서·반영 흐름 정비** (10/18, 사용자 결정으로 직접 push): 위험도별 두 경로와 작업 단위 승인 범위를 정했고([DEVELOPMENT §2.1](DEVELOPMENT.md#위험도별-반영-경로)), HANDOFF 압축·[문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)·완료 계획 보관을 했습니다. 검증: 문서 검사·테스트, 보관 파일 sha256 대조, 독립 검토 2명 반영. 앱 코드 변경 없음, 전체 E2E 미실행. 한계: 설정과 별개로 세션의 자동 권한 검사가 병합을 막을 수 있습니다(#45).
- **#44 로그인 계정 상한·장애 안내** (`007a468`, 10/18): 로그인 제한을 계정당 15분 30회로 바꾸고 교사 초기화로 잠금이 풀립니다. Firebase 자격 증명 오류만 "비밀번호 확인", 장애·차단·설정 오류는 503으로 안내합니다([PRD §6.1](PRD.md#61-계정-체계-및-비밀번호-정책)). 검증: 로컬 E2E 12파일 102개, 리뷰 반영 뒤 19개 통과, PR·main CI smoke. **전체 E2E 생략**(사용자 결정). 한계: 5xx·차단 응답의 자동 검사 없음.

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 성공은 2026-10-14 GitHub 수동 실행이고, #39~#47은 선별 검증만 했습니다. 10/18에 `main`에서도 실패하던 검사 2개(#41 뒤 작품 크기 기준, 순서도 자동 제출 대기)는 #47에서 검사 쪽을 고쳤습니다. F6까지 끝난 뒤 한 번 돌리며 로그인 상한이 긴 실행에서 넘치지 않는지도 봅니다.
- **운영 DB 정리:** 운영 `csRateLimits`에 10/18 이전의 비밀번호별 기록이 남아 있습니다. 정리 기준은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있고, 운영 DB 작업 승인이 필요합니다.
- **운영 강사 계정:** `instructor`의 담당 반을 10/18에 10·11반으로 줄였습니다. 비밀번호는 아직 체험용 공통 비밀번호라, 실제 강사에게 주기 전에 Firebase 콘솔에서 바꿔야 합니다(사용자 작업).
- **의존성:** main CI의 `npm ci`가 취약점 26건(보통 4·높음 22)을 보고합니다(10/18). 아직 점검하지 않았습니다.
- **무료 한도:** 하루 4반×27명×45분 모형에서 정기 읽기만 약 29,520회입니다(실측 아님). 진입·저장·채점은 별도라 무료 일일 읽기 5만 회 안의 4반 운영을 보장하지 않습니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 다시 켜기 전에 오래된 대기 요청의 처리 기준, `csHelpRequests` 인덱스 준비, 활성 모드 검사를 확인합니다.
- **화면:** `programming-concept.module.css`가 쓰는 `--line`·`--ink` 등 변수는 프로토타입에만 정의돼 있어 정식 수업에서 비어 있습니다(F6과 함께 확인). 821px 부근에서 수업 헤더의 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼의 오른쪽 여백 일부가 가려지고, 실제 휴대폰에서는 확인하지 않았습니다(#43).
