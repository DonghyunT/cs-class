### 바로 이어갈 작업

**최신 승인과 진행 방식:** 사용자는 사전 메타프롬프팅 뒤 구현 진행을 승인했습니다. [A안: 실제 계정·저장까지 연결한 작은 버전](../PRD.md#1차-구현-완료-목표--실제-계정과-저장-연결)이 목표입니다. 메인이 공통 기반·통합을, 학생·교사 화면은 각각 한 에이전트가 맡아 구현과 개별 검증을 수행했습니다. [작업 지시문](BUILD_BRIEF.md)의 소유 범위·공통 계약·검증 기준을 유지합니다. 이전의 구현 보류 요청을 현재 지침으로 적용하지 않습니다.

**구현한 1차 흐름:** 중앙 집중형 로그인 → 담당 반의 이번 수업 지정 → 학생의 검증용 활동 → 서버 저장 → 재접속 후 복원을 연결했습니다. 검증용 수업은 개념 2개·퀴즈 3문항·순서 배열 실습 1개입니다. 학생은 이번 수업과 열린 수업에서 단계별 퍼센트·완료 수를 확인하며 전체는 **시작 전 / 진행 중 / 완료**로 표시합니다. 교사는 반 선택·이번 수업 지정·학생별 단계 진행·제출 작품 보기·계정 관리를 사용합니다. 진행 표시와 분담·기능 범위를 다시 미정으로 돌리지 않습니다.

**실제 서비스 준비:** 사용자가 Firebase 프로젝트 `cs-class-f74c4`와 서울 리전의 기본 DB 사용을 승인했습니다. 제공받은 서버 자격 증명과 교사 Google 허용 목록은 Git 제외된 `.env.local`에 설정했습니다. 이메일·비밀번호 및 Google 제공자 활성화, 2학년 1~11반의 빈 반 준비와 Firestore 보안 규칙 배포를 확인했습니다. 실제 학생 계정은 등록하지 않았습니다. 개인 키·실제 비밀번호·허용 이메일·원본 키 파일 경로를 이 문서나 Git에 복사하지 않습니다. PC별 연결·점검 절차는 [Firebase 설정 안내](FIREBASE_SETUP.md)를 따릅니다.

**클라우드 왕복 검증:** 임시 합성 계정으로 실제 Auth 로그인 → 수업 지정 → 개념·퀴즈·실습 검증과 제출 → 재로그인 복원 → 교사 제출 조회를 통과했고 익명 Firestore 접근 거부(403)도 확인했습니다. 시험 계정 2개·작업·요청 제한 기록을 삭제하고 시험 반의 빈 설정을 복원했습니다. Google 제공자 설정·에뮬레이터 토큰 교환에 더해 실제 허용 Google 계정으로 `localhost`에서 로그인하고 교사 대시보드에 진입한 것을 사용자와 브라우저에서 확인했습니다. 담당 반 11개와 빈 반·등록 학생 0명 상태도 확인했습니다. 호스팅 환경 검증은 후속입니다.

**최종 검증 상태:** lint·typecheck·build와 전체 CI 방식 E2E 27개를 통과했습니다. 프로덕션 빌드의 `next start`와 로컬 Firebase 에뮬레이터를 사용했으며 세부 구성과 테스트 주소 보강은 아래 검증 근거에 기록했습니다. Firestore 보안 규칙은 배포했지만 이번 앱 구현은 배포하지 않았으므로 기존 공개 주소에서 새 기능이 제공된다고 가정하지 않습니다.

**예산·AI 결정:** 월 4만 원은 참고 예산으로 수용했습니다. 사용자가 무료 사용 가능한 AI API를 별도로 보유하고 있으므로 AI는 이후 검토합니다. [운영비 예상안](OPERATING_COST_ESTIMATE.md)의 유료 AI 계산과 월 10만 원 확대안은 비교 자료이며 채택한 예산이 아닙니다. 예산 승인을 다시 묻거나 특정 유료 요금제를 자동 구매하지 않습니다.

**Q&A 합의와 후속 범위:** 같은 반 학생과 교사 모두 답변하며 교사 답변을 구분합니다. 질문한 학생과 담당 교사 모두 해결 처리·다시 열기가 가능하고 답변 등록만으로 자동 해결하지 않습니다. 해결됨은 궁금증 해소이지 모든 답변의 공식 정답 승인이 아닙니다. 이 정책을 유지하되 Q&A 연결·게시글 관리, AI·EntryJS·정식 콘텐츠·실학생 등록·배포는 후속 작업입니다. 심화 통과 후 자유시간은 운영 아이디어이며 구체적인 조건·승인·자동 처리는 미정입니다.

1. 현재 Git 변경을 보존하고 [PRD](../PRD.md), [BUILD_BRIEF](BUILD_BRIEF.md), 공통 계약 `src/lib/classroom/types.ts`와 서버 연결 상태를 확인합니다. README·AGENTS의 최신 실행 절차를 사용합니다.

## 확정된 방향과 구현 상태

- 공개 홈 스타일은 사용자 만족을 확인했습니다. 로그인은 입력 위치를 직관적으로 보여주는 **중앙 집중형**으로 확정했고 현재 학생·교사 화면에 적용했습니다. 이번 구현에서 후속 Stitch 생성은 수행하지 않았습니다.
- [로그인 정책](../PRD.md#로그인-정책)의 비밀번호 조건·초기화·역할별 무활동 만료·중복 로그인과 반별 권한을 서버에 구현했습니다. 교사는 허용된 Google 계정, 강사는 2학년 10·11반 범위입니다. 실제 허용 Google 계정의 로컬 로그인과 교사 대시보드 진입도 사용자와 브라우저에서 확인했습니다.
- 학생 홈은 **이번 수업 + 열린 수업**이며 별도 지난 활동 영역은 통합했습니다. 열린 수업 목록에도 이번 수업을 표시로 구분해 포함합니다. 1차에서는 한 번 공개한 수업을 닫지 않습니다.
- 개념 자동 완료·전체 풀이 후 오답만 재도전·선택형 힌트·실습 자유 이동을 구현했습니다. 실습은 검증 통과 뒤 학생이 제출하고 서버 저장에 성공해야 완료됩니다. 필수 기본 활동만 수업 완료 조건에 포함합니다.
- 제출 후 수정하는 동안 기존 제출본·완료를 유지합니다. 수정본을 재검증·제출해야 새 제출본으로 반영합니다. AI 판단 곤란·오류 때 교사 확인으로 넘기는 합의는 유지하되 AI와 해당 예외 화면은 후속 연결입니다.
- 실제 세션·저장 API와 공통 타입을 학생·교사 화면이 공유합니다. 사용하지 않는 `demo-provider.tsx`는 삭제했고 `demo-data.ts`는 공개 홈 예시용으로만 유지합니다. EntryJS 자동채점은 공식 문서·소스로 가능성을 검토한 단계이며 실제 연동·채점 실험은 아직 하지 않았습니다.

## 홈에서 유지할 결정과 구현 주의점

- 담백한 존댓말, 사용 방법이 드러나는 설명. 감성적인 홍보 문구·장식용 영어·과한 응원 문구는 줄입니다.
- 흰색·옅은 회색·은은한 파랑과 절제된 라일락·살구색. Pretendard 유지. 토스는 색·여백·전개의 참고이며 로고·영상은 재사용하지 않았습니다.
- 큰 학사모는 정보 수업과 어울리지 않아 픽셀 캔버스로 교체했습니다. 작은 브랜드 학사모는 유지합니다. 캔버스 클릭·키보드·터치로 커서·반짝임·코드가 바뀝니다.
- 헤더는 왼쪽 브랜드, 가운데 수업 미리보기·공간 안내, 오른쪽 모션 아이콘·교실 입장. 교사 입장은 통합 선택창 안에 있습니다. 첫 화면·역할 예시의 중복 입장 버튼을 다시 추가하지 않습니다.
- 홈 모션은 사용자 요청으로 **OS 설정과 관계없이 기본 켜짐**입니다. 상단에서 줄이면 고정 스크롤과 장식 모션·전환을 해제하되 조작은 유지합니다. 새로고침하면 기본값으로 돌아옵니다. 다른 앱 화면은 OS 설정을 따릅니다.
- 고정 시연은 폭 960px 이상·높이 680px 이상일 때 사용합니다. 모바일·낮은 창은 직접 단계 선택입니다. 수동 선택은 새로운 사용자 스크롤 전까지 유지합니다.
- 활성 패널은 즉시 `visibility: visible`이 되어야 빠른 방향키·Tab 이동에서도 초점이 빠지지 않습니다. 픽셀 그래픽은 클릭 영역을 고정하고 내부 그림만 움직입니다.
- 공간 안내 앵커는 여백이 있는 section이 아닌 제목 `#classrooms`에 있습니다. 낮은 데스크톱은 간격을 줄여 예시 하단까지 들어옵니다.
- Tooltip·Dialog는 기존 Base UI를 활용했습니다. 역할 선택창은 Escape·바깥 클릭·닫기 버튼, 초점 순환·복귀를 지원합니다.
- 개념학습·퀴즈·실습은 한 수업의 예시이며 모든 수업의 진입 순서를 강제하는 정책이 아닙니다. 순서도는 한 단원입니다.

## 검증 근거와 범위

### 현재 구현 검증

- 학생 UI 4개·서버 API 8개·플랫폼 3개·탐색 4개·운영 1개 개별 검사를 로컬 Firebase 에뮬레이터의 합성 계정으로 통과했습니다. 학생 흐름에는 개념 자동 완료·오답 재도전·미응답 복원·순서 실습·검증 후 제출·제출 후 수정·저장 실패·느린 응답·두 탭 충돌이 포함됩니다.

- **전체 E2E 결과:** 프로덕션 빌드의 `next start`와 로컬 Firebase 에뮬레이터를 사용한 CI 방식으로 **27개 전체 통과**, 약 1.3분. 구성은 홈 7개·서버 API 8개·탐색 4개·운영 1개·플랫폼 3개·학생 UI 4개입니다. 원격 CI 실행 결과와는 구분합니다.
- 첫 CI 방식 실행에서 Playwright API 쿠키 저장소가 HTTP `127.0.0.1`의 Secure 쿠키를 보내지 않는 테스트 주소 문제가 드러났습니다. Playwright 설정·실행 스크립트·테스트 주소를 `localhost`로 통일했고 앱 쿠키 보안 설정은 변경하지 않았습니다. CI 방식에서 세션 쿠키의 `secure: true`를 확인하는 검사를 추가했으며 재발 방지 주의사항은 AGENTS에 기록했습니다.
- 승인된 Firebase의 이메일·비밀번호 및 Google 제공자 활성화·11개 빈 반 준비·Firestore 보안 규칙 배포를 확인했습니다. 클라우드 임시 합성 계정의 실제 Auth 로그인·수업 지정·개념/퀴즈/실습 검증과 제출·재로그인 복원·교사 제출 조회와 익명 Firestore 요청 거부(403)를 통과했습니다. 시험 계정 2개·작업·요청 제한 기록 삭제 및 시험 반의 빈 설정 복원을 마쳤습니다.
- **Google 실제 로그인 확인:** 사용자가 실제 허용 Google 계정으로 `localhost`에서 로그인한 결과를 확인했고, 브라우저에서도 `localhost:3001/teacher#students`의 교사 대시보드·담당 반 11개·빈 반·등록 학생 0명 상태를 확인했습니다. 제공자 설정·에뮬레이터 토큰 교환을 넘어서 실제 계정의 로컬 로그인까지 확인한 결과입니다. 호스팅 환경의 로그인·권한·저장 검증은 후속입니다.
- 실제 비밀값은 Git 제외된 `.env.local`에만 설정하고, 테스트 결과·스크린샷은 로컬 검사 산출물로 둡니다. Firestore 보안 규칙을 제외한 앱 배포와 실학생 등록은 아직 하지 않았습니다.

### 이전 기능 명세 인수인계 문서

- 이전 문서 체크포인트의 전달 변경은 PRD·DESIGN·README·HANDOFF 네 문서였습니다. 확정 정책과 제안·미결정·기존 체험 구현을 구분하고 로컬 파일 링크·문서 앵커·`git diff --check`를 확인했습니다. 아래 앱 검증 이력은 이전 실행 결과이며, 문서 변경 때문에 앱 테스트를 다시 실행한 것은 아닙니다.
- 실제 비밀번호·학생 자료·개인 설정·생성 캐시는 커밋 대상이 아닙니다. 화면 지도는 논의용 Mermaid 소스이며 이번 작업에서 브라우저 렌더링 검사는 하지 않았습니다.
