# 이어갈 작업

갱신: 2026-10-23(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정** (10/19): 297개 사전 등록·임시값 미발급([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)). 방식은 반별 30분 임시값 → 첫 입장 때 개인 비밀번호(사용자 결정). 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.
- **축제 미연시:** #59로 운영 `/festival-romance.html`에 공개됐습니다(10/20 응답 200 확인). 남은 일은 현장 확인입니다([자료 인수인계](../teaching-materials/festival-romance/HANDOFF.md)).

## 최근 반영

- **퀴즈 재도전 버튼·문구·이름 미션 검증** (10/23, `fix/quiz-retry-name-check`): 퀴즈를 다 맞히기 전엔 `틀린 문제만 다시 풀기`가 주 버튼, 세 수업 개념·퀴즈 문구 정리, 이름 미션은 두 번 실행 없이 서버 채점만으로 검증. 검증: Tier 1~2·빌드·E2E 10개 스펙, 전체 E2E 미실행.
- **#73 힌트·채점·반복 그림** (10/23, [계획](plans/hints-grading-visuals.md)): 같은 뜻 블록·결과 핵심어 말 인정(이름 미션은 초 없는 `말하기`도), 한 줄 단계·값을 넣은 블록 칩 힌트, 반복 `lc1`·`lc3`·`lc4` 실제 블록 그림. 검증: Tier 1~2·빌드·E2E 13개 스펙 90 통과, 전체 E2E 미실행.
- **#72 학습 경험 개선 1~4단계** (10/22, [계획](plans/learning-experience.md)): 그린 선 유지, 힌트=검증 블록, 1,024px 작업실, 재진입 0/2 없음, 오답 이유·`다시 생각해 보기`, 조립 순서·이름·용어 통일. 검증: Tier 1~2·선별 E2E·빌드, 전체 E2E 436 통과·13 생략.
- **#71 활동 기록의 PC 시계 의존 수정** (10/22): PC 시계가 서버보다 빠르면 학생 활동 기록이 클릭 뒤 60초 동안 매초 나갔고(10/21 두 반 콘솔 읽기 약 3만·쓰기 약 1.4만의 주원인으로 추정), 10분 넘게 빠르면 입장 직후 로그아웃, 느리면 기록이 끊겼습니다. 세션 응답에 서버가 잰 경과 시간 `idleMs`를 더해 PC 시계로 바꿔 비교합니다. 한계: 운영 PC별 시계 차이는 확인하지 못했습니다.
- **#70 반 공통 첫 입장 코드** (10/21): `학생 현황·계정`의 `첫 입장 열기`로 10분짜리 6자리 반 코드를 띄우면, 비밀번호를 아직 정하지 않은 학생이 학번과 코드로 들어와 개인 비밀번호를 정합니다([PRD §5.6](PRD.md#교사-대시보드의-1차-범위)). 한계: 운영 실제 로그인·한 반 동시 입장 미확인.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 두 수업의 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 실제 수업에서 봅니다. 길면 사용자와 정해 `PROGRAMMING_MISSIONS`의 `optional`로 옮길 수 있습니다.
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 터치·화면 읽기·200% 확대·프린터·자연 Cron은 현장에서 확인합니다.
3. **첫 실제 수업 직전 반별 발급:** 사용자는 10/19에 첫 수업은 교사 화면 `학생 현황·계정`(프로젝터 끔)의 학생별 `비밀번호 초기화`로 그 반만 수업 직전에 발급하기로 정했고, 10/20부터 같은 화면의 `임시 비밀번호 한꺼번에 발급`(#63)도 쓸 수 있습니다. 10/21부터는 반 공통 `첫 입장 열기`(#70)로 개별 배부 없이 첫 입장을 할 수 있으니, 첫 수업에 어느 방법을 쓸지 다시 정합니다. 절차는 [명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)를 따릅니다. 첫 반별 발급 전에 사용자가 Firebase 콘솔에서 Auth 할당량·남용 방어가 한 반 동시 입장을 막지 않는지 확인합니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).
5. **조건 수업 개념 흐름(교사 요청, 10/21 보류):** 다섯 개념이 완전히 이어질 필요는 없지만, 하나의 흐름 안에서 다음 개념을 짐작할 수 있게 순서·예시를 다듬습니다. 목차 이름·그림 정리 뒤 수업에서 반응을 보고 정합니다.

Firebase 5xx·차단 응답 E2E는 없습니다(#44).

- **운영 계정 대기:** `instructor` 체험용 비밀번호 교체(사용자, Firebase 콘솔)가 남았습니다. `csRateLimits` 옛 기록은 10/20에 정리했습니다([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)).
- **의존성:** 10/21 `npm audit` 24건(보통 5·높음 19)이 남습니다. 늘어난 1건은 잠금 파일 변경 없이 새로 나온 `hono` 권고(GHSA-5r4p-p66f-jhc7, `firebase-tools` 안, 범위 안 수정 가능)로 보입니다. 나머지는 고친 판이 없거나(`braces`) 메이저 업그레이드가 필요한 개발 도구(`shadcn`·`eslint-config-next`·`firebase-tools` 안)이며 운영 화면 경로가 아닙니다. `firebase` 13에서도 `@firebase/firestore`가 `@grpc/grpc-js ~1.9.0`에 묶여 GHSA-m9gg-hp2v-232j가 남지만, 앱은 클라이언트에서 `firebase/app`·`firebase/auth`만 쓰고 Firestore는 서버의 `firebase-admin`(grpc-js 1.14.5)으로 다룹니다.
