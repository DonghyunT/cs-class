# 이어갈 작업

갱신: 2026-10-19(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **진행 중:** 없음. #58로 조건·반복 수업의 작업실을 강아지 없는 엔트리 오브젝트 작업실로 바꿨습니다.
- **운영:** `main`의 최신 커밋을 배포 게이트(`app` 성공 뒤 공개)로 반영합니다. 앱 코드의 마지막 변경은 #54입니다. 설정 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정** (10/19): 사용자 승인으로 2-1~2-11반 각 1~27번, 297개를 [명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)대로 사전 등록했습니다(2026학년도, 충돌 0, 체험 계정은 건드리지 않음). 사용자는 공통 비밀번호 대신 문서 정책(반별 30분 임시값 → 첫 입장에서 개인 비밀번호)을 골랐고, 임시값은 아직 발급하지 않았습니다. 명부 CSV와 등록 직후 백업은 이 PC의 Git 제외 `private/`에만 있습니다.

## 최근 반영

- **오브젝트 창 높이 고정·미션 힌트 정리·‘새로 그리기’ 잠금** (10/19): 오브젝트 추가 창이 분류마다 높이가 달라지던 것을 고정 높이로 바꾸고, 실험·힌트 카드를 띄웠으며, 힌트를 짧게 하고 검증 블록 목록을 접었습니다. 모양 탭의 ‘새로 그리기’가 믿을 수 없는 빈 그림(`_1x1.png`)을 더해 작품을 읽지 못하게 만들던 버그는 `painter.newPicture`를 막아 고쳤습니다. 검증: 선별 E2E(반복 수업의 새로 그리기 검사 추가 포함)·전체 E2E 미실행. 한계: 옛 작품·「프로그래밍의 기초」는 바뀌지 않았고, 이미 ‘새그림’이 저장된 작품은 확인하지 못했습니다.
- **조건·반복 수업 화면 정리와 첫 미션 시작 작품 수정** (10/19): 새로 여는 조건·반복 수업의 첫 미션(평균 계산기·정사각형)이 강아지로 열리던 문제를 `emptyWork`에서 미션별 시작 작품을 쓰게 고쳤습니다. 개념 화면에 개념마다 작은 그림을 더했고([DESIGN §4.1](DESIGN.md#41-수업-전용-공통-틀-lessonshell)), 미션 카드를 가운데 정렬했으며, 방향키 미션은 앞 미션 작품을 가져오지 않는 독립 작품이 됐습니다([PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초)). 검증: 단위(entry-palette 28)·`test:scope` 20·선별 E2E(프로그래밍·조건·반복 수업, 공통 스모크, 개념 화면, 작업 복구 11개 파일 81개 통과)·전체 E2E 미실행. 한계: 이미 저장된 강아지 작품(체험 계정)은 새 시작 작품으로 바꿀 수 없고, 학교 PC 화면은 보지 않았습니다.
- **#58 조건·반복 수업 엔트리 오브젝트 묶음** (10/19): 두 수업은 공식 엔트리봇으로 시작하고, 분류형 창에서 공식 엔트리 오브젝트 214개(약 16MB)를 골라 쓰며, 모양 탭을 보기 전용으로 엽니다. 채점은 시작하기 줄을 가진 한 오브젝트를 보고, 시작하기 코드가 여러 오브젝트에 나뉘면 경고 토스트와 검증 실패로 알립니다([PRD §4.1.3](PRD.md#413-조건반복-수업의-강아지-없는-작업실)). 「프로그래밍의 기초」와 강아지로 저장한 작품은 그대로입니다. 검증: 단위(entry-palette 27)·`test:scope`·`test:review`·선별 E2E(엔트리 수업 12파일, 두 수업 모든 미션 실제 EntryJS 실행 일치 포함)·PR 머리 전체 E2E 1회. 교사 제출 대화상자 폭 검사는 열림 애니메이션이 끝날 때까지 기다리게 고쳤습니다(CI에서 859px). 한계: 엔트리 저작권 가이드 원문(PDF)은 읽지 못해 공개 요약(CC BY-NC 2.0·학교 수업 허용·출처 표시)만 확인했고, 학교 PC 화면은 보지 않았습니다.
- **#56 교사 실행 작업실 폭 CI 불안정 해결** (10/19): 교사 제출 모달이 실행기를 열어도 CI에서 860px에 머물던 원인은 공용 팝업의 `duration-100`이 함께 켠 `transition: all`이었습니다. 폭 전환이 다음 화면 갱신까지 대기하는데, 느린 CI에서는 엔트리 작업실 부팅이 몇 초간 화면 갱신을 막아 시작값 860px이 남았습니다(임시 진단 #55로 확인). 제출 모달의 전환을 끄고, E2E는 5초 poll(부팅 중엔 측정 자체가 멈춤) 대신 클릭 직후 폭 1220px·전환 없음을 한 번에 확인합니다. 교사 실행기(`entry-project-preview.tsx`)와 그 검사(`programming-learning.spec.ts`)는 선별 검증의 엔트리 공통 파일로 묶었습니다. 검증: lint·typecheck·`test:scope` 20·로컬 프로덕션 빌드 선별 E2E 10파일 64개·PR CI 엔트리 3수업 선별 실행(전체 E2E 미실행).
- **#53·#54 신규 엔트리 수업 2개** (10/18): 「조건에 따라 달라지는 프로그램」(`conditionals`, [PRD §4.1.1](PRD.md#411-정규-수업-조건에-따라-달라지는-프로그램))과 「반복으로 똑똑하게」(`loops`, [§4.1.2](PRD.md#412-정규-수업-반복으로-똑똑하게))를 공개했습니다. 「프로그래밍의 기초」의 평균 계산기는 조건 수업 첫 미션으로 옮겼고, 옛 평균 작품은 저장·교사 열람만 됩니다. 미션은 수업별 목록(`LESSON_MISSIONS`)으로 나뉘고, 서버 채점기(`programming-grader.ts`)는 조건·반복·붓·클릭 이벤트·모양 바꾸기를 엔트리 의미대로 실행하며 실행 예산을 둡니다. 나무 키우기는 사용자가 준 엔트리 공식 자료(`나무 키우기.ent`)의 그림·정답 흐름을 씁니다. 검증: 단위 23·`test:scope` 20·선별 E2E(수업별 실제 EntryJS 실행 일치 포함)·전체 E2E 1회. 한계: 운영 실제 계정 화면과 40분 수업 분량은 현장에서 확인해야 합니다.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 운영 교사 계정으로 두 수업을 미리보기하고, 실제 수업에서 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 관찰합니다. 나무 키우기가 길면 선택 도전으로 옮길 수 있습니다(`PROGRAMMING_MISSIONS`의 `optional`).
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 터치·화면 읽기·200% 확대·프린터·자연 Cron은 현장에서 확인합니다.
3. **첫 실제 수업 직전 반별 발급:** 그 반만 `--mode issue --class 2-N`으로 발급하고 `issued` 줄이 있는 학생에게만 전달합니다(30분 만료라 미리 몰아 발급하지 않음). 관리자 키가 없는 학교 PC에서는 교사 화면 `학생 현황·계정`의 학생별 `비밀번호 초기화`로 같은 30분 임시값을 발급합니다(사용자가 10/19에 첫 수업은 이 방법으로 정함, 프로젝터 끄고 사용). 반 전체 일괄 발급 버튼은 필요해지면 새 기능으로 검토합니다. 명부를 1~27번 일괄로 만들어 실제로 없는 번호의 계정도 있습니다. 해당 번호의 줄은 전달하지 않으면 30분 뒤 만료되어 입장할 수 없습니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).
5. (제안) `scripts/check-docs.mjs`에 HANDOFF 크기·특정 도구 이름 경고 추가(PR 경로).

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 성공은 2026-10-18 `main`(`7264de7`) GitHub 수동 실행(run 39063459497, 397 통과·14 생략)입니다. 로그인 상한은 긴 실행에서도 넘치지 않았으며, Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **운영 DB 정리:** 운영 `csRateLimits`에 10/18 이전 비밀번호별 기록이 남아 있습니다([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황), 운영 DB 작업 승인 필요).
- **운영 강사 계정:** `instructor` 담당 반을 10/18에 10·11반으로 줄였습니다. 실제 강사에게 전달하기 전에 체험용 공통 비밀번호를 Firebase 콘솔에서 바꿔야 합니다(사용자 작업).
- **의존성:** `main` CI의 `npm ci`가 취약점 26건(보통 4·높음 22)을 보고합니다(10/18, 미점검).
- **무료 한도:** 하루 4반×27명×45분 모형에서 정기 읽기만 약 29,520회입니다(실측 아님). 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 내 4반 운영을 보장하지 않습니다.
- **복습 확인 결정(#46):** 열어 둔 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전에 다시 확인 요청을 보내면 결정 메시지가 새 요청으로 덮입니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 재개 전 오래된 대기 요청 처리 기준·`csHelpRequests` 인덱스·활성 모드 검사를 확인합니다.
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
