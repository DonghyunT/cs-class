# 이어갈 작업

갱신: 2026-10-25(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정:** 등록 현황과 입장 방식(10/21부터 반 공통 첫 입장 코드)은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있습니다. 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.

## 최근 반영

- **#86 진도 링 단계별 시작 반원** (10/25): 시작점 반원이 전체 0%일 때만 보여, 한 단계를 진행하면 남은 단계가 빈 칸처럼 보이던 것을 완료 0개인 단계마다 보이게 고침([DESIGN §4.3](DESIGN.md#43-3구간-원형-진도-게이지-activityprogressring)). 검증: typecheck·lint, 선별 E2E 5개 스펙 44 통과, 실습 1개 완료 화면 확인, 전체 E2E 미실행.
- **#85 문서 정비** (10/25): 코드와 어긋난 설명(#74 뒤 이름 미션 실행 기록, 살펴볼 학생 아이콘 색, 교사 미리보기, 미션 개수 등)을 고치고, PRD의 날짜별 이력은 지우고 채점 세부 사본은 개발 안내 링크로, 긴 절차는 번호 목록으로 바꿈. 첫 입장 방식(반 공통 코드, 사용자 확인)을 운영 환경 현황에 기록. 검증: `check-docs`·`git diff --check`, 전체 E2E 미실행(문서만).
- **#84 help-paused 검사 가짜 응답 복구** (10/24): 10/24 전체 E2E의 유일한 실패는 검사 가짜 응답에 #78의 `offList`가 없던 탓이라 검사만 고침(앱 동작 그대로). 검증: `help-paused` 선별 E2E 11 통과, 전체 E2E 미실행.
- **#83 색상 다듬기·퀴즈 화면 통일·0% 진도 링** (10/24): 색마다 뜻 하나([DESIGN §2.1](DESIGN.md#21-컬러-토큰-color-palette))로 대시보드 카드·단계 탭·진도 막대를 다듬고, 기초 수업 퀴즈를 공용 화면으로, 0% 진도 링을 세 단계 반원으로 바꿈. 검증: Tier 1~2·선별 E2E 12개 스펙, 전체 E2E는 #82와 합쳐 실행(남은 한계).
- **#82 강사 안내서 수업 운영판·엔트리 작업 중 로그아웃 수정** (10/24): 안내서 PDF에 수업 운영 5쪽(첫 입장·순회·저장/제출·마치기 확인)을 더하고, 엔트리 작업실 안 조작을 활동으로 세어 10분 로그아웃을 고침. 검증: Tier 1·선별 E2E 32 통과, 전체 E2E는 #83과 합쳐 실행.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 두 수업의 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 실제 수업에서 봅니다. 길면 사용자와 정해 `PROGRAMMING_MISSIONS`의 `optional`로 옮길 수 있습니다.
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 첫 입장 코드(#70)의 동시 입장, PC별 시계 차이(#71), 터치·화면 읽기·200% 확대·프린터·자연 Cron, 축제 미연시(`/festival-romance.html`, [자료 인수인계](../teaching-materials/festival-romance/HANDOFF.md))는 현장에서 확인합니다.
3. **아직 첫 입장 전인 반:** 같은 반 공통 첫 입장 코드로 들입니다([명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)). 사용자가 Firebase 콘솔에서 Auth 할당량·남용 방어가 한 반 동시 입장을 막지 않는지 확인했는지는 기록이 없으니, 확인 뒤 이 줄을 지웁니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).
5. **조건 수업 개념 흐름(교사 요청, 10/21 보류):** 하나의 흐름 안에서 다음 개념을 짐작할 수 있게 순서·예시를 다듬습니다([테스터 합의](reference/student-tester-consensus-20261022.md#4-최종-합의-다섯-개념의-흐름)). 목차 이름·그림은 10/21(`b18763c`)에 정리했으니 실제 수업 반응을 보고 정합니다.
6. **코드 정리 후보(10/25 문서 정비에서 발견):** 남은 한계의 '조건·반복 수업 질문 대기'를 고칠 때 함께 고칩니다. 나무 미션 오류 문구가 없는 `‘처음 작품으로’` 버튼을 안내함(`programming-grader.ts`), `programming-entry.ts`의 `gradeKey` 주석이 낡음, `check-cloud-flow.mjs` 오류 문구가 승인이 필요한 전체 E2E(`npm run test:e2e`)를 권함.

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 `main` 전체 성공은 10/18 `7264de7`(run 39063459497)입니다. 마지막 실행은 10/24 로컬(#82+#83 합친 임시 브랜치, 441 통과·1 실패·13 건너뜀)이고 실패는 #84에서 고쳤습니다. Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **CI·로컬 검사 불안정:** `main` CI의 10초 대기 검사가 재실행으로 통과한 일이 두 번 있었습니다(10/19 `programming-classroom`, 10/21 `conditionals`의 `마지막 말`). 로컬에서는 새로 켠 서버의 첫 실행에서만 `programming-classroom`의 `entry-assets` 검사·`flowchart-auto-completion`(#67)이 실패합니다(원인 미확정). 반복되면 대기 시간 기준을 점검합니다.
- **사용자 할 일:** `instructor` 체험용 비밀번호 교체(Firebase 콘솔, [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)).
- **의존성:** 10/21 `npm audit` 24건은 운영 화면 경로가 아닌 개발 도구이고, `@grpc/grpc-js` 권고(GHSA-m9gg-hp2v-232j)는 서버 `firebase-admin`만 Firestore를 써서 해당하지 않습니다.
- **무료 한도:** 10/21 실제 두 반(엔트리 수업)은 읽기 약 3만·쓰기 약 1.4만이었고, 시계 폭주를 빼도 저장·채점이 반당 쓰기 약 1천 회입니다. 하루 4반×27명×45분의 정기 읽기는 수업 화면 기준 측정 환산 약 2.9만 회(과금 실측 아님, 10/24부터 대시보드 30초 조회도 같은 2회)이고, 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 안을 보장하지 않습니다.
- **수업 누적:** 대시보드 응답에 수업마다 엔트리 작품 원문이 담겨 프로그래밍 수업이 수십 개면 응답이 수 MB가 될 수 있으니, 그때 진도 판정 필드만 보내도록 줄입니다.
- **복습 확인 결정(#46):** 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전 재요청은 결정 메시지를 덮습니다.

- **조건·반복 수업 질문 대기:** 강아지 없는 작품은 `workspace.js`가 강아지의 질문만 대기로 봐서, 대답을 기다리는 시간도 15초 실행 한도에 셉니다(PRD §4.1과 다름, 키 입력은 0부터 다시 셈). 코드 수정 대상입니다.
- **엔트리 작업실:** 엔트리 저작권 가이드 원문(PDF)은 읽지 못해 공개 요약(CC BY-NC 2.0·학교 수업 허용·출처 표시)만 확인했습니다(#58).
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
- **학습 경험 후속:** 옛 피드백 문구·긴 식 잘림 등 기록만 한 항목, 5단계, 복습 개념 확인 정답 위치(사용자 결정)는 [보관된 계획 §14](archive/cs-class/2026-10-24-completed-plans/learning-experience.md#14-제외와-이유).
