### 운영 관찰과 남은 병목

운영은 기존 앱의 조회 중심 관찰입니다. 선생님이 직접 로그인한 Chrome의 Network에서 시간·크기만 제공했습니다. 헤더·쿠키·토큰·응답 본문·학생 자료를 기록하지 않았으며 운영 합성 계정·자료 변경은 하지 않았습니다.

첫 관찰의 변동과 세션 시작 이전 시간이 있으므로 서버 콜드 스타트로 단정하지 않습니다. `identity`의 세션 검증과 트랜잭션 계정 검사는 이번 구현에서 유지했습니다. 운영 로그인 세션 약 627ms와 할 일 약 4.31초는 일괄 조회만으로 해결된다고 보장할 수 없습니다. 후속은 세션 검증·Firestore 계정/목록 요청·서버 초기화·브라우저 초기화 시간을 분리 측정하는 작업입니다. 운영과 로컬 수치로 감소율을 계산하지 않았습니다.

## 다른 PC에서 이어가기

1. [개발 안내](DEVELOPMENT.md#다른-pc에서-시작)에 따라 Git·Node 24·Java 21+와 저장소 접근을 준비합니다. 완료한 파일럿이 포함된 `main` 기준은 `a5ca4aa`이며 이번 UI·성능 개선은 원격 `codex/dashboard-visual-polish`와 Draft PR #12에서 이어갑니다.
2. 기존 PC의 미커밋 변경을 보존하고, 깨끗한 작업 트리에서 `git fetch origin --prune`로 원격 상태를 확인합니다. 이번 작업은 `git switch --track origin/codex/dashboard-visual-polish`(로컬 브랜치가 없을 때)로 이어가고, 별도 작업은 최신 `main`에서 새 `codex/` 브랜치를 만듭니다. 새 PC는 README의 복제 안내를 따릅니다.
3. 루트에서 `npm ci`, 최초 `npx playwright install chromium`을 실행한 뒤 `npm run dev:emulator`로 확인합니다. EntryJS 자산은 자동 준비되며 Java·브라우저·플러그인·인증·`scratch/` 캐시는 PC마다 준비합니다.
4. `.env.local`·관리자 키·학생 원본은 Git으로 전달되지 않습니다. 실제 Firebase 연결이 필요할 때만 [서버 설정](FIREBASE_SETUP.md#다른-pc의-서버-설정)을 따르고 각 PC에서 직접 인증합니다.

> AGENTS.md와 docs/HANDOFF.md를 읽고 CS Class를 이어가자. 현재 브랜치·미커밋 변경·원격 동기화를 확인하자. Draft PR #12의 대시보드 UI·성능 개선을 이어가려면 codex/dashboard-visual-polish를 가져오고 측정 결과와 남은 세션 병목부터 파악하자.
