## 최근 반영

- **#48 프로그래밍 프로토타입 삭제** (10/18): 공개 `/prototype/programming`과 그 코드·검사를 지웠습니다(점검 F6). 정식 수업이 검사하지 않던 동작 5개는 `programming-name-mission.spec.ts`로 옮겼고, 비어 있던 개념 화면 색 변수를 수업 틀 토큰으로 바꿔 카드·선택지 테두리가 보입니다([PRD §4.2](PRD.md#42-프로그래밍-프로토타입-삭제)). 검증: 관련 E2E 10파일 79개, 병합 뒤 전체 E2E 통과. 한계: 화면 변화는 1280·390px 스크린샷으로만 비교했습니다.
- **#47 서버 오류 종류·코드 기록, 담당 교사 Q&A 삭제** (10/18): 예상하지 못한 서버 오류에만 허용 목록의 `errorName`·`errorCode`를 남기고([DEVELOPMENT §5.2](DEVELOPMENT.md#52-실패-진단-및-에러-로깅-규격), F4), 담당 교사·강사가 반 질문을 답변과 함께 지울 수 있습니다([PRD §5.4](PRD.md#54-우리-반-질문-qa), F5). #41 뒤 낡은 E2E 기대값 2개도 고쳤습니다. 검증: 관련 E2E 50개, 고친 2개 5회 반복, 병합 뒤 전체 E2E 통과. 한계: 실제 Firestore 오류로 로그를 확인하는 E2E는 없습니다.
- **#46 교사 확인 결정 뒤 학생 저장 충돌** (10/18): 교사의 복습 확인 결정이 revision을 올리지 않아, 열어 둔 학생 화면이 "다른 탭" 충돌 없이 저장하고 그 응답으로 결정을 받습니다(F3). 검증: 재현 E2E(수정 전 409로 실패, 수정 뒤 통과), 관련 E2E 46개 중 44개(2개는 #47에서 고친 기존 실패), 병합 뒤 전체 E2E 통과. 한계: 학생 화면은 저장·재접속 전까지 결정을 받지 않고(이전과 같음), 그 전에 확인 요청을 다시 보내면 교사의 결정 메시지가 새 요청으로 바뀝니다.
- **#45 게스트 교사 1~11반 담당** (10/18): 로컬 전용 `guest-teacher`가 2학년 1~11반을 맡고 처음 화면은 1반입니다([DEVELOPMENT §1.3](DEVELOPMENT.md#로컬-게스트-입장)). 운영은 게스트 로그인이 꺼져 영향 없음. 검증: 관련 E2E 16개, lint·typecheck·문서·`test:review`, 병합 뒤 전체 E2E 통과. 한계: 담당 반 밖 초기화 거부는 `classroom-api`의 강사 검사만 확인.
- **문서·반영 흐름 정비** (10/18, 사용자 결정으로 직접 push): 위험도별 두 경로와 작업 단위 승인 범위를 정했고([DEVELOPMENT §2.1](DEVELOPMENT.md#위험도별-반영-경로)), HANDOFF 압축·[문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)·완료 계획 보관을 했습니다. 검증: 문서 검사·테스트, 보관 파일 sha256 대조, 독립 검토 2명 반영. 앱 코드 변경 없음, 전체 E2E 미실행. 한계: 설정과 별개로 세션의 자동 권한 검사가 병합을 막을 수 있습니다(#45).

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 성공은 2026-10-18 `main`(`7264de7`) GitHub 수동 실행(run 39063459497)으로 397개 통과, 14개 생략(손들기 활성 모드·Windows 전용 검사)입니다. 로그인 상한은 긴 실행에서도 넘치지 않았습니다. Firebase 5xx·차단 응답을 일으키는 E2E는 없습니다(#44).
- **운영 DB 정리:** 운영 `csRateLimits`에 10/18 이전의 비밀번호별 기록이 남아 있습니다. 정리 기준은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있고, 운영 DB 작업 승인이 필요합니다.
- **운영 강사 계정:** `instructor`의 담당 반을 10/18에 10·11반으로 줄였습니다. 비밀번호는 아직 체험용 공통 비밀번호라, 실제 강사에게 주기 전에 Firebase 콘솔에서 바꿔야 합니다(사용자 작업).
- **의존성:** main CI의 `npm ci`가 취약점 26건(보통 4·높음 22)을 보고합니다(10/18). 아직 점검하지 않았습니다.
- **무료 한도:** 하루 4반×27명×45분 모형에서 정기 읽기만 약 29,520회입니다(실측 아님). 진입·저장·채점은 별도라 무료 일일 읽기 5만 회 안의 4반 운영을 보장하지 않습니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 다시 켜기 전에 오래된 대기 요청의 처리 기준, `csHelpRequests` 인덱스 준비, 활성 모드 검사를 확인합니다.
- **화면:** 821px 부근에서 수업 헤더의 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼의 오른쪽 여백 일부가 가려지고, 실제 휴대폰에서는 확인하지 않았습니다(#43).
