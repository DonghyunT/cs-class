# 이어갈 작업

갱신: 2026-10-18(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **진행 중:** 없음. 신규 엔트리 수업 2개를 #53(수업별 미션 구조)·#54(두 수업과 평균 계산기 이동)로 반영했습니다.
- **운영:** `main`의 최신 커밋을 배포 게이트(`app` 성공 뒤 공개)로 반영합니다. 앱 코드의 마지막 변경은 #54입니다. 설정 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.

## 최근 반영

- **#53·#54 신규 엔트리 수업 2개** (10/18): 「조건에 따라 달라지는 프로그램」(`conditionals`, [PRD §4.1.1](PRD.md#411-정규-수업-조건에-따라-달라지는-프로그램))과 「반복으로 똑똑하게」(`loops`, [§4.1.2](PRD.md#412-정규-수업-반복으로-똑똑하게))를 공개했습니다. 「프로그래밍의 기초」의 평균 계산기는 조건 수업 첫 미션으로 옮겼고, 옛 평균 작품은 저장·교사 열람만 됩니다. 미션은 수업별 목록(`LESSON_MISSIONS`)으로 나뉘고, 서버 채점기(`programming-grader.ts`)는 조건·반복·붓·클릭 이벤트·모양 바꾸기를 엔트리 의미대로 실행하며 실행 예산을 둡니다. 나무 키우기는 사용자가 준 엔트리 공식 자료(`나무 키우기.ent`)의 그림·정답 흐름을 씁니다. 검증: 단위 23·`test:scope` 20·선별 E2E(수업별 실제 EntryJS 실행 일치 포함)·전체 E2E 1회. 한계: 운영 실제 계정 화면과 40분 수업 분량은 현장에서 확인해야 합니다.
- **#51·#52 엔트리 채점 보정** (10/18): 곱셈·평균은 A·B에 두 입력이 순서와 관계없이 있으면 통과하고, 방향키 미션은 네 방향키 줄만 채점합니다(시작하기 줄은 선택, [PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초)). #52는 엔트리 단위 테스트·픽스처를 선별 E2E의 `programming-13`에 연결했습니다. 검증: `entry-palette` 15·`test:scope` 20·선별 E2E 53개·`main` CI 통과(전체 E2E 미실행). 한계: 운영 실제 계정으로 채점을 확인하지 않았습니다.
- **#50 엔트리 후속 보강 및 교사 제출 작품 시각화·실행** (10/18, 후속 `4037e36`): 92개 확장 블록의 입력값·드롭다운·연산자를 한국어 문장으로 표시하고([PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초)), 이벤트 대기·사용자 조작 중 시간을 15초 강제 종료에서 제외하며 내부 API 패치 전 함수 존재 검사를 더했습니다. 교사 제출 모달에 오브젝트 요약·색상 블록 묶음 조립도와 인라인 실행기(모달 폭 `860→1220px` 즉시 확장, `Esc` 2단계 닫기)를 넣었습니다([DESIGN §4.4](DESIGN.md#44-학생교사-대시보드)). 검증: `test:review`(27)·`test:scope`(20)·프로덕션 빌드 E2E 9개·`main` CI 56개 통과(전체 E2E 미실행). 한계: 교사 인라인 실행기는 읽기·실행 전용이라 편집 내용은 저장되지 않습니다.
- **#49 9/26 V1 보관본 삭제** (10/18): algorithm-studio 참고본의 구판이자 개인정보 제외 전 파일이 남았던 `archive/v1/`·`docs/archive/v1/`(약 20MB, 337개)을 사용자 승인으로 지웠습니다. 복구는 [보관함 안내](../archive/README.md#삭제한-926-v1-보관본)를 따르며 깨진 이식 기록 링크도 고쳤습니다. 검증: 문서 검사 통과, 현재 코드·문서 참조 없음(앱 코드 변경 없음). 한계: 지운 파일은 Git 이력에 남습니다.
- **#48 프로그래밍 프로토타입 삭제** (10/18): 공개 `/prototype/programming`과 관련 코드·검사를 지웠습니다(점검 F6). 정식 수업이 검사하지 않던 동작 5개는 `programming-name-mission.spec.ts`로 옮겼고, 비어 있던 개념 화면 색 변수를 수업 틀 토큰으로 연결했습니다([PRD §4.2](PRD.md#42-프로그래밍-프로토타입-삭제)). 검증: 관련 E2E 10파일 79개·병합 뒤 전체 E2E 통과. 한계: 화면 변화는 1280·390px 스크린샷으로만 비교했습니다.

3. (제안) `scripts/check-docs.mjs`에 HANDOFF 크기·특정 도구 이름 경고 추가(PR 경로).

- **전체 E2E:** 마지막 성공은 2026-10-18 `main`(`7264de7`) GitHub 수동 실행(run 39063459497, 397 통과·14 생략)입니다. 로그인 상한은 긴 실행에서도 넘치지 않았으며, Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **운영 DB 정리:** 운영 `csRateLimits`에 10/18 이전 비밀번호별 기록이 남아 있습니다([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황), 운영 DB 작업 승인 필요).
- **운영 강사 계정:** `instructor` 담당 반을 10/18에 10·11반으로 줄였습니다. 실제 강사에게 전달하기 전에 체험용 공통 비밀번호를 Firebase 콘솔에서 바꿔야 합니다(사용자 작업).
- **의존성:** `main` CI의 `npm ci`가 취약점 26건(보통 4·높음 22)을 보고합니다(10/18, 미점검).
- **무료 한도:** 하루 4반×27명×45분 모형에서 정기 읽기만 약 29,520회입니다(실측 아님). 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 내 4반 운영을 보장하지 않습니다.
- **복습 확인 결정(#46):** 열어 둔 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전에 다시 확인 요청을 보내면 결정 메시지가 새 요청으로 덮입니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 재개 전 오래된 대기 요청 처리 기준·`csHelpRequests` 인덱스·활성 모드 검사를 확인합니다.
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
