# 이어갈 작업

갱신: 2026-10-20(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정** (10/19): 297개 사전 등록·임시값 미발급([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)). 방식은 반별 30분 임시값 → 첫 입장 때 개인 비밀번호(사용자 결정). 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.
- **축제 미연시:** #59로 운영 `/festival-romance.html`에 공개됐습니다(10/20 응답 200 확인). 남은 일은 현장 확인입니다([자료 인수인계](../teaching-materials/festival-romance/HANDOFF.md)).

## 최근 반영

- **#68 문서 정비·AGENTS 경계 재구성** (10/20): 읽기 전용 검토자 패널의 만장일치 안만 반영해 문서를 코드·CI 기록과 맞추고, AGENTS.md를 작업 순서와 3단 경계(묻지 않고 하는 일·먼저 묻는 일·절대 금지)로 재구성했습니다. `check-docs`가 HANDOFF 크기·항목 수와 방치된 계획을 검사합니다. 검증: `check-docs`(12개)·문서 단위 3·`test:scope` 20·린트·타입·전체 E2E 미실행(앱 코드 변경 없음).
- **#67 열린 수업 닫기·드롭다운·스크롤바** (10/20): 수업 관리에서 열린 수업도 체크를 풀어 닫습니다(작업은 남고 다시 열면 이어 함, [PRD §5.6](PRD.md#교사-대시보드의-1차-범위)). 드롭다운 7곳·스크롤바·대화상자 닫기 버튼을 공용 모양으로 맞췄습니다([DESIGN §3](DESIGN.md#3-공통-컴포넌트-명세-global-components)). 검증: 린트·타입·`check-docs`·관련 E2E 13개 파일 98개 통과·병합 뒤 `main` 전체 E2E 1 실패([남은 한계](#남은-한계와-다음-결정)). 한계: Windows 실제 Chrome·Whale 화면 미확인.
- **#65·#66 의존성 보안 패치** (10/20): `next` 16.3.8(권고 6건)·범위 안 `npm audit fix`·클라이언트 `firebase` 13으로 올렸고 화면 동작은 같습니다. 검증: 린트·타입·빌드·`check-docs`·단위·대표 E2E(#65 110개, #66 53개 통과)·전체 E2E 미실행. 한계: 운영 Google 로그인 실측 없음. Node 24.12 이상 필요([DEVELOPMENT §1.1](DEVELOPMENT.md#11-시스템-요구사항)).
- **#63 반별 임시 비밀번호 일괄 발급** (10/20): 비밀번호를 아직 정하지 않은 학생만 골라 30분 임시값을 발급·인쇄하며, 이미 정했거나 접속 중인 학생은 서버가 거절합니다([PRD §5.6](PRD.md#교사-대시보드의-1차-범위)). 검증: 린트·타입·`check-docs`·빌드·#61~#64를 합친 선별 E2E 229개 통과(시간표 3개는 가짜 시간표 서버 없이 실패)·전체 E2E 미실행. 한계: 실제 학교 프린터 인쇄 미확인.
- **#62 교사 홈 카드·제출 작품 창 가독성** (10/20): `교사가 확인할 일` 카드에 수업 이름·최근 제출을 더했고, 제출 작품 창은 고른 수업의 작품 하나만 읽습니다([DESIGN](DESIGN.md#학생교사-대시보드)). 검증: 린트·타입·`check-docs`·선별 E2E 52개+55개(새 검사는 수정 전 실패 확인)·전체 E2E 미실행.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 두 수업의 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 실제 수업에서 봅니다. 길면 사용자와 정해 `PROGRAMMING_MISSIONS`의 `optional`로 옮길 수 있습니다.
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 터치·화면 읽기·200% 확대·프린터·자연 Cron은 현장에서 확인합니다.
3. **첫 실제 수업 직전 반별 발급:** 사용자는 10/19에 첫 수업은 교사 화면 `학생 현황·계정`(프로젝터 끔)의 학생별 `비밀번호 초기화`로 그 반만 수업 직전에 발급하기로 정했고, 10/20부터 같은 화면의 `임시 비밀번호 한꺼번에 발급`(#63)도 쓸 수 있습니다. 절차는 [명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)를 따릅니다. 첫 반별 발급 전에 사용자가 Firebase 콘솔에서 Auth 할당량·남용 방어가 한 반 동시 입장을 막지 않는지 확인합니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 실행은 10/20 `main`(`a24e0cc`) run 39375010793으로 420 통과·14 생략·1 실패였고, 실패한 `classroom-api`는 `334cca0`에서 고쳤지만 전체 재실행은 하지 않았습니다. 마지막 `main` 전체 성공은 10/18 `7264de7`(run 39063459497)입니다. Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **CI·로컬 검사 불안정:** 10/19 `main` CI가 `programming-classroom`의 10초 대기 검사에서 한 번 실패해 재실행으로 통과했습니다. 로컬에서는 새로 켠 서버의 첫 실행에서만 `entry-assets`·`flowchart-auto-completion`(#67) 검사가 실패하고 켜 둔 서버에서는 통과합니다(원인 미확정). 반복되면 대기 시간 기준을 점검합니다.
- **운영 계정 대기:** `instructor` 체험용 비밀번호 교체(사용자, Firebase 콘솔)가 남았습니다. `csRateLimits` 옛 기록은 10/20에 정리했습니다([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)).
- **의존성:** 10/20 점검 뒤 `npm audit` 23건(보통 4·높음 19)이 남습니다. 고친 판이 없거나(`braces`) 메이저 업그레이드가 필요한 개발 도구(`shadcn`·`eslint-config-next`·`firebase-tools` 안)이며 운영 화면 경로가 아닙니다. `firebase` 13에서도 `@firebase/firestore`가 `@grpc/grpc-js ~1.9.0`에 묶여 GHSA-m9gg-hp2v-232j가 남지만, 앱은 클라이언트에서 `firebase/app`·`firebase/auth`만 쓰고 Firestore는 서버의 `firebase-admin`(grpc-js 1.14.5)으로 다룹니다.
- **무료 한도:** 하루 4반×27명×45분의 정기 읽기는 측정 환산 약 2.9만 회(과금 실측 아님)이고, 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 안을 보장하지 않습니다.
- **복습 확인 결정(#46):** 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전 재요청은 결정 메시지를 덮습니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 재개 전 오래된 대기 요청 처리 기준·`csHelpRequests` 인덱스·활성 모드 검사를 확인합니다.
- **엔트리 작업실:** 10/19 이전에 강아지로 저장된 체험 계정 작품은 새 시작 작품으로 바뀌지 않습니다. 엔트리 저작권 가이드 원문(PDF)은 읽지 못해 공개 요약(CC BY-NC 2.0·학교 수업 허용·출처 표시)만 확인했습니다(#58).
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
