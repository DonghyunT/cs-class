# 이어갈 작업

갱신: 2026-10-28(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정:** 등록 현황과 입장 방식(10/21부터 반 공통 첫 입장 코드)은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있습니다. 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.
- **진행 중 브랜치(원격):** `feat/assessment-portfolio`(포트폴리오 채점, 0단계는 #93으로 병합, 1단계는 main에서 새로 시작, [계획](plans/assessment-portfolio.md)), `feat/festival-character-v7`(축제 캐릭터 초안 보존, 게임 미적용). 설명은 각 브랜치에 있습니다.

## 최근 반영

- **#93 첫 제출 시각 남기기** (10/28, [포트폴리오 계획](plans/assessment-portfolio.md) 0단계): 다시 제출하거나 교사가 승인해 제출본이 바뀌어도 `firstSubmittedAt`을 이어받고, 교사 조회 요약에도 실음. 이 반영 전 제출본을 다시 내면 그때의 `submittedAt`을 넘겨받아 '이 시각 이전 첫 제출'(상한)로만 쓸 수 있음. 검증: Tier 1~1.5(단위 72), 파일 지정 E2E 6개 스펙 46(`classroom-api` 새 검사는 고친 뒤 단독 10 통과), 전체 E2E 미실행(사용자 결정), Codex 리뷰는 29분 넘게 진행 중이라 사용자 결정으로 기다리지 않음(Gemini 지적 없음), 운영 반영 확인.
- **코드 정리 후보 3건** (10/28): 나무 미션의 나무가 없을 때 없는 버튼 대신 선생님께 알리도록 안내하고, `gradeKey` 주석을 앱이 더는 읽지 않는 현재 동작에 맞추고, `check-cloud-flow.mjs` 거부 문구가 선별 E2E(`npm run test:e2e:scope`)를 권하게 함. `check-cloud-flow.mjs`는 선별 대상에 없어 로컬 선별 실행이 전체 E2E로 분류되므로 파일을 지정해 검증함. 검증: Tier 1~1.5(단위 70), 파일 지정 E2E 14개 스펙 95 통과, 전체 E2E 미실행.
- **#90 질문 대기·다른 계정 초안** (10/27): `코드 멈추기`로 끝난 질문 줄은 대답 칸이 남아도 15초 한도에서 빼지 않고([개발 안내 §4.1](DEVELOPMENT.md#41-entryjs-4023-실습-환경)), 새로고침 때 다른 계정 Q&A 초안을 지움. 검증: Tier 1~1.5, 재현 포함 파일 지정 E2E 6개 스펙 통과(2개는 단독 재실행), 전체 E2E 미실행.
- **#89 Q&A 초안 로그아웃 정리·질문 대기 시간** (10/27): 로그아웃·계정 전환 때 이 탭의 모든 반 Q&A 초안을 지우고, 어느 오브젝트·시작 방식의 질문이든 대답 대기 시간을 15초 실행 한도에 세지 않음([PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초)). 재현 E2E 3개를 더함(고치기 전 실패 확인). 검증: Tier 1~1.5, 파일 지정 E2E 72·45 통과(`guest-login` 1 기존 실패), 로컬 전체 E2E(아래 남은 한계), 운영 반영 확인.
- **#88 엔트리 변수 직접 만들기** (10/26): 세 엔트리 수업의 ‘속성’ 탭에서 학생이 변수를 10개까지 만들어 저장·복원·교사 열람·채점에 쓸 수 있게 함. 수업 변수 A·B·클릭 수는 지우거나 이름을 바꿀 수 없고, 공유·실시간 변수와 슬라이드는 숨김. 학생 변수가 없는 작품의 키·채점은 그대로([PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초), [개발 안내 §4.1](DEVELOPMENT.md#41-entryjs-4023-실습-환경)). 학생이 변수를 쓰기 시작한 뒤 이전 버전으로 되돌리면 그 작품을 읽지 못하므로(원문은 보존) 문제는 수정 반영으로 고침. 검증: 단위 70, 파일 지정 E2E 127·68 통과, 서브에이전트 코드 검토·화면 체험, 운영 반영 확인, 전체 E2E 미실행.

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 `main` 전체 성공은 10/18 `7264de7`(run 39063459497)입니다. 마지막 실행은 10/27 로컬(#89 브랜치, 444 통과·2 실패·13 건너뜀)이고 실패 2개는 아래 순서도 검사입니다. Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **CI·로컬 검사 불안정:** `main` CI의 10초 대기 검사가 재실행으로 통과한 일이 두 번 있었습니다(10/19 `programming-classroom`, 10/21 `conditionals`의 `마지막 말`). 로컬에서는 `programming-classroom`의 `entry-assets` 검사(새로 켠 서버의 첫 실행)·`flowchart-auto-completion`(#67)·`review-flowchart`의 빈 기호 검사가 실패했다가 단독 재실행에서 통과합니다(원인 미확정, 반복되면 대기 시간 기준 점검).
- **의존성:** 10/21 `npm audit` 24건은 운영 화면 경로가 아닌 개발 도구이고, `@grpc/grpc-js` 권고(GHSA-m9gg-hp2v-232j)는 서버 `firebase-admin`만 Firestore를 써서 해당하지 않습니다.
- **무료 한도:** 10/21 실제 두 반(엔트리 수업)은 읽기 약 3만·쓰기 약 1.4만이었고, 시계 폭주를 빼도 저장·채점이 반당 쓰기 약 1천 회입니다. 하루 4반(반 정원 기준)×45분의 정기 읽기는 수업 화면 기준 측정 환산 약 2.9만 회(과금 실측 아님, 10/24부터 대시보드 30초 조회도 같은 2회)이고, 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 안을 보장하지 않습니다.
- **수업 누적:** 대시보드 응답에 수업마다 엔트리 작품 원문이 담겨 프로그래밍 수업이 수십 개면 응답이 수 MB가 될 수 있으니, 그때 진도 판정 필드만 보내도록 줄입니다.
