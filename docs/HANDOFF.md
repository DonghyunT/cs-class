# 이어갈 작업

갱신: 2026-10-29(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

- **실제 학생 계정:** 등록 현황과 입장 방식(10/21부터 반 공통 첫 입장 코드)은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있습니다. 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.
- **진행 중 브랜치(원격):** `feat/festival-character-v7`(축제 캐릭터 초안 보존, 게임 미적용). 포트폴리오 채점은 0단계가 #93으로 병합돼 브랜치를 지웠고, 1단계는 main에서 새로 시작합니다([계획](plans/assessment-portfolio.md)).
- **엔트리 파일 Cloudflare 분리 검토:** [자가검증·인계 보고서](reference/2026-10-29-entry-assets-cloudflare-handoff.md). 로컬 대조 실험 3건 통과, 이전 구현·배포는 미착수입니다. 후속 작업 전 캐시 변경의 반영 상태와 보고서의 미검증 항목을 확인합니다.

## 최근 반영

- **Run the Entry asset proxy only for CORS preflights** (10/29): Vercel 함수 호출 76%·Active CPU 78%의 주원인으로 본 `src/proxy.ts`가 `/entryjs/` 모든 파일 요청마다 함수로 돌던 것을, `access-control-request-method` 헤더가 있는 사전 요청에만 돌게 함. 검증: typecheck·lint·build, 빈 캐시 수업 1회+2분에 프록시 실행 92→2회(소리 정상), 단위 21, 파일 지정 E2E 24 통과·1 실패(단독 3회 통과), 전체 E2E 미실행. 효과는 공개 뒤 확인.
- **엔트리 정적 파일 브라우저 캐시** (10/29): Vercel CDN 요청 한도의 75%가 쓰였고 6시간 표본의 85%가 `/entryjs/` 정적 파일이라, `next.config.ts`가 `public/entryjs/vendor/`·`sprites/`에 하루 브라우저 캐시(`max-age=86400`)를 붙임([개발 안내 §4.1](DEVELOPMENT.md#41-entryjs-4023-실습-환경)의 지연 전제). 로컬에서 작업실 재진입 요청 70→2건. 검증: Tier 1~1.5(단위 21), 파일 지정 E2E `programming-classroom` 16(1개는 20초 대기 검사가 단독 재실행에서 통과)·`lesson-smoke` 6 통과, 로컬 `build`, 전체 E2E 미실행, 운영 응답 헤더·한도 추이 확인은 병합 뒤.
- **Show the quiz button as primary only after the last concept is checked** (10/29): 마지막 개념의 `퀴즈로 이동`이 정답 확인 전부터 파란 주 버튼이라 학생이 확인 없이 넘어가던 문제를 고쳐, `다음 개념`처럼 맞힌 뒤에만 주 버튼이 됨(공통 개념 화면·프로그래밍 기초 개념 화면). 검증: typecheck·lint, 파일 지정 E2E 4개 스펙 16 통과, 화면 확인, 전체 E2E 미실행.
- **#93 첫 제출 시각 남기기** (10/28, [포트폴리오 계획](plans/assessment-portfolio.md) 0단계): 다시 제출하거나 교사가 승인해 제출본이 바뀌어도 `firstSubmittedAt`을 이어받고, 교사 조회 요약에도 실음. 이 반영 전 제출본을 다시 내면 그때의 `submittedAt`을 넘겨받아 '이 시각 이전 첫 제출'(상한)로만 쓸 수 있음. 검증: Tier 1~1.5(단위 72), 파일 지정 E2E 6개 스펙 46(`classroom-api` 새 검사는 고친 뒤 단독 10 통과), 전체 E2E 미실행(사용자 결정), Codex 리뷰는 29분 넘게 진행 중이라 사용자 결정으로 기다리지 않음(Gemini 지적 없음), 운영 반영 확인.
- **코드 정리 후보 3건** (10/28): 나무 미션의 나무가 없을 때 없는 버튼 대신 선생님께 알리도록 안내하고, `gradeKey` 주석을 앱이 더는 읽지 않는 현재 동작에 맞추고, `check-cloud-flow.mjs` 거부 문구가 선별 E2E(`npm run test:e2e:scope`)를 권하게 함. `check-cloud-flow.mjs`는 선별 대상에 없어 로컬 선별 실행이 전체 E2E로 분류되므로 파일을 지정해 검증함. 검증: Tier 1~1.5(단위 70), 파일 지정 E2E 14개 스펙 95 통과, 전체 E2E 미실행.

- **CI·로컬 검사 불안정:** `main` CI의 10초 대기 검사가 재실행으로 통과한 일이 두 번 있었습니다(10/19 `programming-classroom`, 10/21 `conditionals`의 `마지막 말`). 로컬에서는 `programming-classroom`의 `entry-assets` 검사(새로 켠 서버의 첫 실행)·`flowchart-auto-completion`(#67)·`review-flowchart`의 빈 기호 검사가 실패했다가 단독 재실행에서 통과합니다(원인 미확정, 반복되면 대기 시간 기준 점검).
- **의존성:** 10/21 `npm audit` 24건은 운영 화면 경로가 아닌 개발 도구이고, `@grpc/grpc-js` 권고(GHSA-m9gg-hp2v-232j)는 서버 `firebase-admin`만 Firestore를 써서 해당하지 않습니다.
- **무료 한도:** 10/21 실제 두 반(엔트리 수업)은 읽기 약 3만·쓰기 약 1.4만이었고, 시계 폭주를 빼도 저장·채점이 반당 쓰기 약 1천 회입니다. 하루 4반(반 정원 기준)×45분의 정기 읽기는 수업 화면 기준 측정 환산 약 2.9만 회(과금 실측 아님, 10/24부터 대시보드 30초 조회도 같은 2회)이고, 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 안을 보장하지 않습니다.
