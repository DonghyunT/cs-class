# 이어갈 작업

갱신: 2026-10-19(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **진행 중:** 없음. 로컬 브랜치는 `main`뿐이고, 병합이 끝난 원격 브랜치는 10/19에 모두 지웠습니다.
- **운영:** `main`의 최신 커밋을 배포 게이트(`app` 성공 뒤 공개)로 반영합니다. 앱 코드의 마지막 변경은 `90659bc`(10/19)입니다. 설정 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정** (10/19): 사용자 승인으로 2-1~2-11반 각 1~27번, 297개를 [명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)대로 사전 등록했습니다(2026학년도, 충돌 0, 체험 계정은 건드리지 않음). 사용자는 공통 비밀번호 대신 문서 정책(반별 30분 임시값 → 첫 입장에서 개인 비밀번호)을 골랐고, 임시값은 아직 발급하지 않았습니다. 명부 CSV와 등록 직후 백업은 이 PC의 Git 제외 `private/`에만 있습니다.

## 최근 반영

- **화면 정리와 ‘새로 그리기’ 잠금** (10/19, 직접 push `5051359`·`fc92e68`·`81687d6`·`90659bc`): 오브젝트 추가 창이 공통 대화상자의 `sm:max-w-sm`에 눌려 좁던 것을 최대 1,080px로 넓히고 높이를 고정했습니다. 힌트는 한두 줄로 줄이고 검증 블록 목록은 접었으며, 실험·힌트 카드를 띄웠습니다. 모양 탭의 ‘새로 그리기’가 믿을 수 없는 빈 그림(`_1x1.png`)을 더해 작품을 읽지 못하게 하던 버그는 `painter.newPicture`를 막아 고쳤습니다([DEVELOPMENT §4.1](DEVELOPMENT.md#41-entryjs-4023-실습-환경)). 검증: 선별 E2E 4~11개 파일(반복 수업에 새로 그리기 검사 추가)·전체 E2E 미실행.
- **첫 미션 시작 작품·개념 그림·미션 목록 정렬** (10/19): 새로 여는 조건·반복 수업의 첫 미션이 강아지로 열리던 것을 `emptyWork`가 미션별 시작 작품을 쓰게 고쳤습니다. 개념 화면에 개념마다 작은 그림을 더했고([DESIGN §4.1](DESIGN.md#41-수업-전용-공통-틀-lessonshell)), 미션 카드를 가운데 정렬했으며, 방향키 미션은 앞 미션 작품을 가져오지 않는 독립 작품이 됐습니다([PRD §4.1](PRD.md#41-정규-수업-프로그래밍의-기초)). 검증: 단위(entry-palette 28)·`test:scope` 20·선별 E2E 11개 파일 81개. 한계: 이미 강아지로 저장된 체험 계정 작품은 새 시작 작품으로 바꿀 수 없습니다.
- **#58 조건·반복 수업 엔트리 오브젝트 묶음** (10/19): 두 수업은 공식 엔트리봇으로 시작하고, 분류형 창에서 공식 엔트리 오브젝트 214개(약 16MB)를 골라 쓰며, 모양 탭은 보기 전용입니다. 채점은 시작하기 줄을 가진 한 오브젝트를 보고 나뉘어 있으면 경고 토스트와 검증 실패로 알립니다([PRD §4.1.3](PRD.md#413-조건반복-수업의-강아지-없는-작업실)). 검증: 단위 27·선별 E2E 12파일·PR 머리 전체 E2E 1회. 한계: 엔트리 저작권 가이드 원문(PDF)은 읽지 못해 공개 요약(CC BY-NC 2.0·학교 수업 허용·출처 표시)만 확인했습니다.
- **#56 교사 제출 모달 폭 CI 불안정 해결** (10/19): 모달이 CI에서 860px에 머물던 원인은 공용 팝업의 `duration-100`이 켠 `transition: all`이었습니다. 제출 모달의 전환을 끄고 E2E는 클릭 직후 폭 1220px·전환 없음을 한 번에 확인합니다(임시 진단 #55는 닫음). 검증: 선별 E2E 10파일 64개·PR CI(전체 E2E 미실행).
- **#53·#54 신규 엔트리 수업 2개** (10/18): 「조건에 따라 달라지는 프로그램」([PRD §4.1.1](PRD.md#411-정규-수업-조건에-따라-달라지는-프로그램))과 「반복으로 똑똑하게」([§4.1.2](PRD.md#412-정규-수업-반복으로-똑똑하게))를 공개했습니다. 평균 계산기는 조건 수업 첫 미션으로 옮겼고, 서버 채점기는 조건·반복·붓·클릭 이벤트·모양 바꾸기를 엔트리 의미대로 실행하며 실행 예산을 둡니다. 검증: 단위 23·`test:scope` 20·선별 E2E·전체 E2E 1회. 한계: 운영 실제 계정 화면과 40분 분량은 현장 확인이 필요합니다.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 운영 교사 계정으로 두 수업을 미리보기하고, 실제 수업에서 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 관찰합니다. 나무 키우기가 길면 선택 도전으로 옮길 수 있습니다(`PROGRAMMING_MISSIONS`의 `optional`).
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 터치·화면 읽기·200% 확대·프린터·자연 Cron은 현장에서 확인합니다.
3. **첫 실제 수업 직전 반별 발급:** 그 반만 `--mode issue --class 2-N`으로 발급하고 `issued` 줄이 있는 학생에게만 전달합니다(30분 만료라 미리 몰아 발급하지 않음). 관리자 키가 없는 학교 PC에서는 교사 화면 `학생 현황·계정`의 학생별 `비밀번호 초기화`로 같은 30분 임시값을 발급합니다(사용자가 10/19에 첫 수업은 이 방법으로 정함, 프로젝터 끄고 사용). 명부가 1~27번 일괄이라 실제로 없는 번호의 계정도 있으며, 그 줄은 전달하지 않으면 30분 뒤 만료됩니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).
5. (제안) `scripts/check-docs.mjs`에 HANDOFF 크기·특정 도구 이름 경고 추가(PR 경로).

## 남은 한계와 다음 결정

- **전체 E2E:** 마지막 성공은 2026-10-18 `main`(`7264de7`) GitHub 수동 실행(run 39063459497, 397 통과·14 생략)입니다. 로그인 상한은 긴 실행에서도 넘치지 않았으며, Firebase 5xx·차단 응답 E2E는 없습니다(#44).
- **CI·로컬 검사 불안정:** 10/19 `main` CI의 `app`이 `programming-classroom`의 이름 조립 검사(엔트리 실행 뒤 ‘마지막 말’ 10초 대기)에서 한 번 실패했고, 실패한 단계만 재실행해 통과했습니다. 로컬에서는 새로 켠 서버의 첫 실행에서만 `entry-assets` 검사가 실패하고 켜 둔 서버에서는 통과합니다(수정 전 코드에서도 같음, 원인 미확정). 같은 검사가 반복되면 대기 시간 기준을 점검합니다.
- **운영 DB 정리:** 운영 `csRateLimits`에 10/18 이전 비밀번호별 기록이 남아 있습니다([운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황), 운영 DB 작업 승인 필요).
- **운영 강사 계정:** `instructor` 담당 반을 10/18에 10·11반으로 줄였습니다. 실제 강사에게 전달하기 전에 체험용 공통 비밀번호를 Firebase 콘솔에서 바꿔야 합니다(사용자 작업).
- **의존성:** `main` CI의 `npm ci`가 취약점 26건(보통 4·높음 22)을 보고합니다(10/18, 미점검).
- **무료 한도:** 하루 4반×27명×45분 모형에서 정기 읽기만 약 29,520회입니다(실측 아님). 진입·저장·채점은 별도라 일일 무료 읽기 5만 회 내 4반 운영을 보장하지 않습니다.
- **복습 확인 결정(#46):** 열어 둔 학생 화면은 저장·재접속 전까지 교사 결정을 받지 않고, 그 전에 다시 확인 요청을 보내면 결정 메시지가 새 요청으로 덮입니다.
- **손들기:** 일시 중지 상태입니다([PRD §5.5](PRD.md#설정과-손들기)). 재개 전 오래된 대기 요청 처리 기준·`csHelpRequests` 인덱스·활성 모드 검사를 확인합니다.
- **화면:** 821px 부근에서 수업 헤더 저장 문구가 줄바꿈되면 헤더가 약 100px로 높아집니다(#39 이전부터). 320px에서 엔트리 무대 아래 버튼 우측 여백 일부가 가려지며 실기기 미확인 상태입니다(#43).
