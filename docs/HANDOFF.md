# 이어갈 작업

갱신: 2026-10-24(Asia/Seoul). 현재 상태와 다음 작업만 짧게 둡니다([문서 작성 기준](DEVELOPMENT.md#문서-작성-기준)). 주제별 기준 문서는 [AGENTS](../AGENTS.md)의 색인을 따릅니다.

## 현재 작업 상태

- **운영:** 설정·배포 게이트 상태는 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)을 봅니다.
- **실제 학생 계정:** 등록 현황은 [운영 환경 현황](FIREBASE_SETUP.md#운영-환경-현황)에 있습니다. 방식은 반별 30분 임시값 → 첫 입장 때 개인 비밀번호(사용자 결정)이고, 명부 CSV·등록 직후 백업은 등록에 쓴 PC의 Git 제외 `private/`에만 있습니다.

## 최근 반영

- **#83 색상 다듬기·퀴즈 화면 통일·0% 진도 링** (10/24): 색마다 뜻 하나(파랑 행동·개념, 보라·청록 퀴즈·실습은 수업 화면만, 금색 배지·살펴볼 학생, 자두 일정·할 일)로 대시보드 카드·단계 탭·진도 막대를 다듬음([DESIGN §2.1](DESIGN.md#21-컬러-토큰-color-palette)). 기초 수업 퀴즈를 공용 퀴즈 화면으로, 0% 진도 링은 세 단계 반원. 검증: Tier 1~2·선별 E2E 12개 스펙, 전체 E2E 441 통과·1 실패(main에서도 실패하는 `help-paused`, 따로 고침).
- **#82 강사 안내서 수업 운영판·Entry 작업 중 로그아웃 수정** (10/24): 안내서 PDF를 사이트 안내 2쪽·수업 운영 5쪽(첫 입장·순회·저장/제출·마치기 확인, 필수 활동 100% 만점 기준)으로 개정. Entry 작업실 안에서만 작업해도 10분 뒤 로그아웃되던 문제를 프레임 메시지를 활동으로 세어 고침. 검증: Tier 1·선별 E2E 32 통과, 전체 E2E 441 통과·1 실패(main에서도 실패하는 `help-paused`).
- **#81 도전 미션·다음 행동 포커스·강사 안내서** (10/24): 기초 수업에 `도전 · 거스름돈 계산기`를 넣고 조건 수업 방탈출을 `도전 · 놀이기구 탑승`(그리고)으로 바꿈(방탈출 기록은 ‘이전 수업 기록’). 개념 정답·퀴즈 채점 뒤 초점이 다음 버튼으로 감. 논리 연산자 그림 `+` → `AND`·`OR`. 무대의 A·B·클릭 수 칸을 대답 입력창에 가리지 않게 왼쪽 위로 옮김. 질문 등록 뒤 `질문 쓰기`가 접힘. 강사님 안내서 PDF(`teaching-materials/instructor-guide/`). 검증: Tier 1~2·선별 E2E 16개 스펙 158 통과, 전체 E2E 미실행(공통 화면 파일 변경으로 규칙상 전체 대상).
- **#80 학생 대시보드 가벼운 조회·열린 수업 60개** (10/24): 학생 홈·열린 수업 목록은 30초마다 반 설정만 읽고(2회), 열린 수업 기록 전체는 진입·새로고침·반 설정 변경·조회 실패·30초 지난 창 복귀 때만 읽음. 열린 수업 상한 30→60. 문서 정리(완료 계획 보관 포함). 검증: Tier 1~2·빌드·E2E 12개 스펙(1 실패는 실행 중 파일 수정 탓, 재실행 20 통과), 전체 E2E 미실행.
- **#79 배지 도장·별·희귀 배지, 퀴즈 전체 보기** (10/23): 수업 도장 4개, 1·3·5·10·20 별, 희귀 배지 3종, 다 풀면 퀴즈 전체 표시. 검증: Tier 1~2·빌드·E2E 117 통과, 전체 E2E 미실행.

## 다음에 이어갈 작업

1. **새 수업 현장 확인:** 두 수업의 40분 분량(특히 나무 키우기)과 106블록 팔레트가 과한지 실제 수업에서 봅니다. 길면 사용자와 정해 `PROGRAMMING_MISSIONS`의 `optional`로 옮길 수 있습니다.
2. 실제 학교 PC·학교망·물리 한글 입력기에서 [첫 수업 확인](DEVELOPMENT.md#첫-실제-수업-확인-순서)을 합니다. 운영 실제 로그인·AI·저장/제출, 첫 입장 코드(#70)의 동시 입장, PC별 시계 차이(#71), 터치·화면 읽기·200% 확대·프린터·자연 Cron, 축제 미연시(`/festival-romance.html`, [자료 인수인계](../teaching-materials/festival-romance/HANDOFF.md))는 현장에서 확인합니다.
3. **첫 실제 수업 직전 반별 발급:** 첫 수업에 학생별 초기화·한꺼번에 발급·반 공통 `첫 입장 열기` 중 어느 방법을 쓸지 다시 정합니다([명부 절차](DEVELOPMENT.md#실학생-명부-준비와-반별-발급)). 첫 발급 전에 사용자가 Firebase 콘솔에서 Auth 할당량·남용 방어가 한 반 동시 입장을 막지 않는지 확인합니다.
4. **엔트리 후속(교사 요청):** 속성 탭의 변수 직접 만들기와 수행평가용 `.ent` 업로드 채점을 검토합니다(지금 파서·채점기는 A·B·클릭 수 변수만 압니다).
5. **조건 수업 개념 흐름(교사 요청, 10/21 보류):** 다섯 개념이 완전히 이어질 필요는 없지만, 하나의 흐름 안에서 다음 개념을 짐작할 수 있게 순서·예시를 다듬습니다([테스터 합의](reference/student-tester-consensus-20261022.md#4-최종-합의-다섯-개념의-흐름)). 목차 이름·그림 정리 뒤 수업에서 반응을 보고 정합니다.
6. **`help-paused` E2E 기존 실패(별도 세션에서 수정 중):** `/teacher/students`를 열면 `수업 새로고침`이 활성화되지 않아 실패합니다. 10/24 `main`에서도 재현되며 #78 무렵부터로 보입니다. 앱 버그인지 테스트 전제가 낡았는지 가려 `fix/` PR로 고칩니다.
