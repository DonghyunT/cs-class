## 판단과 작업 경계

- 운영 기준은 하루 최대 4반·평균 27명입니다. 반당 45분을 계산 기준으로 삼고, 60분 조건도 별도로 비교합니다.
- 교사 과제 현황의 반복 전량 조회와 학생 손들기 상태 조회를 함께 줄여야 합니다.
- 숨겨진 탭의 폴링 중단과 손들기 독립 조회는 이미 구현되어 있습니다.
- 사용자 입력이 없어도 교사 모니터링은 계속합니다. 인증 검증·단일 세션·수동 저장 정책은 유지합니다.
- 인증 계정 캐시, 전체 명부 캐시, 요약 문서, 외부 캐시 서비스는 1차 범위에서 제외합니다.
- 운영 DB에서 합성 테스트를 하지 않습니다. 운영 읽기 1,100회의 출처는 아직 미확정입니다.
- 교사 해결 후 학생 화면 반영 지연이 실제로 보고되었습니다. 요청 대기 중 조회는 30초를 유지하며, 절감만을 위해 이 지연을 늘리지 않습니다.
- **측정으로 확인한 추가 경로:** 학생 수업 화면의 이번 수업 안내도 열린 수업 전체 작품을 30초마다 조회했습니다. 같은 30초·포커스 갱신을 유지하되 본인 반 설정·공개 수업만 반환하는 `GET /api/classroom/student/class`로 좁힙니다. 기존 하루 읽기 추정은 이 경로를 누락했으므로 운영 예측의 근거로 재사용하지 않습니다.

- [ ] 에뮬레이터는 운영 인덱스 검증을 대신하지 못합니다. 승인된 원격 반영 단계에서는 인덱스를 먼저 배포하고 준비 완료를 확인한 뒤 앱을 반영하며, 허용된 실제 계정으로 목록 조회 성공을 확인합니다. 운영 합성 시드는 사용하지 않습니다.

학생 27명·45분·수업 화면 유지 조건에서, 주기 변경만으로 교사 과제 현황 약 2,520~2,970회와 학생 손들기 최대 약 3,645회를 줄일 수 있다는 계산입니다. 학생별 요청 대기 시간 비율을 `p`라 하면 학생 손들기 감소량은 대략 `3,645 × (1-p)`입니다. 대기 10%이면 약 3,280회 감소합니다. 초기 조회·타이머 전환·학생 행동·세션 확인·재시도는 별도입니다. 전체 80~85% 감소나 무료 한도 내 운영 학급 수를 보장하지 않습니다.

## 4. 효과가 부족할 때만 추가 검토

1. 학생 대시보드에서 열린 수업 전체 작품의 반복 조회를 완화합니다. 수업 공개·진도 표시 지연의 허용 범위를 먼저 정합니다.
2. 학생 손들기 상태 조회의 매회 반 문서 읽기를 줄일 수 있는지 권한 정책과 함께 검토합니다.
3. 명부의 고정 정보와 활동·계정 상태를 분리합니다. 이후 캐시 적중률·무효화·서버 인스턴스별 차이를 측정합니다.
4. 그래도 필요하면 학급 요약 문서를 검토합니다. 읽기 감소뿐 아니라 추가 쓰기·경합·누락 복구 비용까지 비교합니다.

**원격 반영:** 구현·검증 결과를 먼저 검토하며, 푸시·인덱스 배포·운영 반영은 기존 사용자 승인 범위를 따릅니다. Preview는 명시 요청 시에만 생성합니다.

## 로컬 구현 결과와 운영 목표의 재판정

공개 수업 4개·현재 수업 `programming-13`·학생 27명·담당 반 11개를 동일하게 설정한 demo 개발 서버에서 10분 가상 시간의 실제 API 요청을 전후 비교했습니다. 기준 측정은 기존 UI 4개 파일을 임시 복원해 수행하고 변경본은 즉시 복구했으며, 도움 요청이 없는 조건이므로 서버의 대기 상태 필터 차이는 결과에 영향을 주지 않습니다.

| 정기 조회 | 변경 전 | 변경 후 |
|---|---:|---:|
| 교사 과제 현황 | 20회 × 기본 66읽기 | 10회 × 기본 66읽기 |
| 학생 손들기(1명) | 20회 × 기본 3읽기 | 10회 × 기본 3읽기 |
| 학생 수업 안내(1명) | 20회 × 기본 6읽기 | 20회 × 기본 2읽기 |
| 교사 손들기(요청 없음) | 20회 × 최소 2읽기 | 20회 × 최소 2읽기 |

요청 횟수는 관찰값이며 읽기 수는 코드·응답의 반/학생/공개 수업 수를 대조한 모형입니다. 작품이 없는 개별 문서 읽기, 빈 쿼리, 재시도와 사용량 대시보드 차이를 감안해야 하며 실제 과금 실측이 아닙니다. 단일 학생을 27명으로 환산했으며 개발 모드 초기 중복 요청은 정기 조회와 분리했습니다. 가상 시계의 활동 갱신 횟수는 서버 실제 시계와 어긋나므로 하루 예측에 사용하지 않습니다.

공통 세션을 1인당 30초에 1읽기로 별도 가정하면, 10분의 정기 읽기 모형은 **6,780 → 3,150회(약 54% 감소)**입니다. 하루 4반 × 45분이면 **약 12.2만 → 5.7만 회**이며 초기 진입·저장·채점·손들기 대기·재시도는 추가입니다. 요청 대기 중 학생의 손들기 주기는 30초이므로 실제 절감은 대기 시간 비율에 따라 줄어듭니다.

**하루 4만 회 운영 여유 목표는 아직 충족하지 못했습니다.** 기존 약 4.4만 회 예시는 학생 수업 안내 반복 조회를 누락했으므로 폐기합니다. 1차 코드는 인증·학생 작업·수업 안내의 지연 기준을 유지한 개선입니다. 이후에는 안내 갱신 주기와 학생 손들기 상태 조회의 추가 경량화를 검토하되, 실제 수업 행동량 측정과 허용 지연 결정을 거쳐 운영 학급 수를 판단합니다. 추가 캐시나 인증 정책 변경을 임의로 적용하지 않습니다.

원자료·검사 로그는 Git 제외 `scratch/firestore-read-optimization/`에 있습니다. 초기 공개 수업 없는 샘플은 요청 주기 조사용이며 읽기 절감 근거는 `baseline-released-usage.json`·`optimized-released-usage.json`을 사용합니다. 독립 리뷰의 측정 시드 지적을 반영해 공개 수업과 학생 작품 조회 경로를 포함시켰습니다.
