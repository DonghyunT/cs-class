## 1. 목적과 범위

대시보드·열린 수업에서 수업에 들어오면 학습에 필요한 탐색과 상태를 갖춘 전용 화면을 사용합니다. 중학생이 **지금 배우는 것·현재 위치·첫 행동·결과·다음 행동**을 쉽게 찾고, 실습에 넓은 공간을 쓸 수 있어야 합니다.

사용자가 요청한 것은 공통 수업 틀과 학생친화적인 UI·UX입니다. 이 계획의 추천 기본값은 수업 전체에서 전용 틀 사용, 알고리즘 설계 수업의 대표 적용, 수업 진입 경로로 돌아가기입니다. 세부 너비와 문구는 대표 화면에서 검토합니다.

- 학생의 `/classroom/[id]`에 적용합니다. 개념·퀴즈·실습 모두 같은 틀을 사용합니다.
- 알고리즘 설계에서 검토하고 프로그래밍·추상화·순서도와 기존 검증용 EntryJS·순서 배열 수업까지 공통 틀의 호환성을 확인합니다.
- 현재 답안·작품·진행 계산·자동 저장·검증·제출·교사 확인 요청을 연결합니다. 기존 API·DB·완료 조건을 유지합니다.
- 대시보드·열린 수업·반 일정·교사 관리·공개 프로토타입의 화면 역할은 유지합니다. 공통 인증 표현을 분리하는 경우에는 이 화면들도 회귀 검사에 포함합니다.
- 기존 가독성 계획의8~12차 체험·보조색 확장은 별도 범위입니다. 이번 공통 틀 계획만으로 해당 작업이나 운영 배포를 시작하지 않습니다.

## 2. 학생 입장에서의 기본 흐름

1. 대시보드의 이번 수업 또는 열린 수업의 카드를 선택합니다.
2. 해당 수업의 전용 화면으로 들어옵니다. 실제 저장 기록의 단계와 답안·작품을 불러옵니다.
3. 상단에서 수업 이름과 현재 단계를 확인하고, 본문에서 학습·실습합니다.
4. 결과를 확인하고 직접 다음 개념·문항·단계를 선택합니다. 정답이나 완료 뒤 자동으로 다음 화면으로 넘어가지 않습니다.
5. `수업 나가기`로 진입한 대시보드/열린 수업으로 돌아갑니다. 수업 나가기는 로그아웃이나 작품 초기화와 구분합니다.

나갈 때 실제 미저장 변경이 있으면 기존 저장 보호를 거칩니다. 저장 실패가 생기면 작품을 유지한 채 해결 방법을 안내합니다. 정상 저장 상태에서 매번 확인창을 띄우지 않습니다. 최초 조회 대기·조회 실패만으로 나가기나 로그아웃을 막지 않습니다.

## 3. 화면 구성

아래는 기능의 위치를 설명하는 배치도입니다. 실제 픽셀 시안이나 새 구현 화면은 아닙니다.

```text
┌───────────────────────────────────────────────────────────┐
│ ← 수업 나가기   알고리즘 설계     저장 완료   20102 학생 ▾ │
├───────────────────────────────────────────────────────────┤
│       개념 1/3       퀴즈 0/4       실습 · 진행 중          │
├───────────────────────────────────────────────────────────┤
│ 오늘 할 일 / 현재 활동의 짧은 안내               자세히 ▾ │
│                                                           │
│                   현재 학습 또는 실습                      │
│             그림·입력·결과·필요한 조작                     │
│                                                           │
│        관련 활동 바로 아래의 확인·검증·제출·다음 이동      │
└───────────────────────────────────────────────────────────┘
```

### 수업 상단 바

수업 나가기, 수업 제목, 실제 저장 상태, 학생 메뉴를 둡니다. 대시보드의 상시 좌측 메뉴와 일반 대시보드 상단 바는 수업 화면에서 사용하지 않습니다. 제목·나가기·저장 상태가 본문 위에 중복되지 않도록 정리합니다.

- 수업 제목은 한 번 표시합니다. 긴 제목은 줄바꿈하며 학생 메뉴와 겹치지 않습니다.
- 제목 가까이에 기존 수업의 전체 `시작 전 / 진행 중 / 완료`를 표시하고 단계별 진행과 구분합니다. 선택 복습은 `복습 수업 · 성적에 반영하지 않아요`라는 짧은 안내를 유지합니다. 전체 평균 진행률을 새로 만들지 않습니다.
- 학생 메뉴에는 본인의 학번과 로그아웃을 둡니다. 나가기와 로그아웃을 서로 떨어뜨려 우발적인 종료를 줄입니다.
- `저장 중… / 저장 완료 / 저장 확인 필요` 등 현재 저장 의미를 유지합니다. 색과 아이콘만으로 판단하게 하지 않습니다.
- 상세 진행·수업 설명은 공통 `수업 안내` 펼침 영역에 모읍니다. 중요 오류·현재 수업 변경 알림은 접힌 안내 안에 숨기지 않습니다.
- 상단 바의 고정은 CSS 화면 폭821px 이상·높이800px 초과에서만 사용하고, 단계 탐색과 긴 안내는 일반 문서 흐름에 둡니다. 그보다 낮거나 좁은 창·확대로 가용 크기가 줄어든 화면에서는 상단 고정을 풀어 본문 공간을 확보합니다. 상단 높이는 내용에 맞춰 늘어나게 하며 제목을 자르지 않습니다.

### 단계 탐색

`개념 / 퀴즈 / 실습`의 현재 위치와 실제 진행을 보여 줍니다. 단계는 항상 자유롭게 선택할 수 있고, 이전 단계의 완료 여부로 잠그지 않습니다.

처리 중·단계 이동 중에는 기존 중복 요청 제어를 유지합니다. 자유로운 단계 선택은 완료 순서를 강제하지 않는다는 뜻이며 저장 확인·오류 보호를 생략하는 뜻은 아닙니다.

- 기존 단계별 진행률 계산은 유지합니다. 눈에 보이는 표기는 완료 수나 `진행 중`을 우선하고, 퍼센트는 필요하면 상세 진행에서 확인합니다.
- `1/3개 확인`, `0/4문제 해결`과 같이 무엇을 세는지 알 수 있게 합니다. 이를 점수나 이해도처럼 표현하지 않습니다.
- 선택한 단계는 배경·표시선·텍스트로 구분합니다. 단계 탐색은 실행 버튼 모양과 구별합니다.
- 탭의 방향키·Home/End·Tab 조작, 저장 성공 뒤 단계 변경, 오류 시 이전 단계 유지와 Effect 초점 이동을 보존합니다.
- 선택한 개념/문항/미션은 해당 활동의 본문 가까이 둡니다. 큰 상시 목차 사이드바를 새로 만들지 않습니다.

### 활동 본문

본문은 모든 수업에 같은 큰 카드를 강제하기보다 활동의 읽기와 조작에 맞춥니다. 공통 틀은 공간과 일관된 탐색을 담당하고, 각 활동은 자신의 도구와 결과를 담당합니다.

| 활동 | 추천 배치 | 학생에게 보이는 흐름 |
| --- | --- | --- |
| 개념 | 본문 최대1120px, 한 개념과 짧은 목록 | 설명·예시 → 체험·관찰 → 확인 문항·피드백 |
| 퀴즈 | 본문 최대880px, 한 문항 | 문항 번호·미답변 상태 → 선택·힌트 → 이동·회차 결과 |
| 실습 기본 | 본문 최대1440px, 현재보다 가용 공간 확대 | 과제 → 작업·실행 → 결과·검증·제출 |
| 실습 넓게 보기 | 화면 가용 폭, 좌우16px/좁은 창12px | 같은 작업실·작품을 유지하며 작업 공간만 확장 |

상단 바·단계 탐색의 기준선은 최대1440px로 유지합니다. 개념의 작은 목록과 본문을 합한 폭은1120px, 퀴즈의 번호·문항·아래 이동 영역은880px로 정렬합니다. 2026-10-06 후속 요청으로 개념은 프로그래밍13차시와 같은 왼쪽 목록/오른쪽 본문을 공통 CSS Module로 사용하며 아래 이동은 본문과 정렬합니다. 760px 이하에서는 목록을 위로 옮깁니다. 세부 시각 기준은 [DESIGN의 개념 화면](../DESIGN.md#확정된-공통-기준)을 따릅니다. 단계별로 읽기 폭이 다른 이유가 분명하게 보이도록 합니다.

기본 실습과 넓게 보기 모두 좌측 대시보드 메뉴가 없습니다. 처음은 기본 실습 폭이며 학생이 확장을 선택합니다. 수동 폭은 같은 수업의 단계/미션/창 크기 변경에서 유지하고, 새로고침·다른 수업은 기본 폭입니다. `넓게 보기`는 브라우저 전체 화면 전환을 요구하지 않습니다.

## 4. 학생친화적인 조작 원칙

- 화면에 들어온 학생이 현재 활동과 첫 행동을 본문에서 찾을 수 있어야 합니다. 목표 문장은 기존 수업 설명·활동 제목·미션 안내를 활용하고 장문의 소개를 반복하지 않습니다.
- 주요 실행/확인 조작은 파랑으로 강조합니다. 선택은 선택 상태, 탐색은 묶인 탭/목록, 초기화·기록 도구는 작고 조용한 보조 조작으로 표현합니다.
- 실행 결과는 실행한 활동 가까이에 표시합니다. 공통 상단에는 모든 활동의 결과를 모으지 않습니다.
- 초기화는 범위를 문구로 알립니다. 개념 체험 초기화가 답안·완료를 지우지 않고, 새 레시피가 해당 실습의 현재 명령을 비우는 기존 동작을 유지합니다.
- 오류는 무엇이 실패했고 무엇을 다시 하면 되는지 안내합니다. 저장 실패·AI 연결 실패·실습 조건 미충족을 서로 다른 상태로 표시합니다.
- 제출과 저장은 구분합니다. `저장 완료`를 수업 완료나 제출 완료로 오해하지 않게 하고, 이미 제출한 작품을 수정할 때 이전 제출 유지와 재검증 필요를 활동 옆에서 안내합니다.
- 기존 파랑/살구·Pretendard·읽기 글자18/16px·보조 글자14px 이상·조작 영역44px 이상을 기준으로 삼습니다. 글자를 줄여 버튼을 억지로 한 줄에 넣지 않습니다.
- 좁은 창에서는 요소를 줄바꿈하고 본문을 세로로 읽게 합니다. 한 문항·한 개념의 실제 설명은 생략하지 않습니다.
- 본문 바로가기의 `#main-content`와 화면마다 하나의main, 보이는 초점, 메뉴 Escape·초점 복귀, 단계/응답 뒤 Effect 초점을 유지합니다. 갑작스러운 자동 스크롤과 새 동작 없는 초점 이동을 만들지 않습니다.
- 페이지 기본 스크롤을 유지합니다. 필요한 대화 기록·EntryJS 작업실 내부 스크롤은 별도로 두고, 모든 학습을 고정 높이 안에 가두지 않습니다.

## 5. 수업별 유지할 경험

### 알고리즘 설계 — 첫 적용 수업

큰 조리대와 대화의 약2:1 배분, Enter/Shift+Enter/IME, 시간순 말풍선과 읽던 위치, 전체 폭 실행 기록, 대화 옆 새 레시피를 유지합니다. `1280×720`에서 첫 입력·실행 버튼·조리대 안내가 함께 보이는 조건도 유지합니다.

사이드바와 중복 상단이 사라져 얻은 공간을 실제 재료·대화에 배분합니다. 기존 낮은 창의 그림 높이 제한은 새 상단을 실측한 뒤 조정합니다. 안내 잘림을 그림 축소로 다시 해결하지 않습니다. 첫 적용은 개념·퀴즈·실습 전체와 나가기/복원까지 확인합니다.

### 추상화·순서도

현재 색상 작업 영역·기호·캔버스·실행 강조와 실제 AI/교사 요청 상태를 보존합니다. 공통 틀 전환으로 새 단원 체험이나 AI 정책을 추가하지 않습니다.

### 프로그래밍·EntryJS

공통 틀과 폭 전환은 동일한 iframe을 유지합니다. 실행·입력 중 폭 변경이 작업실을 재생성하지 않게 합니다. 미션별 작품·입력 확정·실행/중지 뒤 무대 복원·검증/제출·재접속 계약을 유지합니다. 순서 배열 수업은 읽기 중심의 기본 폭을 사용하며 불필요한 넓게 보기 조작을 추가하지 않습니다.

## 6. 기술 구조와 상태의 소유

현재 `Classroom`은 `AppShell` 안에 `LessonWorkspace`를 표시합니다. `AppShell`은 계정 확인·사이드바·일반 상단·로그아웃을 함께 담당합니다. 학습 컨트롤러와 저장 전 이동 보호는 이미 수업 화면 밖의 루트 Provider에 연결되어 있습니다.

추천 구조는 다음과 같습니다.

```text
공통 SessionProvider / NavigationProvider
├─ 대시보드·열린 수업·반 일정 → 기존 AppShell
└─ /classroom/[id] → Classroom → 공통 접속 확인 → LessonWorkspace
   └─ 기존 WorkEditor / useWork → LessonShell → 현재 단계의 활동
```

- `LessonShell`과 옆 CSS Module은 학생 기능 폴더에 둡니다. 담당은 공통 상단·단계 탐색·본문 폭·계정/나가기의 배치입니다.
- `useWork`의 인스턴스와 초안 소유권은 기존 `WorkEditor`에 유지합니다. 저장 상태·진행·단계 전환 조작을 화면 틀에 전달하며, 상단에서 별도 작품 조회/저장 컨트롤러를 만들지 않습니다.
- `Classroom`의 사용자·수업별 수동 폭 상태를 재사용합니다. 넓게 보기/단계 변경은 CSS 배치와 기존 상태만 갱신하고 동일 수업의 편집기를 다른 key로 재생성하지 않습니다.
- 현재 `AppShell`의 초기 접속·설정 오류·입장 필요·비밀번호 변경 필요 표현은 두 틀에서 재사용하는 작은 공통 부품으로 분리합니다. 역할별 유효 조건과 오류/재시도를 그대로 유지하고 학생/교사 정책을 복사해 따로 관리하지 않습니다.
- 서버의 수업 접근 검사와 현재401/403 처리, 루트 Provider의 이력/클릭/종료 저장 보호를 유지합니다. 전용 화면의 표시만으로 인증을 판단하지 않습니다.
- 진입 링크에는 `from=dashboard` 또는 `from=lessons`라는 제한된 출처 값을 사용하고 내부 두 경로로만 매핑합니다. 직접 링크·알 수 없는 값의 기본 복귀는 `/student/lessons`입니다. 임의 외부 URL이나 `history.back()`을 나가기 대상으로 사용하지 않습니다. 새로고침과 수업 변경 알림을 통한 이동에서도 이 출처를 유지합니다.
- 계정 메뉴의 로그아웃도 기존 `beforeLeave`를 거칩니다. 로딩/오류 화면에도 복귀 경로와 실제 가능한 접속 재시도를 제공합니다.
- Next.js의 라우트 레이아웃·상태 재생성 경계와 계정 메뉴의 설치 버전 문서는 구현 전 로컬 문서/Context7로 확인합니다. 기존 공통 부품·React·CSS를 우선하고 새 의존성·범용 수업 플러그인·중복 상태 저장소는 만들지 않습니다.

## 7. 적용 순서와 완료 조건

각 단계는 아래 조건을 확인하며 진행했습니다. 1~4단계의 구현·대상 검사와5단계의 자동 통합 검증·로컬 기록 복원을 마쳤습니다. 실제200% 확대와 대표 화면 휴먼 리뷰는 자동 검증과 별도로 남깁니다.

| 순서 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1. 배치 확정 | 기존 기본/확대·낮은 창과 비교해 개념/퀴즈/실습의 전용 틀 배치를 검토 | 제목·탐색·저장·첫 행동의 위치가 명료하며 상단 중복·상시 사이드바가 없음 |
| 2. 공통 틀 연결 | 최소 LessonShell, 공통 접속 표현, 진입 출처와 나가기 연결 | 두 진입 경로·직접 링크·조회 실패/대기·로그아웃·미저장 변경 보호가 작동 |
| 3. 알고리즘 설계 적용 | 개념·퀴즈·큰 조리대/대화·기록을 새 틀에 배치 | 기존 실제 조작/저장/복원과 낮은 창 조건을 유지하고 수정 화면의 휴먼 리뷰를 받음 |
| 4. 다른 수업 호환 | 프로그래밍·추상화·순서도·검증용 EntryJS/순서 배열 연결 | 수업별 기능·미션/단계 왕복·동일 iframe·작품·실행·입력·초점 보존 |
| 5. 통합과 인계 | 빌드 앱·넓은 영향 검사·실제 확대·문서 갱신 | 필수 검사와 대표 화면 검토, 남은 한계/복구 방법을 기록하고 로컬 구현을 보존 |

3번에서 학생의 첫 행동이나 실습 공간에 문제가 있으면 해당 배치와 같은 조건을 수정·재검증한 뒤4번으로 진행합니다. 화면 틀이 정리되기 전에 단원 콘텐츠의 후속 확장을 섞지 않습니다. 도입 중 문제는 공통 틀 연결/CSS 변경을 되돌려 복구할 수 있고 DB 이식은 필요하지 않습니다.

- UI를 확인할 때 기존 로컬 검토 계정의 기록을 보존하고 demo 합성 계정을 분리합니다. 운영 DB·실학생 자료를 검사에 쓰지 않습니다.
- 실제200%와 OS 한글 입력기, 실제 학생 관찰은 자동 이벤트/좁은 창 검사와 구분합니다. 이전 도구의 로컬 접근 차단은 해결됐다고 가정하지 않으며 현재 가능한 검증 경로를 확인합니다. 필수 실제 검사가 미확인이면 인계 완료로 처리하지 않습니다.
- 현재 로컬 AI는 합성 fixture입니다. 공통 틀의 UX 검사와 실제 AI 호출/품질 확인을 분리합니다.

## 9. 학생친화성의 수락 질문

대표 화면의 휴먼 리뷰에서는 학생에게 추가 설명을 주기 전에 다음을 찾을 수 있는지 확인합니다.

1. 어떤 수업이고 지금 어느 단계인가요?
2. 지금 무엇을 배우거나 만들어야 하나요?
3. 처음 할 행동은 무엇인가요?
4. 방금 실행/선택한 결과는 어디에 있나요?
5. 저장과 제출은 어떻게 다른가요? 오류가 나면 무엇을 하면 되나요?
6. 하던 것을 유지하며 다른 단계로 가거나 수업에서 나오려면 어디를 누르나요?

교사의 화면 검토와 실제 중학생의 사용 관찰을 구분합니다. 자동 검사·교사 리뷰만으로 학습 효과나 학생 혼란 감소를 입증했다고 기록하지 않습니다. 단계별 첫 행동을 찾지 못하거나 나가기/초기화/로그아웃을 혼동하면 문구·배치·강조를 먼저 수정합니다.

## 10. 현재 구현과 다음 검토

사용자가 승인한 **수업 전체의 전용 틀, 간결한 상단, 자유로운3단계 탐색, 활동별 읽기/작업 폭, 기존 저장 보호**를 구현했습니다. 알고리즘 설계의 대표 적용을 먼저 검증하고 모든 학생 수업으로 확대했습니다. 화면 표현은 `LessonShell`, 접속 상태 표현은 `SessionAccess`가 맡으며 학습 상태·저장 컨트롤러는 기존 `WorkEditor` 한 곳에 유지합니다. 초기 조회부터 같은 상단을 유지해 나가기·학생 메뉴의 초점이 사라지지 않습니다.

다음 검토는 구현 화면의 첫 행동·탐색·실습 공간입니다. 실제200% 확대·OS 한글 입력기·실제 학생 관찰은 자동 검사와 별도로 확인합니다. 기존8~12차 확장과 운영 배포는 이번 구현 범위 밖입니다.

이전7차의 자동 검증은 `7600b82` 및 기존 HANDOFF의 기록이며, 이번 구현 성공 근거로 바꾸지 않습니다.

## 11. 승인 후 실행 단위와 검증

기존 목적 브랜치에서 한 실행자가 순서대로 구현합니다. 마지막에 독립 코드 검토를 한 번 수행합니다. 별도 의존성·상태 저장소는 추가하지 않습니다.

### Task 1: 접속·복귀 연결과 알고리즘 대표 적용

- 인터페이스: `SessionAccess({ teacher?: boolean, children: ReactNode })`는 기존 접속 상태 표현만 공유합니다. `Classroom` → `LessonWorkspace`는 검증된 `returnOrigin: "dashboard" | "lessons"`를 전달합니다. `LessonShell`은 제목·저장 상태·진행·단계 탐색을 표현하며 `useWork`를 소유하지 않습니다.
- 먼저 `tests/lesson-shell.spec.ts`에서 사이드바 없는 수업, 제한된 복귀 경로, 조회 실패 시 나가기, 저장 실패 시 입력 보존, 학생 메뉴 Escape·로그아웃 보호를 작성하고 기존 화면에서 실패를 확인합니다.
- `review-sandwich`만 명시적으로 대표 적용합니다. 다른 수업은 이 검증을 통과한 뒤 적용합니다.
- 검증: `npm run typecheck`, `npm run test:e2e:running -- tests/lesson-shell.spec.ts`. 저장 보호·접속 경계와 실제 알고리즘 화면을 함께 확인합니다.

### Task 2: 모든 수업 호환과 작업실 연속성

- Task 1의 공통 틀을 모든 학생 수업에 적용하고 임시 대표 적용 조건을 제거합니다. 대시보드·열린 수업의 링크에 정해진 출처만 추가합니다.
- 실제 EntryJS·프로그래밍의 동일 iframe/작품, 폭·단계·미션 이동, 추상화·순서도·순서 배열, 키보드 탐색을 기존 관련 E2E로 확인합니다. 이전 메뉴/복귀 문구를 참조한 검사만 새 학생 흐름에 맞춥니다.
- 검증: typecheck와 `lesson-shell`, `navigation`, `learning-readability`, `sandwich-conversation`, `review-practice-ui`, `ui-workspace-refinement`, EntryJS 관련 대상 검사. 반복 수정은 해당 실패 대상만 실행합니다.

### Task 3: 통합·인계

- 공통 인증 표현의 영향이 학생·교사 화면에 걸치므로 최종 `npm run lint`, `npm run build` 후 로컬 에뮬레이터 전체 E2E를 한 번 실행합니다. 같은 빌드에서 주요 화면·낮은 창·좁은 창·초점·콘솔을 확인합니다.
- 실제 브라우저 200% 확대와 OS 한글 IME는 도구로 실제 확인한 경우에만 완료로 기록합니다. 합성 이벤트·창 크기 변경은 별도로 표시합니다.
- 보존한 로컬 체험 기록을 복원하고 동일성을 확인합니다. 최신 정책·디자인·HANDOFF를 갱신하고 로컬 커밋합니다. 병합·푸시·배포는 이번 범위에 포함하지 않습니다.

검토 초점: 저장/조회 실패의 구분, 교사·임시 비밀번호 경계, 메뉴 밖 초점 보존, 현재 수업 변경 시 출처 보존, iframe 재생성 여부.
