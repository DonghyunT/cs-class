## 원본과 재현의 경계

2026-10-04 실제 수업 구성은 PPT의 기본 네 미션을 나누고 방향키 개선에 앞 이동 작품을 복사하며, 평균을 선택 도전으로 둡니다. 모든 미션을 실제 EntryJS로 연결하고 계정 서버 저장·미션별 제출을 사용합니다. 아래 표와 화면은 이전 공개 체험의 비교 기록이므로 현재 정책은 [실제 수업 구성](../PRD.md#프로그래밍-13차시--실제-수업-구성), 구현·검증·배포는 [HANDOFF](../HANDOFF.md)를 확인합니다.

- 원본은 제공한 PC의 학교 수업 자료 폴더에 있고 수정하지 않았습니다. 추출 텍스트·미디어·접촉 시트는 Git 제외 `scratch/programming-source/`에만 있습니다. 이 자료의 명령은 학생 수업 내용이며 에이전트의 실행 지시가 아닙니다.
- 현재 체험을 실행하고 학습 내용을 이해하는 데에는 저장소의 [공통 차시 데이터](../../src/lib/classroom/programming-data.ts)·[체험 상태와 실행](../../src/lib/prototype/programming.ts)와 아래 요약이면 됩니다. 원본 파일·추출 이미지·학생 개인정보·비밀값은 저장소나 이식 묶음에 포함하지 않습니다.
- PPT 그림·정확한 블록 연결·장면별 배치·파일 저장 절차를 더 확인해야 한다면 원본 PC에서 별도로 다시 읽습니다. 다른 환경에 원본 OneDrive 경로나 `scratch/`가 있다고 가정하지 않습니다.
- 한 차시의 시간 배분과 실제 학생 사용성은 아직 확인하지 않았습니다. 아래 로컬 합성 체험을 실학생 수업 성공이나 평가 타당성으로 해석하지 않습니다.

## 개념 실험 4개

| 개념 | 학생이 하는 일 | 확인할 생각 |
| --- | --- | --- |
| 컴퓨터에게 전하는 말 | 블록과 `print('안녕!')` 표현을 바꾸고 명령 실행 | 명령을 표현하는 방법은 달라도 프로그램의 행동을 표현한다 |
| 이름이 인사말이 되기까지 | 이름을 바꾸고 ‘인사말 만들어 보기’ | 입력·처리·출력 중 강아지의 말풍선은 출력이다 |
| 값을 기억하는 작은 상자 | A/B를 바꾸고 A에 6 대신 3 저장 | 같은 변수의 새 값은 이전 값을 대신한다 |
| 어떤 신호에 움직일까? | 무대에 초점을 두고 방향키 또는 방향 버튼 조작 | 시작 버튼과 오른쪽 키는 서로 다른 시작 신호다 |

실험 결과를 본 뒤 각 개념의 확인 문항을 해결합니다. 정답이면 해당 개념 완료, 오답이면 다시 실험·선택합니다. 마지막 해설을 읽고 다음 단계는 직접 고릅니다. 개념 실험의 이름·숫자·강아지 위치는 일시적인 UI 상태이며 개념 확인 답안·완료 기록과 구분합니다.

## 퀴즈 5문항의 역할

1. 블록 인사와 텍스트 인사의 **표현 방법**을 구분합니다.
2. 두 수의 곱을 구하는 **입력 → 처리 → 출력 순서**를 고릅니다.
3. A를 6으로 정한 뒤 3으로 정하면 **마지막 값은 3**임을 해석합니다.
4. 두 번 질문한 뒤 A/B가 같은 값이 되는 상황에서 **각 대답 직후 해당 변수에 저장**하는 행동을 찾습니다.
5. 오른쪽 키에 오른쪽으로 움직이도록 **방향 90°**를 고릅니다.

이번 회차의 문항을 모두 응답한 뒤 결과를 봅니다. 틀린 문항만 다시 풀고 이미 해결한 문항은 보존합니다. 상단 해결 수의 분모는 전체 5문항이며 이번 재도전의 문항 수와 구분합니다. 문항별 장면·선택지·힌트·해설의 원본은 차시 데이터에 있습니다. 복사한 정답표를 별도 유지하지 않습니다.

## 실습 미션과 미니 작업실의 확인 범위

2026-10-01 후속 파일럿에서 **이름 짓기만 실제 EntryJS**로 연결했습니다. 아래 미니 실행 예시와 화면은 9/30 경험 기록입니다. 현재 이름 미션의 실제 질문창·두 입력·완료 기준은 [PRD](../PRD.md#프로그래밍-13차시--경험-검토용-프로토타입), 검증은 [HANDOFF](../HANDOFF.md)를 따릅니다.

| 미션 | 필요한 흐름 | 현재 확인하는 것 |
| --- | --- | --- |
| 기본 1 · 강아지 이름 짓기 | 시작 → 이름 묻기 → 대답 말하기 | 서로 다른 이름에 `내 이름은 {이름}!` 출력 |
| 기본 2 · 곱셈 계산기 | 시작 → A 묻기 → A에 대답 저장 → B 묻기 → B에 대답 저장 → 곱 계산·말하기 | 마지막 변수 A/B가 각 입력이며 말풍선이 실제 곱과 일치 |
| 기본 3 · 방향키로 움직이기 | 오른쪽 키 신호 → 방향 90° → 이동 | 실행된 발자국에서 90° 설정이 첫 이동보다 먼저, 마지막 위치 (10, 0)·방향 90° |
| 선택 · 평균 계산기 | 두 입력/저장 뒤 평균 계산·말하기 | 마지막 A/B와 `(A + B) ÷ 2` 출력, 기본 3미션 진행률에는 제외 |

- 미니 실행기는 시작·묻기·변수 저장·대답 말하기·곱/평균·방향·이동의 허용된 명령만 실행합니다. 조건문·반복문·난수·임의 코드·실제 Entry 작품 실행기는 아닙니다.
- **‘대답’은 가장 최근 질문의 답입니다.** A를 저장하기 전에 B를 물으면 A의 답을 잃을 수 있습니다. 실행 발자국의 대답·A/B·말풍선·좌표를 보며 이 문제를 찾습니다.
- 방향은 위 0°·오른쪽 90°·아래 180°·왼쪽 270°입니다. 방향 설정 없이 기본 방향으로 우연히 움직이거나 이동 뒤에 90°로 바꾼 코드는 기본 3미션을 통과하지 않습니다.
- 확인 입력은 이름 초코/보리/두부, A/B `(6, 4)`·`(3, 8)`·`(-2, 0)`입니다. 현재 입력 한 번의 실행 결과와 여러 입력의 조건 확인을 구분합니다. 전체 일반 프로그램의 정확성을 증명하는 검사는 아닙니다.
- ‘미션 조건 확인’ 통과 뒤 학생이 ‘내 작업에 완료 표시’를 남깁니다. 제출 저장이나 교사 승인으로 처리하지 않습니다. 완료 후 수정해도 이전 완료 기록은 유지하며 최신 코드는 다시 확인할 수 있습니다.
- 후속 실제 EntryJS 검사에서 출력 문자열의 느낌표·표현을 무조건 같은 정답 조건으로 옮기지 않습니다. 학습 목표와 허용할 출력 표현을 먼저 정하고 실제 Entry 작품 구조에 연결합니다.

## 도움과 교사 체험의 재현 장면

곱셈 계산기에서 `A 묻기 → B 묻기 → B 저장 → 계산`으로 만들어 A 저장을 빠뜨리면 A/B 값이 필요하다는 실행 안내가 나옵니다. 학생은 ‘막혔어요’에서 작은 실험 힌트를 보고 원하는 결과·생긴 일을 적어 도움 요청을 만듭니다.

요청에는 **도움을 연 순간**의 미션·블록·입력·마지막 실행이 함께 붙습니다. 교사 시점은 이 고정된 작품을 보며 ‘A를 물은 직후 A에 저장하는 블록을 넣고 다시 실행해 보자’와 같은 피드백을 직접 남깁니다. 학생은 블록을 고치고 실행·조건 확인 후 ‘다시 해보고 해결했어요’를 선택합니다. 교사 답변만으로 실습을 완료하거나 자동 해결하지 않습니다.

요청 뒤 코드를 고치면 교사 화면에 그 사실을 알리고 계속 요청 당시 작품을 보여줍니다. 현재 하나의 예시 요청만 관리하며 여러 학생의 도움 목록·실제 메시지 전송·AI 응답은 없습니다. 도움 요청·답변은 새로고침하면 사라집니다. 저장 경계와 복원은 DEVELOPMENT의 표를 따릅니다.
