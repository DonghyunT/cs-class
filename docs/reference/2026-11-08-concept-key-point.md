# 개념 화면 핵심 한 줄·벽돌 깨기 직접 눌러 보기 설계

작성: 2026-11-08(Asia/Seoul). 상태: 승인됨(11/8). 대상 브랜치: `feat/brick-breaker`.

## 왜 하는가

수업에 집중하지 못한 학생이 개념 화면을 처음 열면 눈이 가운데 그림으로 먼저 간다. 핵심 설명은 그 위의 흐린 줄글이라 건너뛴다. 벽돌 깨기는 개념 뒤에 블록 조립 문제가 있어 이런 학생이 특히 당황한다.

성공 기준: 수업을 놓친 학생이 **개념 화면만 보고** 그 개념의 확인 문제를 풀 수 있다.

## 목표와 비목표

- 목표: 모든 수업의 개념 화면에서 핵심을 굵은 한 줄로 그림 바로 위에 둔다. 벽돌 깨기 개념 4개에는 잠깐 움직여 보는 그림을 넣는다.
- 비목표: 수업의 흐름, 개념 수, 확인 문제, 퀴즈 내용, 저장 방식은 바꾸지 않는다. 새 패키지는 넣지 않는다.
- 하면 실패인 것: 난이도·학습량 증가, 기존 설명에만 있던 규칙이 화면에서 사라지는 것, 체험이 학생 기록을 바꾸는 것.

## 사용자가 정한 것

- 시안 A(핵심 한 줄)를 모든 수업에, 시안 B(직접 눌러 보기)를 벽돌 깨기에 적용한다.
- 기존 흐름과 내용을 살리고 제공 방식만 바꾼다.

## 화면 구성 (`LessonConceptPanel`)

제목 → **핵심 한 줄(굵고 진한 글자)** → 그림 또는 체험 → **기존 설명 전문(보통 진한 글자, 항상 보임)** → 예시 → 확인 문제. 벽돌 깨기만 설명을 한두 문장으로 줄이고 예시를 뺀다(아래 '벽돌 깨기 체험').

- 기존 설명은 줄이거나 접지 않고 위치만 그림 아래로 옮긴다. `또는`, `이상`, 바깥쪽 각도처럼 퀴즈가 쓰는 규칙이 설명에만 있고(`tests/lesson-feedback.test.ts`가 일부를 고정), 접힌 내용은 이 학생이 열어 보지 않기 때문이다.
- `Concept`에 선택 필드 `keyPoint?: string`을 더한다. 있으면 핵심 줄은 `keyPoint`, 설명은 그림 아래에 전문으로 둔다. 없으면 `explanation`이 이미 짧은 것이므로 핵심 줄로 올리고 두 번 보이지 않는다.
- `explanation`은 정답 피드백(`learning.ts`)에도 쓰이므로 내용을 바꾸지 않는다.
- 함수·복습 수업의 조작 체험과 「프로그래밍의 기초」의 실험·관찰 질문은 건드리지 않는다. 기초 수업은 이미 짧은 `subtitle`의 글자만 핵심 줄과 같게 바꾼다.

## 핵심 한 줄 작성 규칙

60자 넘는 설명을 가진 개념(`cc0-4`, `lc1-4`, `bc0-3`, `finite`, `symbols`)에 쓴다.

1. 그 개념의 확인 문제가 기대는 문장을 찾는다.
2. 정의 표현을 덜고 ‘조건 → 결과’만 남긴다.
3. 원문의 낱말과 블록 이름을 쓰고 새 용어·숫자·예시를 더하지 않는다.
4. 뜻을 바꾸는 말(`만`, `모두`, `같을 때도`)은 길어져도 유지한다.
5. 설명을 가리고 핵심 줄과 그림만으로 확인 문제를 풀 수 있는지 본다.

예: `lc2` “한 번에 도는 각도는 360 ÷ 변의 수예요.”, `cc4` “조건이 참이면 안쪽, 거짓이면 ‘아니면’ 아래를 실행해요.”

## 벽돌 깨기 체험

11/8 사용자 검토로 처음 안(엔트리 코드 줄을 보여 주며 실행되는 줄을 밝히기)을 버렸다. 코드 줄이 확인 문제의 답을 그대로 보여 주고, 코드·값·버튼·설명·예시가 함께 있어 무엇을 설명하는지 흐려졌기 때문이다.

개념 하나에 핵심 한 줄, 움직여 보는 것 하나, 설명 한두 문장만 둔다. 블록 코드와 예시는 두지 않는다. 설명에는 어느 칸에 무엇을 넣는지 대신 일반 원칙만 쓴다. 답을 찾는 길잡이는 확인 문제의 힌트와 오답 안내가 맡는다.

| 개념 | 핵심 한 줄 | 움직여 보는 것 | 설명이 주는 원칙 |
| :--- | :--- | :--- | :--- |
| `bc0` | 변수는 게임 중에 바뀌는 값을 기억해요. | [시작하기] 0, [벽돌 깨기] +1 | 한 번 할 일은 반복 밖, 내내 확인할 일은 반복 안 |
| `bc1` | x는 가로 위치, y는 세로 위치예요. | 무대에서 마우스를 움직이면 막대 x만 따라가고 좌표 4개가 실시간으로 바뀜 | 이동 블록은 적힌 좌표만 바꾸고, 계속 따라가려면 되풀이 |
| `bc2` | ‘닿았는가?’는 참 또는 거짓으로 답해요. | 공을 벽에 갖다 대면 아래쪽 벽에서만 참 | 참일 때만 ‘만일’ 안쪽이 실행되고, 공은 화면 끝에서 튕김 |
| `bc3` | 숨긴 오브젝트에는 더 이상 닿지 않아요. | 벽돌을 누르면 점수 +1·숨김, 숨긴 벽돌은 그대로, 3개면 You win! | 벽돌 하나로 한 번만 오르고, `점수 값 = 목표 개수`면 승리 |

- 무대 체험은 마우스·터치·방향키로 움직인다. `bc3`의 승리 조건은 퀴즈 `bq4`에 필요하므로 유지한다.
- 다른 수업의 그림에는 번호를 새로 붙이지 않는다(제작자 판단). 캡처 그림 위에 번호를 얹으려면 다시 만들어야 하고, 핵심 한 줄만으로 학생의 눈이 가는 문제를 해결하기 때문이다.

## 구현 제약

- 체험은 새 파일 `src/components/student/brick-concept-play.tsx`로 만든다. 표시용 `useState`만 쓰고 `useWork`·저장·타이머를 쓰지 않는다. 다른 개념으로 가면 처음 상태로 돌아간다.
- 버튼을 담는 그림에서는 `role="img"`를 쓰지 않는다.
- 개념 그림용 `public/concepts/brick-concept-*.png` 중 체험으로 대체돼 안 쓰이는 파일은 지운다(이번 브랜치에서 만든 파일).
- `scripts/e2e-scope.mjs`에 새 파일을 연결한다.
