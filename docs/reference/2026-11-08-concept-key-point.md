# 개념 화면 핵심 한 줄·벽돌 깨기 직접 눌러 보기 설계

작성: 2026-11-08(Asia/Seoul). 상태: 승인됨(11/8). 대상 브랜치: `feat/brick-breaker`.

## 왜 하는가

수업에 집중하지 못한 학생이 개념 화면을 처음 열면 눈이 가운데 그림으로 먼저 간다. 핵심 설명은 그 위의 흐린 줄글이라 건너뛴다. 벽돌 깨기는 개념 뒤에 블록 조립 문제가 있어 이런 학생이 특히 당황한다.

성공 기준: 수업을 놓친 학생이 **개념 화면만 보고** 그 개념의 확인 문제를 풀 수 있다.

## 목표와 비목표

- 목표: 모든 수업의 개념 화면에서 핵심을 굵은 한 줄로 그림 바로 위에 둔다. 벽돌 깨기 개념 4개에는 직접 눌러 보는 체험을 넣는다.
- 비목표: 수업의 흐름, 개념 수, 확인 문제, 퀴즈 내용, 저장 방식은 바꾸지 않는다. 새 패키지는 넣지 않는다.
- 하면 실패인 것: 난이도·학습량 증가, 기존 설명에만 있던 규칙이 화면에서 사라지는 것, 체험이 학생 기록을 바꾸는 것.

## 사용자가 정한 것

- 시안 A(핵심 한 줄)를 모든 수업에, 시안 B(직접 눌러 보기)를 벽돌 깨기에 적용한다.
- 기존 흐름과 내용을 살리고 제공 방식만 바꾼다.

## 화면 구성 (`LessonConceptPanel`)

제목 → **핵심 한 줄(굵고 진한 글자)** → 그림 또는 체험 → **기존 설명 전문(보통 진한 글자, 항상 보임)** → 예시 → 확인 문제.

- 기존 설명은 줄이거나 접지 않고 위치만 그림 아래로 옮긴다. `또는`, `이상`, 바깥쪽 각도처럼 퀴즈가 쓰는 규칙이 설명에만 있고(`tests/lesson-feedback.test.ts`가 일부를 고정), 접힌 내용은 이 학생이 열어 보지 않기 때문이다.
- `Concept`에 선택 필드 `keyPoint?: string`을 더한다. 있으면 핵심 줄은 `keyPoint`, 설명은 그림 아래에 전문으로 둔다. 없으면 `explanation`이 이미 짧은 것이므로 핵심 줄로 올리고 두 번 보이지 않는다.
- `explanation`은 정답 피드백(`learning.ts`)에도 쓰이므로 내용을 바꾸지 않는다.
- 함수·복습 수업의 조작 체험과 「프로그래밍의 기초」의 실험·관찰 질문은 건드리지 않는다. 기초 수업은 이미 짧은 `subtitle`의 글자만 핵심 줄과 같게 바꾼다.

## 핵심 한 줄 작성 규칙

60자 넘는 설명을 가진 개념(`cc0-4`, `lc1-4`, `bc0-3`, `finite`, `symbols`)에 쓴다.

1. 그 개념의 확인 문제가 기대는 문장을 찾는다.
2. 정의 표현을 덜고 ‘조건 → 결과’만 남긴다.
3. 원문의 낱말과 블록 이름을 쓰고 새 용어·숫자·예시를 더하지 않는다.
4. 뜻을 바꾸는 말(`만`, `모두`, `같을 때도`)은 길어져도 유지한다.
5. 설명을 가리고 핵심 줄과 그림만으로 확인 문제를 풀 수 있는지 본다.

예: `lc2` “한 번에 도는 각도는 360 ÷ 변의 수예요.”, `cc4` “조건이 참이면 안쪽, 거짓이면 ‘아니면’ 아래를 실행해요.”

## 벽돌 깨기 체험

그림 자리에 엔트리 모양 코드 줄, 값 칸, 상황 버튼 1~3개, 쉬운 문장을 둔다. 버튼을 누르면 일한 줄이 빛나고(색만이 아닌 표시 포함) 문장이 바뀐다. 문장은 값·빛나는 줄 바로 곁에 두며 화면 읽기에도 전달한다.

| 개념 | 핵심 한 줄 | 누르는 것 → 변화 | 나오는 문장 | 확인 문제에 주는 지식 |
| :--- | :--- | :--- | :--- | :--- |
| `bc0` | 점수는 처음 한 번만 0, 닿을 때마다 더해요. | [시작하기] 점수 0, 정하기 줄 빛남 → [벽돌에 닿았을 때](시작 뒤 켜짐) +1, 만일·더하기 줄 빛남 | 시작할 때 한 번만 0이 돼요. / 반복하며 확인하다가 닿으면 1을 더해요. | 정하기는 반복 앞, 만일은 반복 안, 더하기는 만일 안 |
| `bc1` | 막대는 x만 마우스를 따라가요. y는 그대로예요. | [마우스 왼쪽 위]·[마우스 오른쪽 아래] x ±80, y -115 유지 / [반복 빼 보기] 따라가지 않음 | 마우스 x가 80이라 막대 x도 80이에요. y는 그대로예요. / 반복이 없으면 한 번만 움직이고 끝나요. | x 블록 선택, 이동은 반복 안 |
| `bc2` | 움직이고 튕기다가, 아래쪽 벽에 닿으면 끝나요. | [빈 곳]·[옆 벽]·[아래쪽 벽] 공 이동, 참/거짓, ①②③ 줄 빛남 | ①움직였어요. 아직 벽이 아니에요. / ①움직이고 ②벽에서 방향이 바뀌었어요. / ③아래쪽 벽이라 참! 모든 코드가 멈춰요. | 이동 → 튕기기 → 만일 순서, 멈추기는 만일 안 |
| `bc3` | 공에 닿으면 점수를 올리고, 벽돌을 숨겨요. | [공이 벽돌에 닿았을 때] 두 번: 처음 0→1·벽돌 사라짐, 두 번째 그대로 | 점수를 먼저 올리고, 그다음 벽돌이 사라져요. / 벽돌이 숨어서 이제 닿지 않아요. 점수는 그대로예요. | 만일은 반복 안, 더하기 다음 숨기기, 보이기 아님 |

- 코드 줄은 확인 문제의 답과 가깝다. 수업을 놓친 학생이 화면만 보고 풀게 하는 것이 목표이므로 받아들인다. `bc0`은 일반 벽돌 +1을 보여 주고 문제는 황금 벽돌 +10을 묻는다. 전이는 퀴즈와 미션에서 확인한다.
- `bc3`의 승리 조건 그림(`점수 값 = 목표`)은 퀴즈 `bq4`에 필요하므로 유지한다.
- 무대 그림은 새로 그리지 않는다(제작자 판단). 공·벽돌의 상태는 값 칸(`공 위치: 아래쪽 벽`, `벽돌: 사라짐`)으로 보여 준다. 데이터로 움직이는 공통 컴포넌트 하나로 끝내고 화면을 늘리지 않기 위해서다. 단 `bc1`의 ‘무대 좌표’ 그림은 x가 가로임을 보여 주는 유일한 그림이므로 체험 옆에 유지한다.
- 다른 수업의 그림에는 번호를 새로 붙이지 않는다(제작자 판단). 캡처 그림 위에 번호를 얹으려면 다시 만들어야 하고, 핵심 한 줄만으로 학생의 눈이 가는 문제를 해결하기 때문이다.

## 구현 제약

- 체험은 새 파일 `src/components/student/brick-concept-play.tsx`로 만든다. 표시용 `useState`만 쓰고 `useWork`·저장·타이머를 쓰지 않는다. 다른 개념으로 가면 처음 상태로 돌아간다.
- 코드 줄은 `concept-assemble.tsx`의 `EntryBlock`을 재사용한다.
- 버튼을 담는 그림에서는 `role="img"`를 쓰지 않는다.
- 개념 그림용 `public/concepts/brick-concept-*.png` 중 체험으로 대체돼 안 쓰이는 파일은 지운다(이번 브랜치에서 만든 파일).
- `scripts/e2e-scope.mjs`에 새 파일을 연결한다.

## 검증

- `npm run check`. 단위 테스트: 공개 수업(기초 제외)의 `keyPoint ?? explanation`이 60자 이하.
- E2E: 체험 버튼을 눌러 값과 문장이 바뀌고 저장 요청이 없으며 새로 고치면 처음 상태인지 확인. 파일 지정 실행(`brick-breaker`·`concept-layout`·`conditionals`·`loops`·`functions`·`programming-learning`·`teacher-lesson-preview`·`lesson-smoke`·`lesson-ui-consistency`).
- 깨질 테스트(`brick-breaker.spec.ts`의 `figure[role=img]`)와 문서(DESIGN·PRD·DEVELOPMENT·HANDOFF)를 함께 고친다.
